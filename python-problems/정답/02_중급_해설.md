# 중급 20문제 해설

문제마다 여섯 칸으로 적었습니다. 「묻는 것 -> 코드 한 줄씩 -> 왜 이렇게 푸나 ->
틀리면 이렇게 된다 -> 실제로 쓸 때는 -> 앞 문제와의 연결」 입니다.
막힌 문제만 골라 봐도 됩니다.

해설에 적힌 에러 문구와 출력은 전부 직접 실행해서 받은 것입니다(파이썬 3.14, 맥).
3.10 이하에서는 `Did you mean:` 같은 안내가 붙지 않는 등 문구가 조금 짧게 나옵니다.
에러 이름과 콜론 뒤의 핵심 문장은 같습니다. 버전마다 크게 다른 곳은 본문에 따로 적었습니다.

메모리 주소가 섞인 문구(`0x1061b4330` 같은 것)는 실행할 때마다 값이 바뀝니다.
그 자리는 숫자가 달라도 맞습니다.

## [2-1] 여러 줄 주문서 합산

**묻는 것**
줄바꿈 글자 `"\n"` 이 든 문자열을 `.split("\n")` 으로 줄마다 자르고, 줄마다 다시 `.split(",")` 으로 칸을 나누는 「두 번 자르기」 입니다. 맨 끝 `"\n"` 뒤에 남는 빈 줄을 거르는 것도 묻습니다.

**코드 한 줄씩**

```python
total = 0
count = 0
for line in memo.split("\n"):               # -> 줄 4개, 마지막은 ""
    if line != "":
        parts = line.split(",")             # -> ['아메리카노', '2', '4500']
        price = int(parts[2])               # -> 4500
        amount = int(parts[1]) * price      # -> 2 x 4500 = 9000
        total = total + amount
        count = count + 1
        print(f"{parts[0]} {parts[1]}개 x {price:,}원 = {amount:,}원")
print(f"주문 {count}건 / 합계 {total:,}원")
```

`memo.split("\n")` 은 줄바꿈 자리마다 잘라 `['아메리카노,2,4500', '라떼,1,5000', '쿠키,3,3200', '']` 을 돌려줍니다. 메모가 `"\n"` 으로 끝나서, 그 뒤의 「아무것도 없음」 이 빈 문자열 `''` 하나로 남습니다. ★ 의 답입니다.

`if line != "":` 가 그 빈 줄을 거릅니다(1-12 의 `!=`). 빈 줄이면 아래 여섯 줄을 통째로 건너뜁니다.

남은 줄은 1-8 처럼 쉼표로 잘라 칸 세 개를 얻습니다. 수량 `parts[1]` 과 단가 `parts[2]` 는 문자열이라 `int()` 로 바꿔 곱합니다. 출력 줄의 `{parts[1]}개` 는 바꾸기 전 글자를 그대로 씁니다. 찍기만 할 때는 숫자로 바꿀 필요가 없습니다.

`total` 과 `count` 는 for 위에서 0 으로 놓고, for 안에서 쌓고, for 밖에서 한 번 찍습니다(1-11).

**왜 이렇게 푸나**
메모는 「줄」 안에 「칸」 이 든 두 겹입니다. 바깥 겹(줄)을 먼저 자르고, 줄마다 안쪽 겹(칸)을 자릅니다.

힌트처럼 `for line in memo:` 로 문자열을 바로 돌면 줄이 아니라 글자가 하나씩 나옵니다. 파일은 for 로 돌면 줄마다 나왔지만(1-18), 문자열은 줄을 모릅니다. 그래서 `"\n"` 으로 직접 자릅니다.

빈 줄을 if 로 거르는 대신 `memo.strip().split("\n")` 처럼 끝의 `"\n"` 을 먼저 떼도 칸과 같은 4줄이 나옵니다. 칸이 이 둘을 못 가려냅니다. 다만 `.strip()` 은 양 끝만 떼서, 메모 가운데에 빈 줄이 끼면 그 줄에서 다시 멈춥니다. 줄마다 검사하는 쪽이 더 넓게 막습니다.

**틀리면 이렇게 된다**
빈 줄 검사를 빼면 마지막 빈 줄에서 멈춥니다.

```python
for line in memo.split("\n"):
    parts = line.split(",")
    price = int(parts[2])
```
```
IndexError: list index out of range
```

`"".split(",")` 은 `['']`, 칸이 하나뿐인 리스트라 `parts[2]` 가 없습니다. 「리스트 번호가 범위를 벗어났다」 는 뜻입니다. 앞의 세 줄은 계산을 마치고, 네 번째 바퀴에서 멈춥니다.

문자열을 바로 돌면 첫 바퀴에 「아」 한 글자가 들어옵니다.

```python
for line in memo:
    print(line)
    break
```
```
아
```

`print` 와 `break` 대신 쉼표로 자르면 「아」 도 칸이 하나뿐이라 같은 IndexError 가 납니다. 에러 문구가 같아도 원인은 다릅니다.

줄로 자르지 않고 쉼표로 한 번에 자르면 줄바꿈이 조각 안에 남습니다.

```python
print(memo.split(","))
```
```
['아메리카노', '2', '4500\n라떼', '1', '5000\n쿠키', '3', '3200\n']
```

`total = 0`·`count = 0` 을 for 안 맨 위로 옮기면 줄마다 금액은 맞게 찍히고 마지막 줄만 `주문 0건 / 합계 0원` 이 됩니다. 마지막 바퀴(빈 줄)에서도 0 으로 다시 놓이는데, 빈 줄은 아무것도 더하지 않기 때문입니다.

**실제로 쓸 때는**
채팅이나 메모장에서 복사해 온 글, 웹 폼의 여러 줄 입력칸이 이 모양입니다. 끝에 줄바꿈이 붙어 오는 일이 잦아서, 빈 줄 거르기는 줄로 자르기와 짝으로 씁니다.

**앞 문제와의 연결**
1-8 은 한 줄을 쉼표로 잘랐고, 1-20 은 파일을 for 로 돌며 줄마다 그렇게 잘라 합계를 냈습니다. 이번에는 파일 대신 문자열 하나라서, 줄로 자르는 일(`.split("\n")`)을 직접 합니다. 빈 줄 거르기는 1-12 의 `!= ""`, 쌓아 더하기는 1-11 그대로입니다.

## [2-2] 결시생이 섞인 평균

**묻는 것**
빈 값이 섞인 리스트로 평균을 낼 때 분모(나누는 수)를 무엇으로 잡는지 묻습니다. 전체 칸 수 `len(scores)` 와 실제로 센 수가 다르면 평균도 달라집니다.

**코드 한 줄씩**

```python
total = 0
taken = 0
for score in scores:
    if score != "":
        total = total + int(score)   # -> 88 + 72 + 95 + 43 = 298
        taken = taken + 1            # -> 4
everyone = len(scores)               # -> 6
print(f"결시까지 나눈 평균 {total / everyone:.1f}점 (분모 {everyone})")
print(f"결시를 뺀 평균 {total / taken:.1f}점 (분모 {taken})")
print(f"차이 {total / taken - total / everyone:.1f}점")
```

`if score != "":` 가 결시를 거릅니다. 걸러진 점수만 `int()` 로 바꿔 더하고, 그때만 `taken` 을 1 올립니다. 두 줄이 같은 if 안에 있어서 「더한 횟수 = 센 사람 수」 가 됩니다.

`len(scores)` 는 리스트의 칸 수입니다. 빈 문자열도 한 칸이라 6 입니다.

298 / 6 = 49.666... 이고 `:.1f` 가 소수 첫째 자리까지 반올림해 49.7 입니다. 298 / 4 = 74.5 입니다(1-11 의 `:.1f`).

차이는 반올림하기 전 두 평균을 빼서 24.833... 이고, 찍을 때 24.8 이 됩니다.

**왜 이렇게 푸나**
★ 의 답입니다. 결시를 분모에 넣으면 평균이 내려갑니다. 결시는 분자(합계)에 아무것도 더하지 않았는데 분모만 커지니, 결시생을 0점 받은 사람처럼 다룬 셈입니다.

평균은 「더한 값의 합 / 더한 값의 개수」 입니다. 더할 때 세고, 센 수로 나누면 분자와 분모가 늘 같은 사람을 가리킵니다.

`len()` 은 「전부 몇 칸인가」 라서, 칸을 하나도 안 거를 때만 분모가 됩니다. 걸러 낸 뒤에는 직접 센 수를 씁니다.

**틀리면 이렇게 된다**
힌트 그대로, 거르지 않고 숫자로 바꾸면 첫 결시에서 멈춥니다.

```python
total = 0
for score in scores:
    total = total + int(score)
```
```
ValueError: invalid literal for int() with base 10: ''
```

`''` 는 빈 문자열입니다. 「빈 글자는 10진수 숫자로 읽을 수 없다」 는 뜻입니다. 88 과 72 는 더한 뒤 세 번째 칸에서 멈춥니다.

세는 줄을 if 밖으로 내면 에러 없이 틀립니다.

```python
total = 0
taken = 0
for score in scores:
    if score != "":
        total = total + int(score)
    taken = taken + 1
print(f"결시를 뺀 평균 {total / taken:.1f}점 (분모 {taken})")
```
```
결시를 뺀 평균 49.7점 (분모 6)
```

이름은 「결시를 뺀」 인데 값은 결시까지 나눈 평균과 같습니다. 지문이 분모를 같이 찍게 한 것은 이런 실수를 눈으로 잡으라는 뜻입니다.

`:.1f` 를 빼면 첫 줄이 `49.666666666666664점` 처럼 길게 나옵니다. 74.5 는 원래 소수 한 자리라 그대로입니다.

**실제로 쓸 때는**
설문의 「응답 없음」, 별점을 안 준 리뷰, 빈칸이 있는 출석부처럼 빈 값이 섞인 평균은 분모부터 정합니다. 결과를 알릴 때도 「응시자 4명 기준」 처럼 분모를 같이 적는 편이 안전합니다.

**앞 문제와의 연결**
1-11 의 합계·평균과 `:.1f`, 1-12 의 「빈 값 거르기」 를 한 for 에 넣었습니다. 새로 나온 것은 칸 수를 세는 `len()` 입니다. 2-3 에서 이 계산을 함수로 묶어 세 반에 씁니다.

## [2-3] 평균을 함수로

**묻는 것**
2-2 의 계산을 `average(scores)` 하나로 묶어 세 반에 부르는 것, 그리고 나눌 사람이 없을 때 `if` 안의 `return` 으로 나누기 전에 끝내는 것입니다.

**코드 한 줄씩**

```python
def average(scores):
    total = 0
    taken = 0
    for score in scores:
        if score != "":
            total = total + int(score)
            taken = taken + 1
    if taken == 0:
        return 0.0              # -> 3반은 여기서 끝
    return total / taken        # -> 1반 298 / 4 = 74.5

print(f"1반 평균 {average(class_1):.1f}점")
print(f"2반 평균 {average(class_2):.1f}점")   # -> 275 / 3 = 91.666...
print(f"3반 평균 {average(class_3):.1f}점")
```

`average(class_1)` 로 부르면 함수 안의 `scores` 가 class_1 을 가리킵니다. `total = 0`, `taken = 0` 이 함수 안 맨 위에 있어서 부를 때마다 새로 0 이 됩니다(힌트). for 부분은 2-2 와 같습니다.

for 가 끝난 뒤 `taken` 이 0 이면 `return 0.0` 이 그 자리에서 함수를 끝냅니다. 아래 `return total / taken` 줄까지 가지 않으니 0 으로 나누는 일이 생기지 않습니다.

출력 줄은 돌려받은 값에 `:.1f` 만 붙입니다. 함수는 숫자만 돌려주고, 「1반 평균」 같은 글자는 부르는 쪽이 붙입니다.

**왜 이렇게 푸나**
함수가 받는 것은 점수 리스트 하나, 돌려주는 것은 평균 숫자 하나입니다. 반 이름도 출력 모양도 모르는 채 계산만 하니, 4반이 생겨도 `average(class_4)` 한 줄이면 됩니다.

print 대신 return 인 것은 1-17 과 같은 이유입니다. 돌려받은 숫자라야 `:.1f` 를 붙이거나 다른 계산에 씁니다.

★ 의 답입니다. 3반은 셋 다 결시라 `taken` 이 0 이고, 그냥 나누면 0 으로 나누다 멈춥니다.

`return 0.0` 을 `return 0` 으로 써도 칸은 같습니다. `{0:.1f}` 도 `0.0` 으로 찍히기 때문입니다. 지문이 0.0 을 돌려 달라고 한 것은 다른 반과 같은 소수로 맞추기 위해서입니다. `:.1f` 없이 그대로 찍으면 `0` 과 `91.66666666666667` 처럼 모양이 갈립니다.

**틀리면 이렇게 된다**
0 검사를 빼면 3반에서 멈춥니다.

```python
def average(scores):
    total = 0
    taken = 0
    for score in scores:
        if score != "":
            total = total + int(score)
            taken = taken + 1
    return total / taken

print(f"3반 평균 {average(class_3):.1f}점")
```
```
ZeroDivisionError: division by zero
```

「0 으로 나눴다」 는 뜻입니다. 세 반을 이어 부르면 1반·2반 줄은 찍히고 3반에서 멈춥니다.

검사 안에 `return 0.0` 대신 `print(0.0)` 을 두면, `0.0` 을 찍고도 아래 줄로 내려가 같은 ZeroDivisionError 로 멈춥니다. return 은 함수를 그 자리에서 끝내지만, print 는 찍고 다음 줄로 넘어갑니다.

힌트의 경우입니다. 0 으로 놓는 두 줄을 함수 밖(위)에 두면 처음 부를 때 바로 멈춥니다.

```python
total = 0
taken = 0
def average(scores):
    for score in scores:
        if score != "":
            total = total + int(score)
            taken = taken + 1
    return total / taken

print(f"1반 평균 {average(class_1):.1f}점")
```
```
UnboundLocalError: cannot access local variable 'total' where it is not associated with a value
```

함수 안에서 `total = ...` 처럼 값을 넣는 이름은 그 함수만의 이름(지역 변수)이 됩니다. 밖의 `total` 과는 다른 이름이라, 「아직 값이 없는 total 을 읽으려 했다」 는 뜻입니다.
파이썬 3.9 에서는 `UnboundLocalError: local variable 'total' referenced before assignment` 로 나옵니다. 뜻은 같습니다.

**실제로 쓸 때는**
반별·지점별·월별처럼 「같은 계산을 묶음마다」 할 때 함수로 뺍니다. 빈 묶음(신입 반, 주문이 없는 날)은 꼭 생기니, 나누는 함수는 분모가 0 일 때 돌려줄 값을 먼저 정해 둡니다.

**앞 문제와의 연결**
계산은 2-2 그대로이고, 1-17 의 def·return 으로 묶었습니다. 함수가 받는 값이 숫자 둘(1-17)에서 리스트 하나로 바뀌었습니다. 2-4 부터는 일을 함수 여러 개로 나눕니다.

## [2-4] 가입 메일 정리와 검사

**묻는 것**
일을 「정리」 「검사」 「모으기」 세 함수로 나누고, 앞의 두 함수를 세 번째 함수 안에서 부르는 것입니다. 검사 함수는 `.count()` 와 `in` 으로 조건을 하나씩 보고 True·False 를 돌려줍니다.

**코드 한 줄씩**

```python
def clean_email(raw):
    return raw.strip().lower()       # -> " KIM.Haneul@Example.COM " -> "kim.haneul@example.com"

def is_valid(email):
    if email.count("@") != 1:
        return False                 # -> "" 와 "minjae@@example.com"
    parts = email.split("@")
    if parts[0] == "":
        return False                 # -> "@example.com"
    if "." in parts[1]:
        return True
    return False                     # -> "jiwoo@example"

def keep_valid(raw_list):
    valid = []
    for raw in raw_list:
        email = clean_email(raw)
        if is_valid(email):
            valid.append(email)
    return valid

passed = keep_valid(signup)
print(f"통과 {len(passed)}명 / 전체 {len(signup)}명")
for email in passed:
    print(email)
```

`clean_email` 은 1-6 의 `.strip().lower()` 를 한 줄로 돌려줍니다. 공백뿐인 `"   "` 은 빈 문자열 `""` 이 됩니다.

`is_valid` 는 조건을 위에서부터 하나씩 봅니다. 어기는 순간 `return False` 로 끝나니(2-3 의 if 안의 return), 아래 줄은 앞 조건을 다 지킨 메일만 봅니다.

`email.count("@")` 는 `@` 가 몇 번 나오는지 셉니다. 빈 문자열은 0, `minjae@@example.com` 은 2 라서 첫 검사에서 떨어집니다.

`@` 가 딱 하나인 것을 확인한 뒤에 `.split("@")` 으로 자르니 `parts` 는 늘 두 칸입니다. `"@example.com"` 은 `['', 'example.com']` 이라 앞 칸이 비어 떨어집니다.

`"." in parts[1]` 은 뒤 칸에 점이 들어 있나입니다. `in` 은 1-16 에서 딕셔너리 키에 썼는데, 문자열에 쓰면 「이 글자가 들어 있나」 입니다.

`keep_valid` 는 1-12 처럼 빈 리스트에 통과한 것만 `.append()` 합니다. 넣는 것은 정리한 `email` 입니다. `len()` 은 2-2 의 칸 수입니다.

**왜 이렇게 푸나**
세 함수는 받는 것과 돌려주는 것이 다 다릅니다. `clean_email` 은 글자 -> 글자, `is_valid` 는 글자 -> True/False, `keep_valid` 는 리스트 -> 리스트입니다. 나눠 두면 `is_valid("a@example.com")` 처럼 하나만 따로 불러 시험해 볼 수 있고, 검사 규칙이 바뀌어도 `is_valid` 만 고칩니다.

정리를 검사보다 먼저 하는 것은, 공백·대문자 때문에 같은 메일이 다르게 보이는 일(1-6)을 검사 전에 없애기 위해서입니다. 검사 순서도 뜻이 있습니다. `@` 개수부터 봐야 `parts[1]` 이 늘 있습니다(아래 「틀리면」).

칸이 못 가려내는 풀이가 둘 있습니다.
`@` 개수를 세지 않고 들어 있는지만(`in`) 봐도 칸은 같습니다. `minjae@@example.com` 은 자르면 `['minjae', '', 'example.com']` 이라 둘째 칸 `''` 에 점이 없어서 어차피 떨어지기 때문입니다. `kim@example.com@example.com` 을 넣으면 갈립니다. 정답은 False, `in` 풀이는 True 입니다.
맨 끝 `return False` 를 빼도 칸은 같습니다. `jiwoo@example` 에서 함수가 아무것도 돌려주지 않아 None 이 되는데, if 는 None 을 거짓으로 다뤄서 통과 목록에 안 넣습니다. `print(is_valid("jiwoo@example"))` 로 찍어 보면 `None` 이 나와 드러납니다. True/False 를 돌려주기로 한 함수는 끝까지 둘 중 하나를 돌려주게 씁니다.

**틀리면 이렇게 된다**
`@` 개수를 보기 전에 자르면, 공백뿐이던 메일에서 멈춥니다.

```python
def is_valid(email):
    parts = email.split("@")
    if "." in parts[1]:
        return True
    return False

print(is_valid(clean_email("   ")))
```
```
IndexError: list index out of range
```

`""` 을 `@` 로 자르면 `['']` 한 칸뿐이라 `parts[1]` 이 없습니다. 2-1 의 빈 줄과 같은 에러입니다.

`.append()` 에 정리한 `email` 대신 받은 그대로의 `raw` 를 넣으면, 첫 줄 `통과 3명 / 전체 7명` 은 맞고 메일은 정리 전 모양으로 찍힙니다. `KIM.Haneul@Example.COM` 은 앞뒤 공백까지 붙은 채, `DAEUN@EXAMPLE.COM` 은 대문자 그대로입니다.

`@` 앞이 비었는지 보는 검사를 빼면 `@example.com` 이 통과해 첫 줄이 `통과 4명 / 전체 7명` 이 됩니다.

**실제로 쓸 때는**
가입·주문 폼, 표 프로그램에서 붙여 넣은 명단처럼 사람이 친 값은 「정리 -> 검사 -> 모으기」 순서로 받습니다. 실제 서비스의 메일 검사는 조건이 더 많지만, 조건을 하나씩 보다가 어기면 바로 False 를 돌려주는 모양은 같습니다. 정말 있는 주소인지는 확인 메일을 보내야 압니다.

**앞 문제와의 연결**
1-6 의 정리(`.strip().lower()`), 1-12 의 「빈 리스트에 골라 담기」, 2-3 의 if 안의 return 을 함수 세 개에 나눠 담았습니다. 2-3 은 함수가 하나였고, 이번에는 함수가 함수를 부릅니다.

## [2-5] 주문 금액과 배송비

**묻는 것**
인자에 기본값을 주어 부를 때 빼도 되게 하는 것(`ship=3000`)과, 부를 때 이름을 붙여 원하는 인자만 바꾸는 것(`free_from=20000`)입니다. 이름 없이 넘긴 값은 순서대로 들어간다는 것도 봅니다.

**코드 한 줄씩**

```python
def order_total(prices, ship=3000, free_from=30000):
    goods = 0
    for price in prices:
        goods = goods + price            # -> 12000 + 8000 + 4500 = 24500
    if goods >= free_from:
        ship = 0
    return goods + ship

print(f"기본값 그대로: {order_total(cart):,}원")                  # -> 24500 + 3000
print(f"무료 기준 20000: {order_total(cart, free_from=20000):,}원")  # -> 24500 + 0
print(f"배송비 2500: {order_total(cart, ship=2500):,}원")           # -> 24500 + 2500
print(f"이름 없이 20000: {order_total(cart, 20000):,}원")           # -> 24500 + 20000
```

`ship=3000` 처럼 `=` 뒤에 적은 값이 기본값입니다. 부를 때 그 인자를 빼면 기본값이 들어갑니다. `order_total(cart)` 는 ship 3000, free_from 30000 으로 계산합니다.

상품 합계는 1-11 처럼 쌓아 더합니다. 「이상」 이라 `>=` 입니다(1-9). 합계가 기준 이상이면 `ship` 을 0 으로 바꿉니다. 받은 인자도 함수 안에서는 보통 변수처럼 바꿀 수 있습니다.

`free_from=20000` 처럼 이름을 붙이면 순서와 상관없이 그 인자에 들어갑니다. ship 은 기본값 3000 그대로이고, 24500 이 20000 이상이라 무료입니다.

`order_total(cart, 20000)` 은 이름이 없으니 두 번째 자리, 곧 `ship` 에 들어갑니다. ★ 의 답입니다. 배송비가 20000원이 되어 44,500원입니다.

**왜 이렇게 푸나**
함수는 상품 금액 리스트를 받아 「낼 돈」 하나를 돌려줍니다. 배송비와 무료 기준은 거의 늘 같고 이벤트 때만 바뀌는 값이라 기본값으로 둡니다. 평소에는 `order_total(cart)` 로 짧게 부르고, 바뀔 때만 그 인자를 이름으로 넘깁니다.

꼭 받아야 하는 `prices` 가 맨 앞이고, 기본값이 있는 인자는 그 뒤입니다. 이 순서는 파이썬의 규칙입니다(아래 「틀리면」).

네 번째 줄은 일부러 넣은 틀린 부르기입니다. 에러 없이 그럴듯한 숫자가 나와서 칸을 보고서야 압니다. 기본값 있는 인자를 바꿀 때는 이름을 붙여 부르는 편이 안전합니다.

칸이 못 가려내는 풀이도 있습니다. `>=` 를 `>` 로 써도 네 줄이 같습니다. 합계 24500 이 기준과 딱 같은 경우가 없어서입니다. `order_total([30000])` 을 부르면 `>=` 는 30,000원, `>` 는 33,000원으로 갈립니다. 경계는 지문의 「이상」 「초과」 를 보고 정합니다.

**틀리면 이렇게 된다**
기본값 있는 인자 뒤에 기본값 없는 인자를 두면 실행하기 전에 막힙니다.

```python
def order_total(prices, ship=3000, free_from):
    return 0
```
```
SyntaxError: parameter without a default follows parameter with a default
```

「기본값 없는 인자가 기본값 있는 인자 뒤에 왔다」 는 뜻입니다. 파이썬 3.9 에서는 `SyntaxError: non-default argument follows default argument` 로 나옵니다.

인자 이름을 틀리게 적으면 그런 인자는 없다고 합니다.

```python
print(order_total(cart, free=20000))
```
```
TypeError: order_total() got an unexpected keyword argument 'free'
```

이름 붙인 값 뒤에 이름 없는 값을 두면 이것도 실행 전에 막힙니다.

```python
print(order_total(cart, free_from=20000, 2500))
```
```
SyntaxError: positional argument follows keyword argument
```

이름 없는 값(위치 인자)은 앞에, 이름 붙인 값은 뒤에 씁니다.

**실제로 쓸 때는**
쇼핑몰의 배송비·할인율, 한 쪽에 보여 줄 글 수처럼 「보통은 이 값, 가끔 바꿈」 인 설정이 기본값 인자입니다. 1-18 의 `open(파일, encoding="utf-8")` 도 `encoding` 을 이름 붙여 넘긴 부르기입니다.

**앞 문제와의 연결**
2-3 의 함수는 부를 때 값을 빠짐없이 넘겼습니다. 이번에는 기본값으로 뺄 수 있는 인자를 만들고, 1-18 에서 써 본 `이름=값` 꼴로 골라 바꿨습니다. 합계는 1-11, 무료 기준은 1-9 의 `>=` 입니다.

## [2-6] 할 일 진행률

**묻는 것**
함수 하나가 값 네 개를 한꺼번에 돌려주고(`return 값, 값, 값, 값`), 부르는 쪽이 그 넷을 변수 네 개로 나눠 받는 것입니다. 줄 앞 세 글자로 종류를 가르는 것과 「처음 만난 것만 남기기」 도 묻습니다.

**코드 한 줄씩**

```python
def progress(lines):
    done = 0
    total = 0
    first = "없음"
    for line in lines:
        line = line.strip()              # -> "  [ ] 간식 주문  " -> "[ ] 간식 주문"
        mark = line[:3]                  # -> "[ ]"
        if mark == "[x]" or mark == "[X]":
            done = done + 1
            total = total + 1
        elif mark == "[ ]":
            total = total + 1
            if first == "없음":
                first = line[3:].strip() # -> "발표 자료 초안"
    if total == 0:
        return 0, 0, 0.0, first
    return done, total, done / total * 100, first

done, total, rate, first = progress(todo_lines)
print(f"{done}/{total} 끝 ({rate:.1f}%) 다음 할 일: {first}")
done, total, rate, first = progress(["## 메모", ""])
print(f"{done}/{total} 끝 ({rate:.1f}%) 다음 할 일: {first}")
```

`first` 는 「아직 못 찾음」 이라는 표시로 `"없음"` 에서 시작합니다. 남은 일이 하나도 없으면 이 값이 그대로 돌아갑니다.

줄마다 `.strip()` 부터 해서, 앞에 공백이 붙은 「간식 주문」 줄도 `[` 로 시작하게 만듭니다.

`line[:3]` 은 앞 세 글자입니다(1-5 의 `[:끝]`). 빈 줄은 `""`, `"## 다음 주"` 는 `"## "` 이라 어느 갈래에도 안 걸리고 세지 않습니다.

끝낸 일은 `or` 로 소문자·대문자 둘 다 받습니다(1-9). 끝낸 일이든 남은 일이든 전체 수 `total` 은 1 올립니다. 3 + 4 라서 7 입니다.

남은 일은 `first` 가 아직 `"없음"` 일 때만 이름을 넣습니다. 한 번 넣고 나면 조건이 거짓이라 뒤의 남은 일이 덮어쓰지 않습니다(힌트). `line[3:]` 은 네 번째 글자부터라 `" 발표 자료 초안"` 처럼 앞에 공백이 하나 남습니다. 그래서 `.strip()` 을 한 번 더 합니다.

`return` 뒤에 쉼표로 값을 넷 적으면 네 개를 한 번에 돌려줍니다. 부르는 쪽 `done, total, rate, first = ...` 가 왼쪽부터 차례로 나눠 받습니다.

두 번째 부르기는 셀 줄이 없어서 `total` 이 0 입니다. 2-3 처럼 나누기 전에 `return 0, 0, 0.0, first` 로 끝냅니다.

**왜 이렇게 푸나**
함수가 받는 것은 줄 리스트, 돌려주는 것은 「끝낸 수 · 전체 수 · 비율 · 다음 할 일」 네 가지입니다. 넷이 다 같은 한 바퀴에서 나오니, 함수를 넷으로 쪼개면 리스트를 네 번 돌아야 합니다. 한 번 돌고 한꺼번에 돌려주는 편이 짧습니다.

나눠 받으면 print 줄에서 `rate` 처럼 뜻이 보이는 이름으로 씁니다.

「처음 것만 남기기」 는 「아직 못 찾음」 표시를 들고 다니다가 그 표시일 때만 넣는 방식입니다. 없을 때 돌려줄 값과 표시를 같은 `"없음"` 으로 두어서, 남은 일이 없으면 손대지 않아도 답이 됩니다.

**틀리면 이렇게 된다**
★ 의 답입니다. 네 개를 돌려주는데 셋으로 받으면 멈춥니다.

```python
done, total, rate = progress(todo_lines)
```
```
ValueError: too many values to unpack (expected 3, got 4)
```

「나눠 받을 값이 너무 많다(3개를 기대했는데 4개가 왔다)」 는 뜻입니다. 파이썬 3.9 에서는 `, got 4` 없이 `(expected 3)` 까지만 나옵니다.

변수 하나로 받으면 에러는 없고, 네 값이 괄호로 묶인 한 덩어리로 들어옵니다. 이 괄호 묶음이 2-7 에서 쓰는 튜플입니다.

```python
result = progress(todo_lines)
print(result)
```
```
(3, 7, 42.857142857142854, '발표 자료 초안')
```

`if first == "없음":` 줄을 빼고 바로 넣으면 남은 일을 만날 때마다 덮어써서 마지막 남은 일이 나옵니다. 첫 줄이 `3/7 끝 (42.9%) 다음 할 일: 교통편 확인` 이 됩니다.

맨 앞 `line = line.strip()` 을 빼면 「간식 주문」 줄의 앞 세 글자가 `"  ["` 이 되어 세지 않습니다. 첫 줄이 `3/6 끝 (50.0%)` 으로 바뀝니다.

`total == 0` 검사를 빼면 두 번째 부르기에서 2-3 과 같은 `ZeroDivisionError: division by zero` 로 멈춥니다.

**실제로 쓸 때는**
메모 앱의 체크 목록, 「완료 3 / 전체 7」 진행 막대, 다음 할 일 미리 보기가 이 계산입니다. 함수가 결과 몇 개를 같이 돌려주는 일은 「가장 작은 값과 가장 큰 값」, 「몫과 나머지」 처럼 자주 나옵니다.

**앞 문제와의 연결**
1-5 의 `[:끝]`·`[시작:]`, 1-6 의 `.strip()`, 1-9 의 `or`, 1-10 의 `elif`, 2-3 의 「분모가 0 이면 먼저 return」 을 한 함수에 모았습니다. 새로 나온 것은 여러 값을 돌려주고 나눠 받는 것입니다. 2-7 에서는 나눠 받기를 for 줄에 씁니다.

## [2-7] 가계부 분류별 합계

**묻는 것**
(분류, 금액) 튜플 리스트를 `for kind, amount in rows:` 로 나눠 받으며 돌고, 딕셔너리에 분류별 합계를 쌓는 것입니다. 다 쌓은 딕셔너리에서 가장 큰 값을 찾는 것도 묻습니다.

**코드 한 줄씩**

```python
def sum_by_kind(rows):
    totals = {}
    for kind, amount in rows:                     # -> kind "식비", amount 9500
        if kind in totals:
            totals[kind] = totals[kind] + amount  # -> 있는 분류는 더하기
        else:
            totals[kind] = amount                 # -> 처음 나온 분류는 넣기
    return totals                                 # -> {'식비': 26000, '교통': 4250, '문화': 18000}

totals = sum_by_kind(ledger)
top_kind = ""
top_amount = 0
for kind in totals:
    print(f"{kind} {totals[kind]:,}원")
    if totals[kind] > top_amount:
        top_kind = kind
        top_amount = totals[kind]
print(f"가장 많이 쓴 분류: {top_kind} ({top_amount:,}원)")
```

`("식비", 9500)` 처럼 괄호로 묶은 값 한 벌이 튜플입니다. `for kind, amount in rows:` 는 바퀴마다 튜플 하나를 꺼내 첫 칸을 `kind`, 둘째 칸을 `amount` 에 나눠 넣습니다. 2-6 의 나눠 받기를 for 줄에서 한 것입니다.

딕셔너리 부분은 1-16 의 투표 세기와 같은 모양입니다. 1-16 은 1 씩 더했고, 이번에는 금액만큼 더합니다. 함수는 다 쌓은 `totals` 를 돌려줍니다.

딕셔너리를 for 로 돌면 키가 넣은 순서대로 나옵니다(1-16). 그래서 「처음 나온 분류부터」 는 따로 할 일 없이 지켜집니다.

가장 큰 것 찾기는 힌트대로, 지금까지 본 것 중 가장 큰 분류와 금액을 `top_kind`·`top_amount` 에 들고 다닙니다. 더 큰 것을 만나면 둘 다 바꿉니다. 식비 26000 -> 교통 4250(작음) -> 문화 18000(작음) 이라 식비가 남습니다.

**왜 이렇게 푸나**
함수는 기록 리스트를 받아 「분류 -> 합계」 딕셔너리를 돌려줍니다. 찍는 모양과 1등 찾기는 쓰는 곳마다 다를 수 있어 바깥에 둡니다. 이달 가계부를 넣든 지난달 가계부를 넣든 같은 함수를 씁니다.

출력과 1등 찾기를 한 for 에 넣은 것은 둘 다 분류를 하나씩 보는 일이라서입니다. 따로 두 번 돌아도 답은 같습니다.

`top_amount` 를 0 에서 시작해도 되는 것은 금액이 다 0 보다 크기 때문입니다.

**틀리면 이렇게 된다**
`if kind in totals:` 없이 바로 더하면 첫 기록에서 멈춥니다.

```python
totals = {}
for kind, amount in ledger:
    totals[kind] = totals[kind] + amount
```
```
KeyError: '식비'
```

빈 딕셔너리에서 아직 없는 키 `'식비'` 를 꺼내려 했다는 뜻입니다(1-16 의 `KeyError: '화'` 와 같습니다).

검사 없이 늘 `totals[kind] = amount` 로 넣으면 더하지 않고 덮어씁니다. 에러는 없습니다.

```python
def sum_by_kind(rows):
    totals = {}
    for kind, amount in rows:
        totals[kind] = amount
    return totals

print(sum_by_kind(ledger))
```
```
{'식비': 4500, '교통': 1450, '문화': 18000}
```

분류마다 마지막 금액만 남았습니다. 이 딕셔너리로 1등을 찾으면 `가장 많이 쓴 분류: 문화 (18,000원)` 이 나옵니다.

`top_kind = ""` 와 `top_amount = 0` 을 for 안 맨 위로 옮겨도 `가장 많이 쓴 분류: 문화 (18,000원)` 이 나옵니다. 바퀴마다 0 으로 돌아가서 늘 마지막 분류가 1등이 되기 때문입니다. 2-3 에서 본 「0 으로 놓는 줄의 자리」 실수입니다.

받는 이름 수가 튜플 칸 수와 다르면 2-6 과 같은 ValueError 가 납니다. `for kind, amount, memo in ledger:` 는 `ValueError: not enough values to unpack (expected 3, got 2)` 입니다.

**실제로 쓸 때는**
가계부의 분류별 지출, 가게의 메뉴별 매출, 부서별 비용처럼 「(무엇, 얼마) 기록 -> 무엇별 합계」 는 자주 나오는 집계입니다. 2-20 에서는 같은 일을 파일에서 읽은 대출 기록으로 합니다.

**앞 문제와의 연결**
1-16 의 「있으면 더하고 없으면 넣기」 를 1 씩 세기에서 금액 더하기로 넓혔습니다. 튜플을 나눠 받는 것은 2-6 의 `변수, 변수 = 함수()` 와 같은 원리입니다. 2-8 에서는 `in` 검사 대신 `.get` 으로 없는 키를 다룹니다.

## [2-8] 메뉴에 없는 주문

**묻는 것**
딕셔너리에 없을 수도 있는 키를 꺼낼 때, `in` 으로 먼저 묻는 방법과 `.get(키, 없을 때 값)` 으로 꺼내는 방법을 자리에 맞게 쓰는 것입니다.

**코드 한 줄씩**

```python
def receipt(order, menu, sale):
    total = 0
    for name in order:
        if name in menu:
            off = sale.get(name, 0)          # -> 쿠키 700, 아메리카노 0
            price = menu[name] - off         # -> 3200 - 700 = 2500
            total = total + price
            print(f"{name} {price:,}원 (할인 {off:,}원)")
        else:
            print(f"{name}: 메뉴에 없음")     # -> 핫초코
    return total                             # -> 4500 + 2500 + 4500 + 4500 = 16000

print(f"합계 {receipt(order, menu, sale):,}원")
```

`if name in menu:` 로 메뉴판에 있는지부터 봅니다(1-16). 핫초코는 else 로 가서 「메뉴에 없음」 만 찍고 다음 주문으로 넘어갑니다. 합계에는 안 들어갑니다.

`sale.get(name, 0)` 은 할인표에 `name` 이 있으면 그 값을, 없으면 뒤에 적은 0 을 돌려줍니다. 아메리카노는 할인표에 없어서 0 이고, 에러가 나지 않습니다.

`menu[name]` 은 대괄호로 꺼냅니다. 바로 위에서 있는 것을 확인했으니 안전합니다.

마지막 줄은 f-string 이 `receipt(...)` 를 부르는 동안 함수 안의 print 다섯 줄이 먼저 찍힙니다. 함수가 합계를 돌려준 뒤에야 「합계 16,000원」 줄이 완성되어 맨 아래에 찍힙니다.

**왜 이렇게 푸나**
두 딕셔너리는 「없는 키」 의 뜻이 다릅니다. 메뉴판에 없으면 팔 수 없는 주문이라 따로 알려야 하고, 할인표에 없으면 그냥 할인 0원입니다. 그래서 메뉴판은 `in` 으로 물어 갈래를 나누고, 할인표는 `.get(name, 0)` 으로 기본값을 받아 갈래 없이 씁니다(힌트).

함수는 주문·메뉴판·할인표 셋을 받아 합계 하나를 돌려줍니다. 할인표를 인자로 받으니 내일 할인이 바뀌어도 함수는 그대로입니다.

**틀리면 이렇게 된다**
★ 의 답입니다. 할인을 대괄호로 꺼내면 할인표에 없는 첫 주문에서 멈춥니다.

```python
for name in order:
    if name in menu:
        off = sale[name]
```
```
KeyError: '아메리카노'
```

메뉴판 검사는 통과했지만 할인표에는 아메리카노가 없습니다. 2-7 의 KeyError 가 다른 딕셔너리에서 난 것입니다.

메뉴판 검사를 빼고 `menu[name]` 으로 바로 꺼내면, 이번에는 세 번째 주문에서 `KeyError: '핫초코'` 로 멈춥니다.

메뉴판까지 `.get(name, 0)` 으로 꺼내면 에러는 없지만, 핫초코가 0원짜리 주문으로 찍힙니다.

```python
def receipt(order, menu, sale):
    total = 0
    for name in order:
        off = sale.get(name, 0)
        price = menu.get(name, 0) - off
        total = total + price
        print(f"{name} {price:,}원 (할인 {off:,}원)")
    return total

print(f"합계 {receipt(order, menu, sale):,}원")
```
```
아메리카노 4,500원 (할인 0원)
쿠키 2,500원 (할인 700원)
핫초코 0원 (할인 0원)
라떼 4,500원 (할인 500원)
아메리카노 4,500원 (할인 0원)
합계 16,000원
```

합계는 맞지만 「팔 수 없는 주문」 이 「공짜 주문」 이 됐습니다. 없는 키를 `.get` 으로 덮어도 되는지는, 그 딕셔너리에서 「없음」 이 무슨 뜻인지로 정합니다.

`.get(name)` 처럼 없을 때 값을 안 적으면 None 이 돌아옵니다. 첫 주문에서 `TypeError: unsupported operand type(s) for -: 'int' and 'NoneType'` 로 멈춥니다.

함수 끝의 `return total` 을 빼면 다섯 줄은 다 찍히고, 합계 줄에서 1-17 과 같은 `TypeError: unsupported format string passed to NoneType.__format__` 로 멈춥니다.

**실제로 쓸 때는**
쿠폰표·회원 등급표·설정값처럼 「대부분은 기본값, 일부만 따로 정한」 표는 `.get(키, 기본값)` 으로 읽습니다. 상품 목록·회원 명단처럼 없으면 안 되는 표는 `in` 으로 먼저 묻고 따로 알립니다.

**앞 문제와의 연결**
2-7 은 `in` 으로 묻고 없으면 새로 넣었습니다. 이번에는 메뉴판에는 `in`, 할인표에는 `.get` 을 써서 「없는 키」 를 두 방법으로 다뤘습니다. 2-7 의 if·else 네 줄도 `totals[kind] = totals.get(kind, 0) + amount` 한 줄로 쓸 수 있고, 결과 딕셔너리가 같습니다.

## [2-9] 반찬 판매량 순위

**묻는 것**
딕셔너리를 (판매량, 이름) 튜플 리스트로 바꾸고, `sorted(..., reverse=True)` 로 큰 것부터 늘어놓아 `[:3]` 으로 앞 셋만 자르는 것입니다. 튜플을 정렬할 때 무엇이 기준이 되는지 묻습니다.

**코드 한 줄씩**

```python
def top3(sales):
    pairs = []
    for name in sales:
        pairs.append((sales[name], name))   # -> (42, '멸치볶음') ...
    ranked = sorted(pairs, reverse=True)    # -> (57, '계란말이') 부터
    return ranked[:3]

rank = 1
for count, name in top3(sales):
    print(f"{rank}위 {name} {count}개")
    rank = rank + 1
```

`for name in sales:` 는 키(반찬 이름)를 하나씩 줍니다(1-16). `sales[name]` 으로 판매량을 꺼내 `(판매량, 이름)` 튜플을 만들어 담습니다. 괄호가 두 겹인 것은 바깥이 `.append()` 의 괄호, 안쪽이 튜플이라서입니다. 다 담으면 `[(42, '멸치볶음'), (57, '계란말이'), (18, '시금치나물'), (35, '장조림'), (49, '어묵볶음')]` 입니다.

`sorted(pairs)` 는 작은 것부터 늘어놓은 새 리스트를 돌려줍니다(1-7). `reverse=True` 를 붙이면 큰 것부터입니다. 2-5 의 「이름 붙여 넘기기」 입니다.

튜플끼리는 첫 칸부터 비교합니다(힌트). 첫 칸이 판매량이라 판매량 순으로 섭니다.

`ranked[:3]` 은 앞에서 세 개입니다. 1-5 의 `[:끝]` 을 리스트에 쓴 것입니다.

바깥 for 는 2-7 처럼 튜플을 `count, name` 으로 나눠 받습니다. 순위 `rank` 는 1 에서 시작해 바퀴마다 1 씩 올립니다.

**왜 이렇게 푸나**
함수는 딕셔너리를 받아 「(판매량, 이름) 세 쌍」 을 돌려줍니다. 「몇 위」 를 붙이는 일과 출력 모양은 부르는 쪽이 정합니다. 5위까지 보고 싶으면 `[:3]` 한 곳만 바꿉니다.

이 문제의 핵심은 판매량을 앞 칸에 두는 것입니다. sorted 는 튜플의 첫 칸으로 순서를 정하고, 첫 칸이 같을 때만 둘째 칸을 봅니다. 줄 세울 기준을 앞 칸에 둡니다. 지문이 판매량 동점을 없앤 것도 둘째 칸(이름)까지 가지 않게 하려는 것입니다.

**틀리면 이렇게 된다**
★ 의 답입니다. (이름, 판매량) 순서로 모으면 이름으로 줄을 섭니다.

```python
def top3(sales):
    pairs = []
    for name in sales:
        pairs.append((name, sales[name]))
    ranked = sorted(pairs, reverse=True)
    return ranked[:3]

rank = 1
for name, count in top3(sales):
    print(f"{rank}위 {name} {count}개")
    rank = rank + 1
```
```
1위 장조림 35개
2위 어묵볶음 49개
3위 시금치나물 18개
```

글자는 가나다순으로 비교하니, 거꾸로 세우면 「장」 이 맨 앞입니다. 판매량은 뒤죽박죽인데 에러가 없어서 숫자를 봐야 압니다.

`reverse=True` 를 빼면 작은 것부터라 꼴찌 셋이 나옵니다. `1위 시금치나물 18개`, `2위 장조림 35개`, `3위 멸치볶음 42개` 입니다.

1-7 해설에서 본 `.sort()` 로 `ranked = pairs.sort(reverse=True)` 라고 쓰면, `.sort()` 가 아무것도 돌려주지 않아 `ranked` 가 None 이 됩니다.

```python
def top3(sales):
    pairs = []
    for name in sales:
        pairs.append((sales[name], name))
    ranked = pairs.sort(reverse=True)
    return ranked[:3]

print(top3(sales))
```
```
TypeError: 'NoneType' object is not subscriptable
```

「None 에서는 `[ ]` 로 잘라 낼 수 없다」 는 뜻입니다. sorted 는 새 리스트를 돌려주고, `.sort()` 는 리스트를 그 자리에서 고치기만 합니다.

**실제로 쓸 때는**
판매 순위, 점수 상위 몇 명, 많이 본 글처럼 「값으로 줄 세워 위에서 몇 개」 는 이 세 단계(쌍으로 묶기 -> 정렬 -> 자르기)로 합니다.

**앞 문제와의 연결**
2-7 은 주어진 튜플을 나눠 받았고, 이번에는 튜플을 직접 만들었습니다. 1-7 에서 글자 리스트에 쓴 sorted 를 튜플 리스트에 썼습니다. 딕셔너리 돌기는 1-16, 앞에서 자르기는 1-5, `reverse=True` 처럼 이름 붙여 넘기기는 2-5 입니다.

## [2-10] 로그인 3회 제한

**묻는 것**
while 로 입력받기를 되풀이하다가, 맞으면 while 안의 `return True` 로 되풀이와 함수를 한꺼번에 끝내는 것입니다. 중간에 나간 경우(성공)와 되풀이를 끝까지 돌고 나온 경우(3번 틀림)를 가르는 것도 묻습니다.

**코드 한 줄씩**

```python
def login(password):
    tries = 0
    while tries < 3:
        typed = input("비밀번호: ")
        if typed == "":
            print("빈 줄은 세지 않습니다")
        elif typed == password:
            print("로그인 성공")
            return True
        else:
            tries = tries + 1
            print(f"틀렸습니다 ({tries}/3)")
    print("계정 잠금")
    return False

print(f"결과: {login(password)}")
print(f"결과: {login(password)}")
```

`tries` 는 틀린 횟수입니다. 함수 안에서 0 으로 놓아 login 을 부를 때마다 새로 셉니다(2-3).

`while tries < 3:` 은 틀린 횟수가 3 이 되기 전까지 돕니다(1-13). 입력받는 줄이 while 안에 있어 바퀴마다 새로 묻습니다(1-14).

빈 줄이면 안내만 찍고 `tries` 는 그대로라, 같은 횟수로 다시 묻습니다. 맞으면 `return True` 가 while 과 함수를 같이 끝냅니다. 아래 「계정 잠금」 줄로 가지 않습니다.

틀리면 `tries` 를 1 올리고 몇 번째인지 찍습니다. 3 이 되면 while 조건이 거짓이라 되풀이를 빠져나옵니다. while 아래 두 줄은 return 없이 되풀이를 다 돈 경우, 곧 3번 다 틀린 경우에만 닿습니다(힌트).

터미널에서는 이렇게 보입니다. 값을 치고 Enter(맥은 return)를 누릅니다. 엔터만 친 줄은 `비밀번호:` 뒤가 비어 있습니다.

```
비밀번호: 
빈 줄은 세지 않습니다
비밀번호: 1111
틀렸습니다 (1/3)
비밀번호: 9876
로그인 성공
결과: True
비밀번호: 0000
틀렸습니다 (1/3)
비밀번호: 
빈 줄은 세지 않습니다
비밀번호: 1234
틀렸습니다 (2/3)
비밀번호: 5555
틀렸습니다 (3/3)
계정 잠금
결과: False
```

두 번째 login 은 `tries` 가 다시 0 부터라 0000 이 `(1/3)` 입니다. 「결과:」 줄이 login 마다 맨 끝에 찍히는 것은 2-8 과 같은 까닭입니다. f-string 은 login 이 값을 돌려준 뒤에 완성됩니다.

**왜 이렇게 푸나**
함수가 받는 것은 맞는 비밀번호, 돌려주는 것은 성공했나(True/False)입니다. 「로그인 성공」 같은 안내는 함수 안에서 찍지만, 그다음 할 일(화면을 열지, 막을지)은 돌려받은 값으로 바깥에서 정합니다.

끝나는 길이 둘입니다. 성공은 while 안의 return, 실패는 while 을 다 돈 뒤의 return 입니다. 1-14 의 `while True` + `break` 로도 쓸 수 있지만, 빠져나온 뒤에 「성공해서 나왔나, 3번 틀려서 나왔나」 를 다시 가려야 합니다. return 은 나가는 자리마다 답을 같이 돌려주니 그 검사가 필요 없습니다.

**틀리면 이렇게 된다**
★ 의 답입니다. 빈 줄 갈래(`if typed == "":` 와 그 아래 한 줄)를 빼고 `elif` 를 `if` 로 바꾸면 빈 줄도 틀린 것으로 셉니다. 칸과 같은 7개를 차례로 넣으면, 첫 login 은 엔터가 `(1/3)`, 1111 이 `(2/3)` 이 된 뒤 9876 에서 성공해 「2번 틀리고 성공」 이 됩니다. 두 번째 login 은 0000 `(1/3)`, 엔터 `(2/3)`, 1234 `(3/3)` 에서 잠기고 5555 는 묻지도 않습니다. 실수로 엔터를 친 사람의 계정이 잠기는 셈입니다.

`return True` 를 빼면 「로그인 성공」 을 찍고도 계속 묻습니다. 첫 login 이 9876 뒤에 0000, 엔터, 1234 를 더 받아 `(3/3)` 에서 잠기고 `결과: False` 를 냅니다.

비밀번호를 숫자로 바꿔 받으면 첫 입력(엔터만)에서 멈춥니다.

```python
typed = int(input("비밀번호: "))
```
```
ValueError: invalid literal for int() with base 10: ''
```

2-2 의 빈 점수와 같은 에러입니다. 빈 줄이 아니어도 숫자 `9876` 과 글자 `"9876"` 은 `==` 로 비교하면 False 라 맞게 쳐도 통과하지 못합니다. `input()` 은 늘 문자열이고(1-4) `password` 도 문자열이니, 비밀번호는 숫자처럼 보여도 글자끼리 비교합니다.

**실제로 쓸 때는**
로그인·결제 비밀번호·인증번호처럼 횟수를 세는 입력은 「빈 입력은 세지 않기」 「맞으면 바로 나가기」 「다 쓰면 잠그기」 세 갈래로 짭니다. 실제 서비스에서는 틀린 횟수를 서버에 남겨 두어, 프로그램을 다시 켜도 이어서 세게 합니다.

**앞 문제와의 연결**
1-13 의 `while 조건:`, 1-14 의 「되풀이 안에서 입력받기」, 1-10 의 `elif` 를 함수에 넣고, 2-3 의 「if 안의 return」 을 while 안으로 옮겼습니다. 2-11 에서는 되풀이 입력에 딕셔너리를 더해 장바구니를 만듭니다.

## [2-11] 카페 장바구니

**묻는 것**
`while True:` 로 입력받기를 되풀이하면서, 받은 메뉴를 딕셔너리에 세어 담는 법을 묻습니다. 빈 장바구니를 만드는 줄을 어디에 두느냐가 핵심입니다.

**코드 한 줄씩**

```python
menu = {"아메리카노": 4500, "라떼": 5000, "쿠키": 3200}
def take_order(menu):
    cart = {}
    while True:
        name = input("메뉴: ")
        if name == "결제":
            break
        if name in menu:
            cart[name] = cart.get(name, 0) + 1
        else:
            print(f"{name}: 메뉴에 없음")
    return cart

cart = take_order(menu)
total = 0
for name in cart:
    amount = menu[name] * cart[name]
    total = total + amount
    print(f"{name} x{cart[name]} = {amount:,}원")
print(f"합계 {total:,}원")
```

`cart = {}` 는 while 보다 위에서 한 번만 만듭니다. 이 빈 딕셔너리에 주문이 쌓입니다.
`input("메뉴: ")` 은 while 안에 있어서 바퀴마다 새로 묻습니다(1-14).
「결제」 검사가 맨 앞입니다. 결제면 `break` 로 while 을 빠져나가 `return cart` 로 갑니다.
`cart.get(name, 0)` 은 처음 담는 메뉴면 0, 이미 담은 메뉴면 지금 수량을 줍니다(2-8). 거기에 1을 더해 다시 넣습니다.
메뉴에 없는 이름은 담지 않고 안내만 찍습니다.
함수 밖에서는 장바구니를 돌며 「단가 x 수량」 으로 금액을 내고 합계에 쌓습니다. 딕셔너리는 넣은 순서를 기억해서, 담은 순서대로 찍힙니다.

터미널 화면은 문제 칸과 같습니다. `메뉴: ` 뒤가 직접 친 값이고, 치고 나서 Enter(맥은 return)를 누릅니다.

**왜 이렇게 푸나**
take_order 는 메뉴판을 받아 장바구니(메뉴: 수량)를 돌려줍니다. 묻고 담는 일만 하고 돈 계산은 하지 않습니다. 그래서 같은 장바구니로 영수증을 찍든 합계만 내든 함수는 고치지 않아도 됩니다.
2-10 은 while 안의 return 으로 끝냈고, 여기서는 break 로 빠져나온 뒤 return 합니다. 끝나는 길이 「결제」 하나뿐이라 어느 쪽이든 됩니다.
`.get` 대신 1-16 처럼 `if name in cart:` 와 `else:` 로 나눠 써도 출력은 같습니다.

**틀리면 이렇게 된다**
★ 의 답입니다. `cart = {}` 를 while 안 첫 줄로 옮기면 바퀴마다 장바구니가 비워집니다.

```python
    while True:
        cart = {}
        name = input("메뉴: ")
```
```
메뉴: 아메리카노
메뉴: 라떼
메뉴: 아메리카노
메뉴: 핫초코
핫초코: 메뉴에 없음
메뉴: 쿠키
메뉴: 결제
합계 0원
```

「결제」 를 친 바퀴에서도 먼저 비우고 묻기 때문에, 돌려주는 장바구니는 늘 빈 딕셔너리입니다. 에러가 없어서 더 찾기 어렵습니다.

`.get` 없이 `cart[name] + 1` 로 쓰면 첫 메뉴에서 멈춥니다. 처음 담는 메뉴는 아직 장바구니에 없습니다(힌트).

```python
cart = {}
name = "아메리카노"
cart[name] = cart[name] + 1
```
```
KeyError: '아메리카노'
```

터미널에는 `메뉴: 아메리카노` 한 줄 뒤에 이 에러가 나옵니다.

`return cart` 를 한 단계 더 들여 while 안에 넣으면 첫 메뉴를 담자마자 함수가 끝납니다. `메뉴: 아메리카노` 다음에 `아메리카노 x1 = 4,500원` 과 `합계 4,500원` 만 나오고 다시 묻지 않습니다.

「결제」 검사를 메뉴 검사 뒤로 보내면 `메뉴: 결제` 아래에 `결제: 메뉴에 없음` 이 한 줄 더 찍힙니다. 합계는 맞아서 놓치기 쉽습니다.

**실제로 쓸 때는**
키오스크 주문, 재고 입력처럼 「끝내는 말이 나올 때까지 받아서 모은다」 는 화면이 이 모양입니다. 모을 그릇은 반복 밖에서 한 번 만들고, 끝내는 말은 맨 먼저 검사합니다.

**앞 문제와의 연결**
1-14 의 `while True` + `break` 입력에 2-8 의 `.get(키, 없을 때 값)` 을 더했습니다. 「메뉴에 없음」 안내도 2-8 과 같습니다. 2-10 처럼 입력은 함수 안에서 받습니다.

## [2-12] 대출일수에 섞인 글자

**묻는 것**
`.strip()` 으로 공백을 뗀 뒤 `.isdigit()` 으로 숫자로만 된 글자인지 보고, 통과한 것만 `int()` 로 바꾸는 순서를 묻습니다. 결과는 목록 두 개로 돌려줍니다.

**코드 한 줄씩**

```python
raw_days = ["14", " 7 ", "열흘", "", "5일"]
def split_days(values):
    numbers = []
    others = []
    for value in values:
        value = value.strip()
        if value.isdigit():
            numbers.append(int(value))
        else:
            others.append(value)
    return numbers, others

numbers, others = split_days(raw_days)
total = 0
for day in numbers:
    total = total + day
print(f"숫자로 바꾼 것: {numbers} / 합계 {total}일")
print(f"못 바꾼 것: {others}")
```

빈 목록 두 개를 for 위에 만들고, 바퀴마다 둘 중 하나에 넣습니다.
`value = value.strip()` 은 공백을 뗀 값을 같은 이름에 다시 담습니다. 아래 줄은 전부 뗀 값을 봅니다.
`.isdigit()` 은 글자가 0~9 로만 되어 있으면 True 입니다. 「열흘」 과 「5일」 은 숫자 아닌 글자가 섞여 False, 빈 글자 `""` 도 False 입니다.
True 일 때만 `int(value)` 로 바꿉니다. 검사를 통과한 값이라 int 에서 멈출 일이 없습니다.
`return numbers, others` 로 두 목록을 한꺼번에 돌려주고, 부르는 쪽에서 두 변수로 나눠 받습니다(2-6).
합계는 숫자 목록만 돌며 쌓습니다.

**왜 이렇게 푸나**
split_days 는 섞인 목록을 받아 (숫자 목록, 못 바꾼 목록) 을 돌려줍니다. 가르기만 하고 합계는 부르는 쪽이 냅니다. 못 바꾼 값도 버리지 않고 돌려주니, 누가 무엇을 잘못 적었는지 다시 물어볼 수 있습니다.
★ 의 답은 False 입니다. 공백도 숫자가 아닌 글자라서입니다. 그래서 떼기가 검사보다 먼저입니다(힌트).
합계 줄은 `total = sum(numbers)` 로 써도 같은 21 이 나옵니다. 1-11 해설에서 본 sum 입니다.

**틀리면 이렇게 된다**
strip 줄을 빼면 `" 7 "` 이 검사에서 떨어집니다. 에러는 없고 숫자가 하나 줄어듭니다.

```python
    for value in values:
        if value.isdigit():
```
```
숫자로 바꾼 것: [14] / 합계 14일
못 바꾼 것: [' 7 ', '열흘', '', '5일']
```

못 바꾼 목록에 공백이 붙은 채로 들어가서, 목록을 찍어 보면 무엇이 문제였는지 보입니다.

isdigit 검사 없이 전부 `int()` 로 바꾸면 「열흘」 에서 멈춥니다.

```python
for value in raw_days:
    print(int(value.strip()))
```
```
ValueError: invalid literal for int() with base 10: '열흘'
```

14 와 7 은 찍히고 세 번째 값에서 멈춥니다.

`int(" 7 ")` 은 7 이 됩니다. int 는 앞뒤 공백을 스스로 떼지만 isdigit 은 떼지 않습니다. 「int 가 되니 isdigit 도 되겠지」 하고 strip 을 빼면 위처럼 7 을 잃습니다.

**실제로 쓸 때는**
폼이나 표에 손으로 적은 숫자를 받을 때 「떼고 -> 검사하고 -> 바꾸기」 를 거의 그대로 씁니다. isdigit 은 `"-3"` 과 `"3.5"` 에도 False 를 줍니다. 음수나 소수가 올 수 있는 값이면 다른 검사가 필요합니다. 에러가 난 뒤 잡는 방법(try)은 고급에서 씁니다.

**앞 문제와의 연결**
2-2 는 빈 점수를 `!= ""` 로 걸렀습니다. 이번에는 빈 값과 글자를 isdigit 하나로 같이 거릅니다. 두 값 돌려주기는 2-6 과 같고, 2-20 에서 대출일수 칸을 이 방법으로 검사합니다.

## [2-13] 방문 기록 더러운 줄

**묻는 것**
맨 앞에 BOM 이 붙은 CSV 를 `utf-8-sig` 로 읽고, 머리줄은 `continue` 로 건너뛰고, `and` 로 「칸이 3개이고 셋째 칸이 비지 않은」 줄만 살리는 법을 묻습니다.

**코드 한 줄씩**

```python
def read_visits(path):
    kept = []
    bad = []
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            if no == 1:
                continue
            line = line.strip()
            parts = line.split(",")
            if len(parts) == 3 and parts[2].strip() != "":
                kept.append(line)
            else:
                bad.append((no, line))
    return kept, bad

kept, bad = read_visits("visits.csv")
print(f"살린 줄 {len(kept)}개 / 버린 줄 {len(bad)}개")
for item in bad:
    print(f"{item[0]}번 줄: [{item[1]}]")
```

`no` 는 몇 번째 줄인지 셉니다. 줄을 읽자마자 1을 더해서 머리줄이 1번입니다.
`if no == 1: continue` 는 이번 바퀴의 남은 줄을 건너뛰고 다음 줄로 갑니다. 머리줄은 어느 목록에도 안 들어갑니다.
`line.strip()` 으로 줄 끝의 `\n` 을 먼저 떼고 쉼표로 나눕니다.
`and` 는 양쪽이 다 True 여야 True 입니다. 왼쪽 `len(parts) == 3` 이 False 면 오른쪽은 보지도 않습니다. 칸이 2개인 줄에서 `parts[2]` 를 꺼내다 멈추지 않는 것이 이 덕분입니다(힌트).
버린 줄은 `(no, line)` 튜플로 담아 줄번호와 원본을 같이 둡니다(2-7).
출력에서 `item[0]` 은 줄번호, `item[1]` 은 원본입니다.

**왜 이렇게 푸나**
read_visits 는 파일 이름을 받아 (살린 줄 목록, 버린 줄 목록) 을 돌려줍니다. 화면에 찍는 일은 밖에서 합니다. 2-14 가 이 함수를 그대로 다시 불러 버린 줄을 파일로 씁니다. 읽기를 함수로 떼어 둔 덕분입니다.
9번 빈 줄은 `"".split(",")` 이 `['']`(칸 1개)가 되어 칸 수에서 걸립니다. 12번은 칸이 2개, 4번은 칸은 3개인데 셋째 칸이 비었습니다.
「사십」 이 든 7번 줄과 메일에 @ 가 없는 11번 줄은 살립니다. 지문이 칸 수와 빈 값만 보라고 했습니다.

★ 의 답입니다. `"utf-8"` 로 열고 첫 줄을 나누면 첫 칸 앞에 `\ufeff` 가 붙습니다. 화면에는 안 보이는 BOM 글자입니다.

```python
with open("visits.csv", encoding="utf-8") as f:
    for line in f:
        print(line.strip().split(","))
        break
```
```
['\ufeff날짜', '방문자메일', '머문분']
```

`"utf-8-sig"` 로 열면 `['날짜', '방문자메일', '머문분']` 입니다. 그런데 이 문제는 `"utf-8"` 로 열어도 칸과 출력이 똑같습니다. 머리줄을 번호로 건너뛰어서 BOM 이 붙은 칸을 아무도 안 쓰기 때문입니다. 칸만 보고는 못 가려내는 자리입니다. 그래도 CSV 는 `utf-8-sig` 로 여는 버릇을 들이세요. 머리줄 글자를 비교하는 순간(`parts[0] == "날짜"`) utf-8 쪽은 False 가 됩니다.

**틀리면 이렇게 된다**
`and` 양쪽을 바꿔 쓰면 9번 빈 줄에서 멈춥니다. 칸이 1개뿐인데 셋째 칸부터 꺼내기 때문입니다.

```python
parts = "".split(",")
if parts[2].strip() != "" and len(parts) == 3:
    print("살림")
```
```
IndexError: list index out of range
```

정답 함수에서 순서만 바꿔도 같은 에러로 멈추고, 화면에는 한 줄도 안 나옵니다.

`continue` 두 줄을 빼면 머리줄도 칸이 3개이고 셋째 칸이 「머문분」 이라 살린 줄에 들어갑니다. 첫 줄이 `살린 줄 10개 / 버린 줄 3개` 로 바뀌고 나머지 세 줄은 그대로입니다.

`line = line.strip()` 을 빼면 원본 끝에 `\n` 이 남아 닫는 대괄호가 다음 줄로 내려갑니다. 개수는 그대로입니다.

```
살린 줄 9개 / 버린 줄 3개
4번 줄: [2026-11-02,daeun@example.com,
]
9번 줄: [
]
12번 줄: [2026-11-05,seoyeon@example.com
]
```

**실제로 쓸 때는**
사람이 손댄 CSV 에는 거의 늘 깨진 줄이 섞여 옵니다. 버린 줄을 줄번호와 같이 남겨 두면 원본 파일에서 바로 찾아 고칠 수 있습니다. 다른 프로그램이 저장한 CSV 는 맨 앞에 BOM 이 붙어 있는 일이 있어서, 읽을 때는 `utf-8-sig` 가 안전합니다(BOM 이 없어도 그대로 읽습니다).

**앞 문제와의 연결**
1-18 의 `with open` + `for line in f` 에 2-1 의 split 과 2-2 의 len 을 더했습니다. 2-14 가 여기서 버린 줄을 파일로 씁니다.

## [2-14] 버린 줄을 사유와 함께 로그로

**묻는 것**
파일을 `"w"` 로 열어 `f.write` 로 한 줄씩 쓰는 법을 묻습니다. write 는 줄바꿈을 붙여 주지 않는다는 것, 다 쓴 파일은 with 밖에서 다시 읽는다는 것도 봅니다.

**코드 한 줄씩**

```python
def skip_reason(line):
    if len(line.split(",")) != 3:
        return "칸 수"
    return "빈 값"

def write_skipped(path, bad):
    with open(path, "w", encoding="utf-8") as f:
        for item in bad:
            f.write(f"{item[0]}: {skip_reason(item[1])}: {item[1]}\n")

kept, bad = read_visits("visits.csv")
write_skipped("visits_skipped.txt", bad)
print(f"{len(bad)}줄 썼습니다 -> visits_skipped.txt")
with open("visits_skipped.txt", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```

skip_reason 은 칸이 3개가 아니면 그 자리에서 「칸 수」 를 돌려주고 끝납니다(2-3 의 if 안 return). 그 아래까지 왔으면 칸은 3개인데 버려진 줄이니 「빈 값」 입니다.
`open(path, "w", encoding="utf-8")` 의 `"w"` 는 쓰기로 연다는 뜻입니다. 파일이 없으면 새로 만들고, 있으면 내용을 비우고 처음부터 씁니다.
`f.write(...)` 는 받은 글자를 그대로 파일 뒤에 붙입니다. 줄 끝 `\n` 은 직접 넣습니다.
f-string 안에서 skip_reason 을 바로 불러 사유를 넣었습니다.
write_skipped 는 돌려주는 값이 없습니다. 파일을 쓰는 것이 할 일 전부입니다.
2-13 의 read_visits 를 다시 불러 버린 줄 목록을 받습니다. 함수로 만들어 둔 덕분에 한 줄이면 됩니다.
다시 읽는 with 는 write_skipped 가 끝난 뒤에 엽니다.

**왜 이렇게 푸나**
사유 정하기(skip_reason)와 파일 쓰기(write_skipped)를 나눴습니다. skip_reason 은 줄 하나를 받아 글자 하나를 돌려주니 `skip_reason("")` 처럼 따로 불러 시험해 볼 수 있습니다. 사유가 하나 늘면 이 함수만 고칩니다.
2-13 이 원본을 strip 해서 넘겨주므로 9번 빈 줄의 원본은 `""` 입니다. 그래서 파일의 9번 줄은 `9: 칸 수: ` 로 끝에 공백이 하나 남고, 다시 읽어 strip 하면 `9: 칸 수:` 로 찍힙니다.
쓰기를 끝낸 with 밖에서 다시 여는 것은, with 가 파일을 닫을 때 쓴 내용이 파일에 다 들어가기 때문입니다(힌트).

**틀리면 이렇게 된다**
★ 의 답입니다. `\n` 을 빼면 세 줄이 한 줄로 붙어 들어갑니다. 「3줄 썼습니다」 안내는 그대로라 더 헷갈립니다.

```
3줄 썼습니다 -> visits_skipped.txt
4: 빈 값: 2026-11-02,daeun@example.com,9: 칸 수: 12: 칸 수: 2026-11-05,seoyeon@example.com
```

다시 읽는 줄을 쓰기 with 안으로 옮기면(밖의 읽는 줄은 지우고) 파일 내용이 하나도 안 찍힙니다.

```python
    with open(path, "w", encoding="utf-8") as f:
        for item in bad:
            f.write(f"{item[0]}: {skip_reason(item[1])}: {item[1]}\n")
        with open(path, encoding="utf-8") as g:
            for line in g:
                print(line.strip())
```
```
3줄 썼습니다 -> visits_skipped.txt
```

write 는 쓸 글자를 잠시 모아 뒀다가 파일을 닫을 때 한꺼번에 씁니다. 닫기 전에 읽으면 파일이 아직 비어 있습니다. 실행이 끝난 뒤 파일을 열어 보면 세 줄이 다 들어 있습니다.

write 에 숫자를 넘기면 멈춥니다. print 는 숫자도 찍어 주지만 write 는 글자만 받습니다.

```python
item = (4, "2026-11-02,daeun@example.com,")
with open("visits_skipped.txt", "w", encoding="utf-8") as f:
    f.write(item[0])
```
```
TypeError: write() argument must be str, not int
```

f-string 에 넣거나 `str(item[0])` 으로 바꿔 넘깁니다.

`"w"` 를 빠뜨리면 읽기로 열립니다. 파일이 아직 없으면 `FileNotFoundError: [Errno 2] No such file or directory: 'visits_skipped.txt'`, 이미 있으면 `io.UnsupportedOperation: not writable` 로 멈춥니다.

**실제로 쓸 때는**
처리하다 버린 자료를 「몇 번째 줄 / 왜 / 원본」 으로 남긴 파일을 흔히 로그라고 부릅니다. 원본을 고칠 사람이 이 파일만 보고 일할 수 있습니다. `"w"` 는 돌릴 때마다 덮어씁니다. 지난 기록 뒤에 이어 붙이려면 `"a"`(덧붙이기)로 엽니다.

**앞 문제와의 연결**
2-13 의 read_visits 를 그대로 다시 썼습니다. 다시 읽는 부분은 1-18 과 같습니다. 2-15·2-20 은 읽기·거르기·쓰기를 한 흐름으로 묶습니다.

## [2-15] 단어장 중복 걸러내기

**묻는 것**
파일을 읽으며 대소문자만 다른 단어를 같은 단어로 보고(소문자로 바꾼 키), 처음 나온 줄만 남겨 새 파일로 쓰는 법을 묻습니다. 2-13 의 읽기와 2-14 의 쓰기를 한 함수에 담습니다.

**코드 한 줄씩**

```python
def clean_wordbook(src, dst):
    words = {}
    no = 0
    with open(src, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            if no == 1:
                continue
            parts = line.strip().split(",")
            word = parts[0].strip().lower()
            if len(parts) != 3 or word in words:
                continue
            words[word] = f"{word},{parts[1].strip()},{parts[2].strip()}"
    with open(dst, "w", encoding="utf-8") as f:
        f.write("영어,뜻,맞힌횟수\n")
        for word in words:
            f.write(words[word] + "\n")
    return len(words), no - 1 - len(words)

kept, dropped = clean_wordbook("wordbook.csv", "wordbook_clean.csv")
print(f"남긴 단어 {kept}개 / 버린 줄 {dropped}개")
with open("wordbook_clean.csv", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```

`words` 딕셔너리가 「이미 나온 단어」 를 기억합니다. 키는 소문자 영어, 값은 파일에 쓸 한 줄입니다.
머리줄 건너뛰기는 2-13 과 같습니다.
`parts[0].strip().lower()` 로 앞뒤 공백을 떼고 소문자로 바꿉니다. 「Invoice」 와 「INVOICE」 가 둘 다 `invoice` 가 됩니다. 빈 줄도 나누면 칸 하나(`''`)는 있어서 `parts[0]` 에서 멈추지 않습니다.
`or` 는 둘 중 하나만 True 여도 True 입니다(1-9). 칸이 3개가 아니거나 이미 나온 단어면 `continue` 로 버립니다.
`word in words` 는 딕셔너리에 그 키가 있는지 봅니다(1-16).
살아남은 줄은 칸마다 공백을 떼고 쉼표로 다시 이어 값으로 넣습니다.
쓰기는 읽기 with 가 끝난 뒤 따로 엽니다. 머리줄을 먼저 쓰고, 딕셔너리를 돌며 넣은 순서대로 씁니다.
`no - 1 - len(words)` 는 「읽은 줄 수 - 머리줄 - 남긴 수」, 곧 버린 줄 수입니다.

**왜 이렇게 푸나**
clean_wordbook 은 읽을 파일과 쓸 파일 이름을 받아 (남긴 단어 수, 버린 줄 수) 를 돌려줍니다. 파일 이름을 인자로 받으니 다른 단어장에도 그대로 씁니다.
기억할 곳을 딕셔너리로 한 것은 「이미 나왔나」 검사와 「쓸 줄 모으기」 를 한 그릇으로 하려고서입니다. 단어 목록과 줄 목록을 리스트 두 개로 따로 두고 `in` 으로 봐도 같은 답이 나옵니다.
버린 4줄은 INVOICE(중복) · 빈 줄 · inventory(칸 1개) · escalate(뜻에 쉼표가 들어가 칸 4개) 입니다. 맞힌횟수는 안 보니 빈 값인 refund 줄과 「두번」 인 receipt 줄은 남습니다.

칸이 못 가려내는 풀이가 셋 있습니다.
버린 줄 수를 버릴 때마다 1씩 세는 변수로 구해도 됩니다. 정답처럼 끝에 빼서 구하든, 세어서 구하든 출력은 같습니다.
`"utf-8-sig"` 대신 `"utf-8"` 로 열어도 같습니다. 2-13 처럼 머리줄을 번호로 건너뛰어 BOM 이 붙은 칸을 안 쓰기 때문입니다.
`or word in words` 를 빼도 같습니다. 이미 있는 키에 다시 넣으면 자리는 처음 그대로이고 값만 뒤 줄로 바뀝니다. 이 파일은 겹친 두 줄이 소문자로 바꾸면 똑같은 `invoice,청구서,5` 라 티가 안 납니다. 뒤 줄의 횟수가 달랐다면 처음 줄이 아니라 뒤 줄 값이 남습니다.

**틀리면 이렇게 된다**
★ 의 답은 9개입니다. 소문자로 안 바꾸면 Invoice 와 INVOICE 가 다른 단어가 되어 둘 다 남습니다.

```
남긴 단어 9개 / 버린 줄 3개
영어,뜻,맞힌횟수
budget,예산,3
Invoice,청구서,5
refund,환불,
deadline,마감일,7
INVOICE,청구서,5
receipt,영수증,두번
warranty,보증,2
shipment,배송,4
vendor,공급처,0
```

budget 줄은 소문자로 안 바꿔도 맞게 나옵니다. 원래 소문자이고, 앞뒤 공백은 strip 이 뗐기 때문입니다.

**실제로 쓸 때는**
메일 주소·상품 코드·태그처럼 「대소문자가 달라도 같은 것」 은 비교하기 전에 모양을 하나로 맞춥니다. 맞춘 값을 딕셔너리 키로 쓰면 중복이 저절로 걸러집니다.

**앞 문제와의 연결**
2-13 의 읽기 · 2-14 의 쓰기 · 1-16 의 딕셔너리 `in` 을 한 함수에 넣었습니다. 키를 만드는 `.strip().lower()` 는 2-4 의 메일 정리와 같습니다.

## [2-16] 없는 파일은 다음 후보로

**묻는 것**
`os.path.exists` 로 파일이 있는지 먼저 보고, 있는 첫 파일에서 바로 `return` 하는 법을 묻습니다. 하나도 없을 때 돌려줄 값도 정해 둡니다.

**코드 한 줄씩**

```python
contact_files = ["contacts_today.csv", "contacts.csv", "contacts_old.csv"]
word_files = ["words_a.csv", "words_b.csv"]
def read_first(paths):
    for path in paths:
        if os.path.exists(path):
            count = 0
            with open(path, encoding="utf-8-sig") as f:
                for line in f:
                    count = count + 1
            return path, count
        print(f"{path} 없음 -> 다음 후보")
    return "", 0

path, count = read_first(contact_files)
print(f"쓴 파일 '{path}' / {count}줄")
path, count = read_first(word_files)
print(f"쓴 파일 '{path}' / {count}줄")
```

`for path in paths:` 로 후보를 앞에서부터 봅니다.
`os.path.exists(path)` 는 그 이름의 파일이 있으면 True 입니다. `os` 는 맨 위 두 줄에서 이미 불러왔습니다.
있으면 열어서 줄마다 `count` 를 1씩 올립니다. 머리줄과 빈 줄도 한 줄로 셉니다. contacts.csv 는 머리줄 1 + 7줄(빈 줄 포함)이라 8줄입니다.
`return path, count` 에서 함수가 끝납니다. 뒤 후보 contacts_old.csv 는 보지 않습니다(힌트).
「없음」 을 찍는 print 는 if 밖에 있지만, 있는 파일이면 그 전에 return 으로 나가니 없는 파일일 때만 찍힙니다. `else:` 를 붙여 써도 같습니다.
`return "", 0` 은 for 가 끝까지 돈 뒤, 곧 후보가 다 없을 때만 닿습니다.

**왜 이렇게 푸나**
read_first 는 후보 목록을 받아 (쓴 파일 이름, 줄 수) 를 돌려줍니다. 못 찾았을 때도 같은 모양 `("", 0)` 을 돌려주니, 부르는 쪽은 언제나 두 변수로 나눠 받으면 됩니다(2-6).
없는 파일을 그냥 열면 ★ 처럼 멈춥니다. 열기 전에 확인하는 것이 이 문제의 방법입니다. 에러가 난 뒤 잡는 방법(try)은 고급에서 씁니다.
줄 수만 세니 `"utf-8-sig"` 대신 `"utf-8"` 로 열어도 같은 8줄이 나옵니다. 칸이 못 가려내는 자리입니다. 줄 안의 글자를 쓰는 순간 2-13 처럼 BOM 이 끼어드니, CSV 는 `utf-8-sig` 로 엽니다.

**틀리면 이렇게 된다**
★ 의 문구입니다. 확인 없이 첫 후보를 열면 이렇게 멈춥니다.

```python
with open("contacts_today.csv", encoding="utf-8-sig") as f:
    for line in f:
        print(line)
```
```
FileNotFoundError: [Errno 2] No such file or directory: 'contacts_today.csv'
```

따옴표 안이 파이썬이 찾은 이름입니다(1-18).

`return "", 0` 을 한 단계 더 들여 for 안에 넣으면 첫 후보가 없을 때 바로 포기합니다. contacts.csv 가 있는데도 못 씁니다.

```
contacts_today.csv 없음 -> 다음 후보
쓴 파일 '' / 0줄
words_a.csv 없음 -> 다음 후보
쓴 파일 '' / 0줄
```

**실제로 쓸 때는**
설정 파일을 「작업 폴더 -> 사용자 폴더 -> 기본값」 순서로 찾는 프로그램이 이 모양입니다. `os.path.exists` 는 폴더 이름에도 True 를 줍니다. 파일만 보려면 `os.path.isfile` 을 씁니다.

**앞 문제와의 연결**
2-10 의 「되풀이 안의 return」 을 for 에 썼습니다. 줄 세기는 1-18 의 읽기와 같고, 두 값 돌려주기는 2-6 입니다. import 를 직접 쓰는 것은 다음 2-17 입니다.

## [2-17] 택배 도착 예정일

**묻는 것**
`import datetime` 으로 날짜를 만들고, `timedelta` 로 며칠 뒤를 구하고, `.weekday()` 요일 번호로 주말을 월요일로 미루는 법을 묻습니다.

**코드 한 줄씩**

```python
import datetime
ship_days = [1, 2, 3, 6]
day_names = ["월", "화", "수", "목", "금", "토", "일"]
def arrival(order_date, days):
    arrive = order_date + datetime.timedelta(days=days)
    if arrive.weekday() == 5:
        arrive = arrive + datetime.timedelta(days=2)
    elif arrive.weekday() == 6:
        arrive = arrive + datetime.timedelta(days=1)
    return arrive

order_date = datetime.date(2026, 11, 26)
print(f"주문일 {order_date} ({day_names[order_date.weekday()]})")
for days in ship_days:
    arrive = arrival(order_date, days)
    print(f"배송 {days}일 -> {arrive} ({day_names[arrive.weekday()]})")
```

`import datetime` 은 파이썬에 딸려 오는 날짜 도구 묶음(모듈)을 불러옵니다. 안의 것은 `datetime.date` 처럼 점으로 꺼냅니다.
`day_names` 는 요일 번호(월 0 ~ 일 6)와 같은 순서로 적은 목록입니다. `day_names[번호]` 로 요일 글자를 꺼냅니다.
`order_date + datetime.timedelta(days=days)` 가 「주문일에서 days 일 뒤」 입니다. 11월 30일 다음이 12월 1일인 것처럼 달이 바뀌는 것도 알아서 맞춥니다.
`.weekday()` 가 5(토)면 2일, 6(일)이면 1일 더해 월요일로 미룹니다.
f-string 에 날짜를 그대로 넣으면 `2026-11-26` 모양으로 찍힙니다.
출력 줄의 요일은 함수가 돌려준, 미룬 뒤의 날짜로 다시 구합니다(힌트).

**왜 이렇게 푸나**
arrival 은 주문일과 배송일수를 받아 도착일을 돌려줍니다. 글자가 아니라 날짜를 돌려주니, 부르는 쪽에서 요일을 구하든 날짜를 더 계산하든 마음대로 씁니다.
★ 의 답입니다. 배송 2일은 11월 28일(토)이라 2일 미뤄 30일(월), 배송 3일은 29일(일)이라 1일 미뤄 역시 30일(월)입니다.
`elif` 대신 `if` 를 두 번 써도 출력이 같습니다. 토요일에 2일을 더하면 월요일이라 두 번째 검사에 걸리지 않습니다.

**틀리면 이렇게 된다**
요일을 미루기 전 날짜로 구하면 날짜는 월요일인데 요일 글자가 (토)·(일) 로 찍힙니다.

```python
for days in ship_days:
    arrive = arrival(order_date, days)
    week = (order_date + datetime.timedelta(days=days)).weekday()
    print(f"배송 {days}일 -> {arrive} ({day_names[week]})")
```
```
주문일 2026-11-26 (목)
배송 1일 -> 2026-11-27 (금)
배송 2일 -> 2026-11-30 (토)
배송 3일 -> 2026-11-30 (일)
배송 6일 -> 2026-12-02 (수)
```

날짜에 숫자를 바로 더하면 멈춥니다. 며칠 뒤는 timedelta 로 만들어 더합니다.

```python
arrive = order_date + 2
```
```
TypeError: unsupported operand type(s) for +: 'datetime.date' and 'int'
```

없는 날짜는 만드는 자리에서 멈춥니다.

```python
order_date = datetime.date(2026, 11, 31)
```
```
ValueError: day 31 must be in range 1..30 for month 11 in year 2026
```

3.9 에서는 `ValueError: day is out of range for month` 로 나옵니다.

**실제로 쓸 때는**
도착 예정일, 반납일, 결제일처럼 「며칠 뒤, 주말이면 미룸」 은 쇼핑몰이나 도서관 프로그램에 흔합니다. 공휴일까지 빼려면 쉬는 날 목록을 만들어 `in` 으로 검사하는 줄이 더 붙습니다.

**앞 문제와의 연결**
2-16 까지는 맨 위의 `import os` 를 쓰기만 했고, 여기서 처음 import 를 직접 씁니다. if·elif 갈래는 1-10 과 같은 모양이고, 목록에서 번호로 꺼내기는 초급부터 쓴 `목록[번호]` 입니다.

## [2-18] 메뉴별 매출 정산 표

**묻는 것**
f-string 서식으로 표를 만드는 법을 묻습니다. 숫자는 폭·쉼표·소수 자리를, 글자 머리줄은 폭을 맞추고, 한글은 화면에서 한 글자가 두 칸이라는 점을 셈에 넣습니다.

**코드 한 줄씩**

```python
menu_sales = {"아메리카노": 144000, "라떼": 85000, "쿠키": 38400, "케이크": 52000}
def print_report(sales):
    total = 0
    for name in sales:
        total = total + sales[name]
    print(f"{'매출':>7}{'비중':>5}  메뉴")
    print("-" * 28)
    for name in sales:
        share = sales[name] / total * 100
        print(f"{sales[name]:>9,}{share:>6.1f}%  {name}")
    print("-" * 28)
    print(f"{total:>9,}{100:>6.1f}%  합계")

print_report(menu_sales)
```

첫 for 는 비중의 분모가 될 합계를 먼저 구합니다. 비중은 합계가 있어야 낼 수 있어서 for 가 두 번입니다.
`{'매출':>7}` 은 글자 「매출」 을 7칸에 오른쪽으로 붙입니다. f-string 안이라 따옴표는 작은따옴표로 씁니다.
`"-" * 28` 은 `-` 를 28번 이어 붙인 글자입니다.
`{sales[name]:>9,}` 는 9칸 오른쪽 맞춤 + 쉼표입니다(1-2). `{share:>6.1f}` 는 6칸 오른쪽 맞춤 + 소수 첫째 자리입니다. 45.0845... 가 `45.1` 로 찍힙니다.
합계 줄의 비중은 계산하지 않고 `100` 을 넣었습니다. `.1f` 가 `100.0` 으로 찍어 줍니다(힌트).

**왜 이렇게 푸나**
print_report 는 매출 딕셔너리를 받아 표를 찍기만 하고 돌려주는 값이 없습니다. 메뉴가 늘어도 딕셔너리만 바꿔 넘기면 표가 늘어납니다.
★ 의 이유입니다. 파이썬은 「매출」 을 2글자로 세지만 화면에서는 4칸을 차지합니다. `>7` 은 공백 5개 + 「매출」 4칸 = 화면 9칸이라 숫자 칸 9칸과 끝이 맞습니다. 「비중」 도 `>5` 가 공백 3개 + 4칸 = 7칸이라 `{share:>6.1f}%` 의 6칸 + `%` 와 맞습니다.
메뉴 이름을 맨 끝 칸에 둔 것도 같은 까닭입니다. 이름 길이가 제각각이라 이름 뒤에 칸이 오면 줄마다 어긋납니다.

**틀리면 이렇게 된다**
머리줄 폭을 숫자 칸과 같은 9·6 으로 쓰면 화면에서 머리 글자가 숫자보다 2칸씩 오른쪽으로 밀립니다.

```
       매출    비중  메뉴
----------------------------
  144,000  45.1%  아메리카노
   85,000  26.6%  라떼
   38,400  12.0%  쿠키
   52,000  16.3%  케이크
----------------------------
  319,400 100.0%  합계
```

`.1f` 를 빼고 `{share:>6}` 만 쓰면 소수점 아래가 다 나옵니다. 폭 6 은 「적어도 6칸」 이라 긴 값을 자르지 않아서, 앞 칸 숫자에 바로 붙어 버립니다.

```
     매출   비중  메뉴
----------------------------
  144,00045.084533500313086%  아메리카노
   85,00026.612398246712587%  라떼
   38,40012.022542266750156%  쿠키
   52,00016.28052598622417%  케이크
----------------------------
  319,400 100.0%  합계
```

`f` 만 빼고 `{share:>6.1}` 로 쓰면 「소수 첫째 자리」 가 아니라 「숫자 1개」 가 되어 아메리카노 줄이 `  144,000 5e+01%  아메리카노` 로 찍힙니다. `5e+01` 은 5 x 10 = 50 이라는 뜻입니다.

f-string 안에서 바깥과 같은 큰따옴표를 쓰면(`{"매출":>7}`) 3.14 에서는 돌지만, 3.9 에서는 `SyntaxError: f-string: expecting '}'` 로 멈춥니다. 어느 버전에서나 돌게 작은따옴표를 씁니다.

**실제로 쓸 때는**
정산표·성적표·재고표를 터미널이나 텍스트 파일로 낼 때 이렇게 칸을 맞춥니다. 비중은 `{sales[name] / total:>7.1%}` 처럼 `%` 서식으로도 찍을 수 있습니다. 100 을 곱하고 `%` 까지 붙여서 `  45.1%` 가 나옵니다.

**앞 문제와의 연결**
1-2 의 `>N,` 칸 맞춤에 1-11 의 `.1f` 와 글자 칸 맞춤을 더했습니다. 합계를 쌓는 첫 for 는 1-11 과 같습니다. 2-20 보고서의 `:>3` 칸도 같은 서식입니다.

## [2-19] 어제 명단 오늘 명단

**묻는 것**
`not in` 으로 「아직 없으면 넣기」(중복 빼기)와 「저쪽에 없는 것 고르기」(명단 비교)를 하는 법을 묻습니다. 비교 전에 공백을 떼는 정리가 왜 먼저인지도 봅니다.

**코드 한 줄씩**

```python
yesterday = ["김민수", "이서연", "박지훈", "정하늘"]
today = [" 이서연", "박지훈 ", "최유진", "이서연", "한도윤", "최유진 "]
def clean_names(names):
    result = []
    for name in names:
        name = name.strip()
        if name not in result:
            result.append(name)
    return result

def only_in(a, b):
    result = []
    for name in a:
        if name not in b:
            result.append(name)
    return result

old = clean_names(yesterday)
new = clean_names(today)
print(f"어제: {old}")
print(f"오늘: {new}")
print(f"새로 온 사람: {only_in(new, old)}")
print(f"빠진 사람: {only_in(old, new)}")
```

clean_names 는 공백을 먼저 떼고, `result` 에 아직 없을 때만 넣습니다. 받은 목록은 건드리지 않고 새 목록을 돌려줍니다.
`not in` 은 `in` 의 반대입니다. 들어 있지 않으면 True 입니다.
only_in 은 a 를 돌며 b 에 없는 이름만 모읍니다.
`only_in(new, old)` 는 오늘에만 있는 사람(새로 온 사람), `only_in(old, new)` 는 어제에만 있는 사람(빠진 사람)입니다. 인자 순서만 바꿨습니다(힌트).

**왜 이렇게 푸나**
정리(clean_names)와 비교(only_in)를 나눴습니다. only_in 하나를 방향만 바꿔 두 번 부르니 같은 코드를 두 번 쓰지 않습니다. 함수 이름과 인자 순서가 「a 에만 있는 것」 이라는 뜻을 담고 있어서, 부르는 줄만 읽어도 무엇을 구하는지 보입니다.
어제 명단도 clean_names 에 넣었습니다. 어제 명단은 깨끗해서 그대로 나오지만, 두 명단을 같은 규칙으로 정리해야 비교가 맞습니다.

**틀리면 이렇게 된다**
★ 의 답은 박지훈입니다. 오늘 명단을 정리하지 않고(`new = today`) 비교하면 `"박지훈 "`(끝에 공백)은 `"박지훈"` 과 다른 이름입니다.

```
어제: ['김민수', '이서연', '박지훈', '정하늘']
오늘: [' 이서연', '박지훈 ', '최유진', '이서연', '한도윤', '최유진 ']
새로 온 사람: [' 이서연', '박지훈 ', '최유진', '한도윤', '최유진 ']
빠진 사람: ['김민수', '박지훈', '정하늘']
```

이서연은 오늘 명단에 공백 없는 「이서연」 도 있어서 빠진 사람에 안 들어갑니다. 대신 새로 온 사람에 공백 붙은 이름들이 섞여 들어갑니다.

clean_names 에서 공백 떼기를 검사 뒤로 미루면 「최유진」 이 두 번 남습니다. 검사하는 순간에는 `"최유진 "` 과 `"최유진"` 이 다른 글자이기 때문입니다. 2-12 의 strip 순서와 같은 함정입니다.

```python
    for name in names:
        if name not in result:
            result.append(name.strip())
```
```
어제: ['김민수', '이서연', '박지훈', '정하늘']
오늘: ['이서연', '박지훈', '최유진', '한도윤', '최유진']
새로 온 사람: ['최유진', '한도윤', '최유진']
빠진 사람: ['김민수', '정하늘']
```

인자를 하나만 넘기면 멈춥니다. 빠진 인자의 이름(`'b'`)까지 알려 줍니다.

```python
print(f"새로 온 사람: {only_in(new)}")
```
```
TypeError: only_in() missing 1 required positional argument: 'b'
```

**실제로 쓸 때는**
어제와 오늘의 회원 목록, 지난달과 이번 달 상품 목록을 비교해 「새로 생긴 것 / 없어진 것」 을 뽑는 일이 많습니다. 사람이 친 값은 비교하기 전에 꼭 같은 규칙으로 정리합니다.

**앞 문제와의 연결**
1-16 의 `in` 을 뒤집은 `not in` 입니다. 정리 함수와 검사 함수를 나눈 짜임은 2-4 와 같습니다. 공백 떼기를 검사보다 먼저 하는 것은 2-12 와 같습니다.

## [2-20] 대출 기록 집계 -- 종합

**묻는 것**
중급에서 쓴 것을 한 번에 엮습니다. CSV 를 읽어(2-13) 깨진 줄을 거르고(2-12 의 isdigit), 도서별 횟수와 일수를 딕셔너리 두 개에 쌓아(2-8 의 .get), 보고서 파일로 씁니다(2-14).

**코드 한 줄씩**

```python
def read_loans(path):
    counts = {}
    days = {}
    dropped = 0
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            if no == 1:
                continue
            parts = line.strip().split(",")
            if len(parts) == 4 and parts[2].strip().isdigit():
                book = parts[0].strip()
                counts[book] = counts.get(book, 0) + 1
                days[book] = days.get(book, 0) + int(parts[2])
            else:
                dropped = dropped + 1
    return counts, days, dropped

def write_report(path, counts, days):
    with open(path, "w", encoding="utf-8") as f:
        f.write("도서별 대출 횟수와 총 일수\n")
        for book in counts:
            f.write(f"{counts[book]}회 {days[book]:>3}일  {book}\n")

counts, days, dropped = read_loans("loans.csv")
write_report("loans_report.txt", counts, days)
print(f"도서 {len(counts)}종 / 버린 줄 {dropped}줄")
with open("loans_report.txt", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```

read_loans 의 `counts` 와 `days` 는 같은 도서 이름을 키로 쓰는 딕셔너리 두 개입니다. `dropped` 는 버린 줄 수, `no` 는 줄번호입니다.
머리줄 건너뛰기는 2-13 과 같습니다.
조건은 「칸이 4개」 그리고 「대출일수의 공백을 뗀 것이 숫자」 입니다. 칸 수를 `and` 왼쪽에 둬서, 칸이 모자란 줄에서는 `parts[2]` 를 꺼내지 않습니다(2-13).
도서 이름은 `parts[0].strip()` 으로 공백을 뗀 것을 키로 씁니다.
`counts.get(book, 0) + 1` 이 횟수, `days.get(book, 0) + int(parts[2])` 가 일수입니다. 같은 줄을 읽을 때 둘을 한꺼번에 더합니다(힌트).
`int(parts[2])` 에는 strip 이 없어도 됩니다. int 는 앞뒤 공백을 스스로 뗍니다(2-12).
조건에 안 맞는 줄은 `dropped` 만 1 올립니다.
write_report 는 제목 줄을 쓰고, `counts` 를 돌며 한 줄씩 씁니다. 키가 같으니 같은 `book` 으로 `days[book]` 을 꺼냅니다. `:>3` 이 일수를 3칸에 맞춥니다.
부르는 쪽에서는 세 값을 나눠 받고(2-6), 보고서를 쓴 뒤 다시 읽어 찍습니다(2-14).

**왜 이렇게 푸나**
읽고 세기(read_loans)와 쓰기(write_report)를 나눴습니다. read_loans 는 파일 이름을 받아 (횟수 딕셔너리, 일수 딕셔너리, 버린 줄 수) 를 돌려주고, write_report 는 그 두 딕셔너리를 받아 파일만 씁니다. 화면용 표가 따로 필요해져도 read_loans 는 그대로 둡니다.
버린 4줄은 대출일수가 빈 4번 줄 · 「열흘」 인 5번 줄 · 8번 빈 줄 · 칸이 3개인 10번 모모 줄입니다. 모모는 두 줄 다 버려져서 보고서에 안 나옵니다.
메일은 안 보니 @ 가 없는 11번 데미안 줄도 셉니다. 파이썬 입문은 메일 대소문자만 다른 3번·6번 줄을 두 번 대출로 세어 2회 42일입니다.
`"utf-8-sig"` 대신 `"utf-8"` 로 열어도 출력이 같습니다. 머리줄을 번호로 건너뛰어서입니다. 칸이 못 가려내는 자리라 2-13 의 이유로 `utf-8-sig` 를 씁니다.

**틀리면 이렇게 된다**
도서 이름의 공백을 안 떼면(`book = parts[0]`) 5종이 됩니다. 줄 맨 앞 공백은 `line.strip()` 이 떼 주지만, 쉼표 앞에 붙은 공백은 남아 `"어린 왕자 "` 가 다른 키가 됩니다.

```
도서 5종 / 버린 줄 4줄
도서별 대출 횟수와 총 일수
1회   7일  어린 왕자
2회  42일  파이썬 입문
2회  19일  데미안
1회  30일  토지
1회  14일  어린 왕자
```

화면으로는 「어린 왕자」 가 두 번 보일 뿐 무엇이 다른지 안 보입니다. 파일의 `1회   7일` 줄 끝에는 공백이 하나 남아 있는데, 다시 읽어 찍을 때 strip 이 지웠기 때문입니다.

대출일수 검사를 빼고 칸 수만 보면 4번 줄의 빈 대출일수에서 멈춥니다.

```python
parts = "어린 왕자,minjae@example.com,,0".split(",")
if len(parts) == 4:
    print(int(parts[2]))
```
```
ValueError: invalid literal for int() with base 10: ''
```

정답 함수에서 isdigit 검사만 빼도 같은 에러로 멈춥니다. `and` 양쪽을 바꾸면(`parts[2].strip().isdigit() and len(parts) == 4`) 8번 빈 줄에서 2-13 과 같은 `IndexError: list index out of range` 로 멈춥니다.

`:>3` 을 빼고 `{days[book]}일` 로 쓰면 횟수와 일수 사이가 한 칸이 되어 `2회 21일  어린 왕자` 처럼 칸과 달라집니다. 일수가 모두 두 자리라서, `:>3` 이 앞에 공백 하나를 채워 칸 모양을 만들고 있었습니다.

**실제로 쓸 때는**
「파일 읽기 -> 깨진 줄 거르기 -> 키별로 쌓기 -> 보고서 쓰기」 는 실무에서 자주 받는 일의 뼈대입니다. 거르는 규칙(무엇을 버리나)과 세는 규칙(같은 줄을 몇 번으로 보나)에 따라 숫자가 바뀌니, 규칙을 먼저 글로 정해 두고 코드로 옮깁니다.

**앞 문제와의 연결**
2-13(머리줄 건너뛰기·`and` 순서) · 2-12(공백 뗀 뒤 isdigit) · 2-8(.get 으로 쌓기) · 2-6(세 값 나눠 받기) · 2-14(쓰고 다시 읽기) · 2-18(`:>3` 칸 맞춤)을 한데 썼습니다.
