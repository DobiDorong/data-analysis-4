# 초급 20문제 해설

문제마다 여섯 칸으로 적었습니다. 「묻는 것 -> 코드 한 줄씩 -> 왜 이렇게 푸나 ->
틀리면 이렇게 된다 -> 실제로 쓸 때는 -> 앞 문제와의 연결」 입니다.
막힌 문제만 골라 봐도 됩니다.

해설에 적힌 에러 문구와 출력은 전부 직접 실행해서 받은 것입니다(파이썬 3.14, 맥).
3.10 이하에서는 `Did you mean:` 같은 안내가 붙지 않는 등 문구가 조금 짧게 나옵니다.
에러 이름과 콜론 뒤의 핵심 문장은 같습니다. 버전마다 크게 다른 곳은 본문에 따로 적었습니다.

메모리 주소가 섞인 문구(`0x1061b4330` 같은 것)는 실행할 때마다 값이 바뀝니다.
그 자리는 숫자가 달라도 맞습니다.

## [1-1] 나누기 세 가지

**묻는 것**
48500원을 3명이 나눌 때 `/` `//` `%` 가 각각 무엇을 돌려주는지 묻습니다.

**코드 한 줄씩**

```python
exact = total / people     # -> 16166.666666666666
each = total // people     # -> 16166
left = total % people      # -> 2
print("그냥 나누기:", exact)
print("한 사람당:", each)
print("남는 금액:", left)
```

`/` 는 소수점 아래까지 다 남깁니다. 나누어떨어져도 소수로 나옵니다(`48600 / 3` 은 `16200.0`).

`//` 는 소수점 아래를 버리고 몫만 남깁니다. 16166.666... 에서 16166 입니다.

`%` 는 나누고 남은 값입니다. 16166 x 3 = 48498 이니 48500 에서 2가 남습니다.

print 에 쉼표로 값을 두 개 넘기면 사이에 공백이 하나 들어갑니다. 그래서 `"그냥 나누기:"` 끝에 공백을 따로 넣지 않았습니다.

**왜 이렇게 푸나**
돈은 원 아래로 쪼갤 수 없습니다. 한 사람이 낼 금액은 `//`, 남는 금액은 `%` 로 구합니다. `/` 는 「딱 나누면 얼마인가」 를 확인하는 값입니다. 세 결과를 변수에 따로 담아 두면 print 줄에서 이름으로 꺼내 쓸 수 있습니다.

**틀리면 이렇게 된다**
`//` 와 `%` 를 바꿔 쓰면 에러 없이 엉뚱한 숫자가 나옵니다.

```python
each = total % people
print("한 사람당:", each)
```
```
한 사람당: 2
```

한 사람이 2원을 낸다고 나와도 파이썬은 아무 말도 하지 않습니다. 숫자가 이상하게 작으면 기호를 바꿔 썼는지 보세요.

print 안에서 쉼표를 빼먹으면 실행하기 전에 막힙니다.

```python
each = total // people
print("한 사람당:" each)
```
```
SyntaxError: invalid syntax. Perhaps you forgot a comma?
```

파이썬 3.9 에서는 뒤의 `Perhaps you forgot a comma?` 없이 `SyntaxError: invalid syntax` 만 나옵니다.

**실제로 쓸 때는**
더치페이처럼 금액을 나눌 때, 글 125개를 한 쪽에 10개씩 보여 줄 때(125 // 10 = 12쪽이 꽉 차고, 125 % 10 = 5개가 남는다) `//` 와 `%` 가 짝으로 나옵니다.

**앞 문제와의 연결**
첫 문제입니다. 여기서 쓴 「계산 결과를 변수에 담고 print 로 찍기」 가 뒤 문제 전부의 바탕입니다.

## [1-2] 자리 맞춘 영수증

**묻는 것**
f-string 안에서 숫자에 쉼표를 넣고(`,`), 정해진 칸 수에 오른쪽으로 붙이는(`>N`) 법을 묻습니다.

**코드 한 줄씩**

```python
total = mug_price * mug_count + note_price * note_count + pen_price * pen_count
print(f"머그 {mug_price:>6,} x {mug_count}개 {mug_price * mug_count:>8,}원")
print(f"노트 {note_price:>6,} x {note_count}개 {note_price * note_count:>8,}원")
print(f"볼펜 {pen_price:>6,} x {pen_count}개 {pen_price * pen_count:>8,}원")
print(f"합계 {total:>21,}원")
```

첫 줄은 곱하기를 더하기보다 먼저 계산합니다. 괄호 없이 써도 품목별 금액을 먼저 구해 더합니다.

따옴표 앞에 `f` 를 붙이면 `{ }` 안에 변수나 식을 넣을 수 있습니다. `{mug_price * mug_count:>8,}` 처럼 식을 바로 넣어도 됩니다.

`{mug_price:>6,}` 에서 콜론 뒤가 서식입니다. `>6` 은 「6칸을 잡고 오른쪽에 붙여라」, `,` 는 「세 자리마다 쉼표」 입니다. 순서는 맞춤(`>`) -> 폭(`6`) -> 쉼표(`,`) 로 정해져 있습니다. 폭은 쉼표까지 넣은 길이로 셉니다. `8,900` 은 5글자라 앞에 공백 하나가 붙어 6칸이 됩니다.

**왜 이렇게 푸나**
칸 폭을 고정하면 숫자 길이가 달라도 끝자리가 세로로 맞습니다. 합계 칸이 21인 것은 품목 줄과 끝을 맞추기 위해서입니다. 「머그 」 뒤로 단가 6 + ` x ` 3 + 수량 1 + 「개」 + 공백 1 + 금액 8 이 이어지는데, 한글 「개」는 터미널에서 두 칸 너비로 찍힙니다. 그래서 화면으로는 6+3+1+2+1+8 = 21칸입니다.

숫자는 원래 오른쪽에 붙어서 `>` 를 빼고 `{mug_price:6,}` 로 써도 같은 화면이 나옵니다. 글자는 왼쪽에 붙으니(`f"{'볼펜':6}"` 은 `볼펜    `), 오른쪽 맞춤은 `>` 를 적는 버릇을 들이세요.

**틀리면 이렇게 된다**
따옴표 앞의 `f` 를 빼면 중괄호가 글자 그대로 찍힙니다.

```python
print("머그 {mug_price:>6,} x {mug_count}개 {mug_price * mug_count:>8,}원")
```
```
머그 {mug_price:>6,} x {mug_count}개 {mug_price * mug_count:>8,}원
```

쉼표를 `>` 앞에 쓰면 쉼표가 빈칸을 채우는 글자가 되고, 숫자 쉼표는 사라집니다.

```python
print(f"머그 {mug_price:,>6} x {mug_count}개 {mug_price * mug_count:>8,}원")
```
```
머그 ,,8900 x 2개   17,800원
```

`>` 없이 쉼표를 폭 앞에 쓰면 에러가 납니다.

```python
print(f"머그 {mug_price:,6} x {mug_count}개")
```
```
ValueError: Cannot specify ',' with '6'.
```

**실제로 쓸 때는**
영수증, 가계부, 정산표처럼 숫자를 세로로 비교하는 화면은 이렇게 칸을 맞춥니다. 금액 칸 폭은 가장 큰 금액이 쉼표까지 다 들어갈 만큼 잡습니다.

**앞 문제와의 연결**
1-1 은 print 에 쉼표로 값을 이어 찍었습니다. 이번에는 f-string 한 줄 안에 글자와 값을 섞고, 값의 모양(쉼표·칸)까지 정했습니다.

## [1-3] 폼에서 온 값 세 개

**묻는 것**
문자열로 온 숫자를 `int()` `float()` 로 바꾸고, 계산 결과를 `str()` 로 다시 글자로 바꾸는 법을 묻습니다. 「3.5」 처럼 점이 든 글자는 `int()` 로 바로 안 바뀐다는 것도 직접 봅니다.

**코드 한 줄씩**

```python
# int(box_text)   <- 돌려 보면 ValueError 가 나서 # 로 막아 두었습니다
price = int(price_text)          # -> 4500
boxes = int(float(box_text))     # -> "3.5" -> 3.5 -> 3
rate = float(rate_text)          # -> 0.07
sales = price * boxes            # -> 13500
fee = int(sales * rate)          # -> 945
print(f"상자: {box_text} -> {boxes}개")
print(f"판매 금액: {sales:,}원 / 수수료: {fee}원")
print("받을 금액: " + str(sales - fee) + "원")
```

`int()` 는 정수 모양의 글자만 받습니다. `"3.5"` 는 점이 있어서 `float()` 로 소수 3.5 를 먼저 만들고, 그것을 `int()` 로 바꿉니다. `int()` 는 소수점 아래를 반올림하지 않고 버립니다(`int(3.9)` 도 3). 반 상자는 안 세는 이 문제에 맞습니다.

`+` 는 글자끼리만 이어 붙입니다. 그래서 `sales - fee` 를 `str()` 로 감싸 글자로 바꿨습니다.

**왜 이렇게 푸나**
폼·파일·키보드에서 온 값은 숫자처럼 보여도 글자입니다. 계산하기 전에 한 번 바꿔 두고, 그 뒤로는 바꾼 변수만 씁니다.

수수료에 `int()` 를 씌운 것은 원 아래를 버리기 위해서입니다. 13500 x 0.07 은 945 가 아니라 945.0000000000001 로 계산됩니다. 컴퓨터는 0.07 같은 소수를 정확히 담지 못해 끝에 아주 작은 오차가 붙습니다.

**틀리면 이렇게 된다**
할 일 1번에서 본 에러입니다. 「10진법 정수로 읽을 수 없는 글자 '3.5'」 라는 뜻입니다.

```python
int(box_text)
```
```
ValueError: invalid literal for int() with base 10: '3.5'
```

수수료에 `int()` 를 안 씌우면 끝자리 오차가 그대로 찍힙니다.

```python
sales = 13500
fee = sales * float(rate_text)
print(f"수수료: {fee}원")
```
```
수수료: 945.0000000000001원
```

마지막 줄에서 `str()` 을 빼면 글자와 숫자를 이을 수 없다는 에러가 납니다.

```python
sales = 13500
fee = 945
print("받을 금액: " + (sales - fee) + "원")
```
```
TypeError: can only concatenate str (not "int") to str
```

**실제로 쓸 때는**
웹 폼, 문자로 받은 주문, 파일에서 읽은 줄은 전부 글자로 들어옵니다. 받자마자 숫자로 바꾸는 줄을 한곳에 모아 두면, 어디서 바꿨는지 찾기 쉽습니다.

**앞 문제와의 연결**
1-2 의 f-string 과 `:,` 를 그대로 썼습니다. 1-2 는 처음부터 숫자였고, 이번에는 숫자로 바꾸는 단계가 앞에 붙었습니다.

## [1-4] 입력은 전부 문자열

**묻는 것**
`input()` 이 돌려주는 값이 무엇인지 묻습니다. 1 과 2 를 쳐도 숫자가 아니라 글자 `"1"` `"2"` 가 들어옵니다.

**코드 한 줄씩**

```python
first = input("1번 수량: ")     # -> "1"
second = input("2번 수량: ")    # -> "2"
print(f"그냥 더하면: {first + second}")    # -> "1" + "2" = "12"
total = int(first) + int(second)          # -> 1 + 2 = 3
print(f"숫자로 더하면: {total}")
```

`input("안내문")` 은 안내문을 띄우고 기다립니다. 키보드로 치고 Enter(맥은 return)를 누르면 친 글자를 돌려줍니다. 터미널에는 이렇게 보입니다. 첫 두 줄 끝의 `1` 과 `2` 가 내가 친 값입니다.

```
1번 수량: 1
2번 수량: 2
그냥 더하면: 12
숫자로 더하면: 3
```

글자끼리 `+` 는 이어 붙이기라서 `"12"` 가 나옵니다. `int()` 로 바꾼 뒤에 더해야 3 입니다.

**왜 이렇게 푸나**
input 은 손님이 무엇을 칠지 모르니 늘 글자로 받습니다. 그래서 숫자가 필요한 자리에서 직접 바꿉니다. 1-3 의 폼 값과 같은 처지입니다. 「그냥 더하면」 줄은 그 차이를 눈으로 보려고 넣었습니다.

**틀리면 이렇게 된다**
둘 중 하나만 바꾸면 숫자와 글자를 더하게 됩니다.

```python
first = input("1번 수량: ")
second = input("2번 수량: ")
total = int(first) + second
```
```
TypeError: unsupported operand type(s) for +: 'int' and 'str'
```

안내문 끝의 공백을 빼면 친 값이 콜론에 바로 붙습니다. 에러는 아니지만 읽기 불편합니다.

```python
first = input("1번 수량:")
second = input("2번 수량:")
```
```
1번 수량:1
2번 수량:2
```

수량 칸에 `1개` 처럼 숫자 아닌 글자를 섞어 치면 「그냥 더하면: 1개2」 까지 찍히고, `int()` 줄에서 이렇게 멈춥니다.

```
ValueError: invalid literal for int() with base 10: '1개'
```

**실제로 쓸 때는**
키오스크 수량, 메뉴 번호처럼 키보드로 숫자를 받는 곳은 받은 다음 `int()` 로 바꿉니다. 글자가 섞여 들어올 수 있어서, 실제 프로그램은 바꾸기 전에 무엇이 들어왔는지부터 확인합니다. 1-14 에서 「끝」 을 먼저 검사하는 것이 그 모양입니다.

**앞 문제와의 연결**
1-3 은 문자열이 처음부터 변수에 들어 있었습니다. 이번에는 키보드로 쳐서 같은 처지의 문자열을 만들었습니다. 바꾸는 법(`int()`)은 같습니다.

## [1-5] 가운데만 가리기

**묻는 것**
`문자열[시작:끝]` 으로 원하는 부분만 잘라 내는 법을 묻습니다. 끝 번호 글자는 결과에 들어가지 않는다는 것이 핵심입니다.

**코드 한 줄씩**

```python
front = phone[:4]     # -> "010-"
back = phone[8:]      # -> "-5678"
print(f"전화: {front}****{back}")
print(f"메일: {email[:2]}****{email[6:]}")
```

문자열의 글자는 0번부터 번호가 붙습니다. `010-1234-5678` 에서 하이픈은 3번과 8번입니다.

`[:4]` 는 시작을 비웠으니 0번부터 4번 앞까지, 곧 0·1·2·3번 `010-` 입니다. `[8:]` 은 끝을 비웠으니 8번부터 끝까지 `-5678` 입니다. 빠진 4·5·6·7번 자리에 `****` 를 넣었습니다.

메일은 `m` `i` 가 0·1번이라 `[:2]` 가 `mi`, `@` 가 6번이라 `[6:]` 이 `@example.com` 입니다.

**왜 이렇게 푸나**
가리기는 「남길 앞부분 + 별표 + 남길 뒷부분」 을 새로 이어 붙이는 일입니다. 문자열은 칸 하나만 바꿀 수 없어서, 남길 부분을 잘라 와 새 문자열을 만듭니다. 끝 번호가 빠지는 덕분에 `[:4]` 는 「앞에서 4글자」 로 숫자 그대로 읽힙니다.

**틀리면 이렇게 된다**
하이픈을 세지 않으면 한 칸 모자랍니다.

```python
print(f"전화: {phone[:3]}****{phone[8:]}")
```
```
전화: 010****-5678
```

메일에서 `@` 번호를 하나 더 세면 `@` 가 사라집니다.

```python
print(f"메일: {email[:2]}****{email[7:]}")
```
```
메일: mi****example.com
```

칸 하나를 바로 바꾸려 하면 에러가 납니다. 문자열은 만든 뒤에 고칠 수 없습니다.

```python
phone[4] = "*"
```
```
TypeError: 'str' object does not support item assignment
```

**실제로 쓸 때는**
주문 확인 화면, 회원 목록, 영수증의 카드 번호를 이렇게 가립니다. 메일은 사람마다 아이디 길이가 달라서 `6` 을 박아 두면 다른 메일에서 틀립니다. 실제 코드는 `@` 의 자리를 먼저 찾고(`email.index("@")` 는 6) 그 번호로 자릅니다.

**앞 문제와의 연결**
1-3·1-4 는 문자열을 숫자로 바꿨습니다. 이번에는 문자열 안을 번호로 잘라 냈습니다. 「0번부터 센다」 는 1-7 리스트에서 그대로 다시 나옵니다.

## [1-6] 같은 메일인데 다르다

**묻는 것**
`==` 는 글자를 한 자씩 똑같은지 비교한다는 것, 그리고 `.strip()` `.lower()` `.replace()` 로 값을 다듬은 뒤 비교하는 법을 묻습니다.

**코드 한 줄씩**

```python
print(f"그대로: {typed_email == saved_email}")      # -> False
step1 = typed_email.strip().lower()                # -> "minjun @example.com"
print(f"양 끝 정리: {step1} / {step1 == saved_email}")
step2 = step1.replace(" ", "")                     # -> "minjun@example.com"
print(f"가운데까지: {step2} / {step2 == saved_email}")
```

`==` 는 두 값이 같으면 `True`, 다르면 `False` 를 돌려줍니다. 대문자와 소문자도, 공백 하나도 다른 글자로 봅니다.

값 뒤에 점을 찍고 붙이는 `.strip()` 같은 것을 메서드라고 부릅니다. `.strip()` 은 양 끝 공백만 떼고 가운데 공백은 둡니다. `.lower()` 는 전부 소문자로 바꿉니다. `typed_email.strip().lower()` 처럼 이어 쓰면 왼쪽부터 차례로 적용됩니다.

`.replace(" ", "")` 는 공백을 빈 문자열로 바꿉니다. 공백을 지우는 것과 같습니다.

**왜 이렇게 푸나**
사람이 친 값에는 실수로 넣은 공백과 대문자가 섞입니다. 같은 모양으로 다듬은 뒤에 비교해야 같은 주소를 같다고 판단합니다. 메서드는 원래 문자열을 바꾸지 않고 다듬은 새 문자열을 돌려줍니다. 그래서 결과를 `step1` `step2` 에 담았습니다.

**틀리면 이렇게 된다**
결과를 변수에 담지 않으면 원래 값이 그대로 남습니다(공백이 보이게 `[ ]` 로 감쌌습니다).

```python
typed_email.strip()
print(f"[{typed_email}]")
```
```
[  MinJun @Example.COM ]
```

`.lower` 뒤 괄호를 빼면 소문자로 바꾼 결과가 아니라 그 메서드 자체가 담깁니다. 찍어 보면 이렇게 나오고, `0x` 뒤 숫자는 실행할 때마다 다릅니다.

```python
step1 = typed_email.strip().lower
print(step1)
```
```
<built-in method lower of str object at 0x106194970>
```

그 상태로 `.replace()` 를 이으면 에러가 납니다.

```python
step1 = typed_email.strip().lower
step2 = step1.replace(" ", "")
```
```
AttributeError: 'builtin_function_or_method' object has no attribute 'replace'
```

`.replace()` 의 두 값을 거꾸로 쓰면 빈 문자열을 공백으로 바꾸게 되어, 글자 사이마다 공백이 들어갑니다.

```python
step1 = typed_email.strip().lower()
print(step1.replace("", " "))
```
```
 m i n j u n   @ e x a m p l e . c o m 
```

**실제로 쓸 때는**
로그인·회원가입에서 메일이나 아이디를 저장하기 전, 비교하기 전에 이렇게 다듬습니다. 저장할 때와 비교할 때 같은 순서로 다듬어야 합니다.

**앞 문제와의 연결**
1-5 는 번호로 문자열을 잘랐습니다. 이번에는 메서드로 다듬었습니다. 둘 다 원래 문자열은 그대로 두고 새 문자열을 만듭니다.

## [1-7] 할 일 목록 고치기

**묻는 것**
리스트에서 값을 꺼내고(`[번호]`), 바꾸고, 맨 뒤에 넣고(`.append()`), 정렬해 보여 주는(`sorted()`) 법을 묻습니다. 「몇 번째」 와 「몇 번 칸」 이 하나씩 어긋난다는 것이 핵심입니다.

**코드 한 줄씩**

```python
print(f"3번째 할 일: {todos[2]}")    # -> 회의록 정리
todos[1] = "메일 회신(완료)"
todos.append("출장 정산")
print(f"고친 목록: {todos}")
print(f"가나다순: {sorted(todos)}")
```

리스트도 1-5 의 문자열처럼 0번부터 셉니다. 3번째 할 일은 2번 칸, 2번째는 1번 칸입니다.

`todos[1] = "메일 회신(완료)"` 는 1번 칸의 값을 바꿉니다. 문자열은 칸을 못 바꿨지만 리스트는 됩니다. `.append()` 는 맨 뒤에 칸을 하나 늘려 값을 넣습니다.

`sorted(todos)` 는 가나다순으로 늘어놓은 새 리스트를 돌려줍니다. `todos` 의 순서는 그대로라서, 「고친 목록」 줄은 고친 순서대로 나옵니다.

**왜 이렇게 푸나**
목록을 고치는 일과 보여 주는 일을 나눴습니다. 할 일은 적은 순서에도 뜻이 있으니 원본은 그대로 두고, 정렬은 보여 줄 때만 합니다.

**틀리면 이렇게 된다**
「3번째」 를 그대로 `[3]` 으로 쓰면 한 칸 뒤 값이 나옵니다. 에러가 없어서 알아채기 어렵습니다.

```python
print(f"3번째 할 일: {todos[3]}")
```
```
3번째 할 일: 비품 신청
```

대괄호 대신 소괄호를 쓰면 에러가 납니다. 소괄호는 `print()` 처럼 「불러서 실행하라」 는 표시이고, `callable` 은 「부를 수 있는」 이라는 뜻입니다.

```python
print(todos(2))
```
```
TypeError: 'list' object is not callable
```

맨 뒤에 넣으려고 없는 칸 번호에 값을 넣어도 에러가 납니다. 번호로는 있는 칸만 바꿀 수 있고, 칸을 늘릴 때는 `.append()` 를 씁니다.

```python
todos = ["보고서 초안", "메일 회신", "회의록 정리", "비품 신청"]
todos[4] = "출장 정산"
```
```
IndexError: list assignment index out of range
```

`sorted()` 대신 `.sort()` 를 쓰면 두 가지가 틀립니다. `.sort()` 는 원본의 순서를 바꿔 버리고, 돌려주는 값이 없어서 찍으면 `None`(값 없음)이 나옵니다.

```python
print(f"가나다순: {todos.sort()}")
print(f"고친 목록: {todos}")
```
```
가나다순: None
고친 목록: ['메일 회신', '보고서 초안', '비품 신청', '회의록 정리']
```

**실제로 쓸 때는**
장바구니, 대기 명단, 할 일 앱의 목록이 리스트입니다. 들어온 순서를 지켜야 하는 목록은 `sorted()` 로 보여 주기만 하고, 원본 순서를 바꿔도 될 때만 `.sort()` 를 씁니다.

**앞 문제와의 연결**
1-5 에서 문자열을 0번부터 셌던 것이 리스트에도 그대로입니다. 다른 점은 리스트는 칸 값을 바꾸고 칸을 늘릴 수 있다는 것입니다.

## [1-8] 영수증 한 줄 쪼개기

**묻는 것**
`.split(",")` 로 문자열을 리스트로 쪼갠 뒤, 조각마다 공백을 떼고 숫자로 바꿔 계산하는 법을 묻습니다.

**코드 한 줄씩**

```python
parts = line.split(",")       # -> ['  우유 ', '2', '2800']
name = parts[0].strip()       # -> "우유"
count = int(parts[1])         # -> 2
price = int(parts[2])         # -> 2800
print(f"{name} {count}개 x {price:,}원 = {count * price:,}원")
```

`.split(",")` 는 쉼표 자리마다 잘라 조각들을 리스트로 돌려줍니다. 쉼표 자체는 사라집니다.

조각은 전부 문자열입니다. 품목은 1-6 의 `.strip()` 으로 양 끝 공백을 떼고, 수량·단가는 1-3 의 `int()` 로 바꿨습니다. 조각을 꺼내는 번호는 1-7 처럼 0번부터입니다.

**왜 이렇게 푸나**
쉼표로 붙어 온 기록은 「쪼개기 -> 조각마다 다듬기 -> 계산」 순서로 풉니다. 조각마다 이름을 붙여 두면 마지막 print 줄이 짧아지고, `parts[2]` 가 무엇이었는지 기억하지 않아도 됩니다.

**틀리면 이렇게 된다**
`.split()` 에 쉼표를 안 넣으면 공백 기준으로 잘립니다.

```python
print(line.split())
```
```
['우유', ',2,2800']
```

수량·단가를 둘 다 안 바꾸고 곱하면 에러가 납니다. 글자끼리는 곱할 수 없습니다.

```python
parts = line.split(",")
print(parts[1] * parts[2])
```
```
TypeError: can't multiply sequence by non-int of type 'str'
```

수량 하나만 안 바꾸면 더 헷갈립니다. 글자 x 정수는 「그 글자를 정수만큼 이어 붙이기」 라서, `"2" * 2800` 은 2가 2800개 이어진 글자입니다. 그 글자에 쉼표 서식을 걸다가 에러가 납니다. `'s'` 는 문자열 서식이라는 뜻입니다.

```python
parts = line.split(",")
count = parts[1]
price = int(parts[2])
print(f"{count * price:,}원")
```
```
ValueError: Cannot specify ',' with 's'.
```

`.strip()` 을 빼면 품목 앞뒤 공백이 그대로 찍힙니다.

```python
parts = line.split(",")
name = parts[0]
print(f"{name} {parts[1]}개")
```
```
  우유  2개
```

**실제로 쓸 때는**
계산대 기록, 메모장에 적은 장보기 목록, 쉼표로 칸을 나눈 파일(CSV)의 한 줄이 이 모양입니다. 1-20 에서 파일의 여러 줄을 같은 방법으로 쪼갭니다.

**앞 문제와의 연결**
1-3 의 `int()`, 1-6 의 `.strip()`, 1-7 의 `[번호]` 를 한 줄씩 이었습니다. 새로 나온 것은 `.split(",")` 하나입니다.

## [1-9] 무료배송 기준을 딱 맞췄을 때

**묻는 것**
`if` `else` 로 두 값 중 하나를 고르는 법, 「이상」을 `>=` 로 쓰는 법, 조건 둘 중 하나만 맞아도 되게 `or` 로 잇는 법을 묻습니다.

**코드 한 줄씩**

```python
if total >= 30000 or member:
    fee = 0
else:
    fee = 3000
print(f"합계 {total:,}원 / 배송비 {fee:,}원")
print(f"결제 금액 {total + fee:,}원")
```

`total >= 30000` 은 30000 과 같거나 크면 `True` 입니다. 「이상」은 기준값을 넣으니 `>=`, 「초과」는 빼니 `>` 입니다.

`A or B` 는 둘 중 하나라도 `True` 면 `True` 입니다. `member` 는 그 자체가 `True`/`False` 값이라 이름만 적으면 됩니다.

`if` 줄 끝의 콜론(`:`)과 그 아래 안쪽으로 들여 쓴 줄(공백 4칸)이 「조건이 맞을 때 할 일」 입니다. `else:` 아래는 조건이 `False` 일 때 실행됩니다.

**왜 이렇게 푸나**
if 안에서는 배송비만 정하고 print 는 밖에서 한 번 했습니다. 「무엇을 고를지」 와 「어떻게 보여 줄지」 를 나누면 출력 줄을 두 번 쓰지 않아도 됩니다. 장바구니가 딱 30000원이라 이 칸은 `>` 와 `>=` 를 가려냅니다.

**틀리면 이렇게 된다**
「이상」을 `>` 로 쓰면 딱 30000원인 이 장바구니에 배송비가 붙습니다.

```python
if total > 30000 or member:
    fee = 0
else:
    fee = 3000
print(f"합계 {total:,}원 / 배송비 {fee:,}원")
print(f"결제 금액 {total + fee:,}원")
```
```
합계 30,000원 / 배송비 3,000원
결제 금액 33,000원
```

`or member` 는 반대로, 빼먹어도 이 칸으로는 알 수 없습니다. `member` 가 `False` 라서 `or member` 를 지워도 똑같은 2줄이 나옵니다. 칸과 같다고 끝내지 말고 값을 바꿔 보세요. 25000원짜리 회원 장바구니로 바꾸면, `or member` 를 뺀 코드는 회원에게 배송비를 받습니다(정답 코드는 같은 값에서 `배송비 0원`).

```python
total = 25000
member = True
if total >= 30000:
    fee = 0
else:
    fee = 3000
print(f"배송비 {fee:,}원")
```
```
배송비 3,000원
```

`or` 를 `and` 로 써도 틀립니다. 「30000원 이상이면서 회원」 일 때만 무료가 되어, 이 문제의 장바구니에도 3000원이 붙습니다.

`if` 줄 끝 콜론을 빼면 실행하기 전에 막힙니다.

```python
if total >= 30000 or member
    fee = 0
```
```
SyntaxError: expected ':'
```

파이썬 3.9 에서는 `SyntaxError: invalid syntax` 로 나옵니다.

**실제로 쓸 때는**
무료배송, 쿠폰 최소 금액, 회원 할인처럼 「기준 이상이면」 이 붙는 규칙은 경계값을 넣느냐 빼느냐가 바로 돈입니다. 시험할 때는 기준값(30000)과 바로 아래(29999), 그리고 조건마다 하나씩 맞는 경우를 넣어 봅니다.

**앞 문제와의 연결**
1-1~1-8 은 모든 줄이 위에서 아래로 실행됐습니다. 이번에 처음으로 조건에 따라 실행할 줄과 건너뛸 줄이 갈렸습니다. 출력은 1-2 의 `:,` 그대로입니다.

## [1-10] 택배 무게별 요금

**묻는 것**
구간이 셋 이상일 때 `elif` 로 잇는 법, 그리고 조건을 적는 순서가 결과를 바꾼다는 것을 묻습니다.

**코드 한 줄씩**

```python
if weight <= 5:
    print(f"{weight}kg: 3,000원")
elif weight <= 10:
    print(f"{weight}kg: 4,500원")
elif weight <= 20:
    print(f"{weight}kg: 6,000원")
else:
    print(f"{weight}kg: 접수 불가")
```

파이썬은 위에서부터 조건을 하나씩 봅니다. 처음으로 `True` 인 칸 하나만 실행하고 나머지는 건너뜁니다.

weight 가 10 이면 `10 <= 5` 는 `False`, `10 <= 10` 은 `True` 라서 4,500원 줄만 찍힙니다. `<= 20` 도 맞지만 앞 칸이 이미 실행됐으므로 보지 않습니다. `else` 는 위 조건이 전부 `False` 일 때, 곧 20kg 을 넘을 때입니다.

**왜 이렇게 푸나**
요금표가 「~이하」 라서 `<=` 를 쓰고, 작은 구간부터 차례로 적었습니다. 그러면 `elif weight <= 10` 에 「5kg 보다 무겁고」 를 따로 쓰지 않아도 됩니다. 5kg 이하는 이미 첫 칸에서 걸렸기 때문입니다. 무게 10 은 구간 경계값이라 이 칸은 `<` 와 `<=` 를 가려냅니다.

**틀리면 이렇게 된다**
★ 처럼 20kg 조건부터 쓰면 10kg 이 첫 칸에서 걸립니다. 20kg 이하 짐은 전부 6,000원이 되고, 아래 두 elif 는 한 번도 실행되지 않습니다.

```python
if weight <= 20:
    print(f"{weight}kg: 6,000원")
elif weight <= 10:
    print(f"{weight}kg: 4,500원")
elif weight <= 5:
    print(f"{weight}kg: 3,000원")
else:
    print(f"{weight}kg: 접수 불가")
```
```
10kg: 6,000원
```

「이하」를 `<` 로 쓰면(`weight < 5` · `weight < 10` · `weight < 20`) 경계값 10 이 다음 구간으로 넘어가 같은 `10kg: 6,000원` 이 나옵니다.

`elif` 대신 `if` 를 셋 쓰면 칸마다 따로 검사해서 두 줄이 찍힙니다.

```python
if weight <= 5:
    print(f"{weight}kg: 3,000원")
if weight <= 10:
    print(f"{weight}kg: 4,500원")
if weight <= 20:
    print(f"{weight}kg: 6,000원")
else:
    print(f"{weight}kg: 접수 불가")
```
```
10kg: 4,500원
10kg: 6,000원
```

`else` 뒤에 조건을 붙이면 에러가 납니다. `else` 는 조건 없이 콜론만 씁니다.

```python
if weight <= 5:
    print(f"{weight}kg: 3,000원")
else weight > 20:
    print(f"{weight}kg: 접수 불가")
```
```
SyntaxError: expected ':'
```

파이썬 3.9 에서는 `SyntaxError: invalid syntax` 로 나옵니다.

**실제로 쓸 때는**
택배 요금, 학점, 회원 등급처럼 구간이 여럿인 표를 if·elif·else 로 옮깁니다. 실제 코드는 1-9 처럼 요금을 변수에 담고 print 는 한 번만 쓰는 편이 고치기 쉽습니다. 출력 문구가 바뀌어도 한 곳만 고치면 됩니다.

**앞 문제와의 연결**
1-9 는 둘 중 하나(if·else)를 골랐습니다. 이번에는 그 사이에 `elif` 를 넣어 넷 중 하나를 골랐습니다. 1-9 의 「경계값을 넣느냐 빼느냐」 가 여기서도 결과를 가릅니다.

## [1-11] 일주일 점심값 합계

**묻는 것**
리스트의 값을 for 로 하나씩 꺼내 합계와 횟수를 직접 쌓고, 평균을 `:.1f` 로 소수 첫째 자리까지 보여 주는 것입니다.

**코드 한 줄씩**

```python
total = 0
count = 0
for price in lunches:
    total = total + price
    count = count + 1
print(f"점심 {count}번 / 합계 {total:,}원")   # -> 점심 7번 / 합계 62,500원
print(f"하루 평균 {total / count:.1f}원")     # -> 하루 평균 8928.6원
```

`total` 과 `count` 를 반복이 시작되기 **전에** 0 으로 놓습니다.
`for price in lunches:` 는 리스트에서 값을 앞에서부터 하나씩 꺼내 `price` 에 담고, 그때마다 아래에 들여 쓴 두 줄을 실행합니다. 값이 7개라 7번 돕니다.
첫 바퀴에 `total` 은 0 + 8500 = 8500, 둘째 바퀴에 8500 + 9000 = 17500 이 됩니다. 앞의 합계에 새 값을 얹어 다시 담는 이 모양이 「쌓아 더하기」입니다.
줄 앞의 공백 4칸(들여쓰기)이 for 의 범위입니다. 들여 쓴 줄만 되풀이됩니다.
`total / count` 는 62500 / 7 = 8928.57142857143 이고, `:.1f` 가 소수 첫째 자리까지 반올림해서 보여 줍니다.

**왜 이렇게 푸나**
for 는 값을 꺼내 줄 뿐 더해 주지는 않습니다(힌트). 더한 값을 들고 있을 변수가 for 밖에 있어야 바퀴가 바뀌어도 값이 남습니다.
그래서 0 으로 놓는 줄은 for 위, 더하는 줄은 for 안, 평균을 내는 줄은 다 더한 뒤인 for 밖입니다.

**틀리면 이렇게 된다**
★ 의 답입니다. 합계를 0 으로 놓는 줄을 for 안에 넣으면 바퀴마다 0 으로 돌아가서 마지막 값만 남습니다.

```python
count = 0
for price in lunches:
    total = 0
    total = total + price
    count = count + 1
print(f"점심 {count}번 / 합계 {total:,}원")
```
```
점심 7번 / 합계 11,000원
```

에러가 안 나고 횟수는 맞아서 얼핏 보면 맞아 보입니다.

`count = 0` 을 빠뜨리면 처음 세는 순간 `count` 가 아직 없어서 멈춥니다.

```python
lunches = [8500, 9000, 7500, 12000, 8000, 6500, 11000]
total = 0
for price in lunches:
    total = total + price
    count = count + 1
```
```
NameError: name 'count' is not defined. Did you mean: 'round'?
```

뒤의 `Did you mean: 'round'?` 는 3.14 가 비슷한 이름을 짐작해 붙인 것이고 여기와는 상관없습니다. 3.9 에서는 `NameError: name 'count' is not defined` 까지만 나옵니다.

`:.1f` 에서 점을 빠뜨려 `:1f` 로 쓰면 `하루 평균 8928.571429원` 처럼 소수 여섯째 자리까지 나옵니다. 점 앞의 숫자는 「전체 폭」, 점 뒤의 숫자가 「소수 자리 수」입니다.
서식을 아예 빼면 `하루 평균 8928.57142857143원` 입니다.

**실제로 쓸 때는**
가계부의 한 달 합계, 장부의 건수처럼 「다 더하고 몇 건인지 세기」는 늘 나옵니다.
합계와 개수만이라면 `sum(lunches)` 와 `len(lunches)` 로도 62500 과 7 이 나옵니다. 그래도 「꺼내서 검사하고 골라 담기」처럼 sum 하나로 안 되는 일이 바로 다음 문제부터 나오니, for 로 쌓는 모양을 손에 익혀 둡니다.

**앞 문제와의 연결**
1-7 에서 만든 리스트를 처음으로 되풀이해 돕니다. `:,` 는 1-2, 나누기 `/` 는 1-1 에서 썼습니다. 다음 1-12 는 이 for 안에 if 를 한 겹 넣습니다.

## [1-12] 지저분한 명단 청소

**묻는 것**
for 로 이름을 하나씩 꺼내 앞뒤 공백을 떼고, 빈 이름이 아닌 것만 새 리스트에 모으는 것입니다.

**코드 한 줄씩**

```python
names = []
for name in raw_names:
    name = name.strip()
    if name != "":
        names.append(name)
print(f"정리 전: {raw_names}")   # -> 정리 전: ['김민수', '', '  이서연 ', '   ', '박지훈 ']
print(f"정리 후: {names}")       # -> 정리 후: ['김민수', '이서연', '박지훈']
```

`names = []` 는 깨끗한 이름을 모을 빈 리스트입니다. 1-11 의 `total = 0` 과 같은 자리(for 위)입니다.
`name = name.strip()` 은 앞뒤 공백을 뗀 결과를 다시 `name` 에 담습니다. `.strip()` 은 원래 문자열을 고치지 않고 새 문자열을 돌려주기 때문에(1-6) 다시 담아야 바뀝니다. 공백만 있던 `"   "` 는 떼고 나면 `""`(빈 문자열)입니다.
`!=` 는 「다른가」입니다. 빈 문자열과 다르면 `.append()` 로 새 리스트 끝에 붙입니다(1-7). if 가 for 안에 있어서 들여쓰기가 두 단계입니다.
`name` 에 새 값을 담아도 `raw_names` 는 그대로입니다. 「정리 전」 줄이 그 증거입니다.

**왜 이렇게 푸나**
공백만 있는 이름도 빈 이름입니다(힌트). 그래서 **떼고 나서** 검사합니다. 순서가 반대면 `"   "` 가 검사를 통과합니다.
원본은 그대로 두고 새 리스트에 모으면 정리 전과 후를 나란히 볼 수 있습니다.

**틀리면 이렇게 된다**
검사를 먼저 하고 strip 을 나중에 하면, 공백만 있던 칸이 빈 문자열로 살아남습니다.

```python
names = []
for name in raw_names:
    if name != "":
        names.append(name.strip())
print(f"정리 후: {names}")
```
```
정리 후: ['김민수', '이서연', '', '박지훈']
```

`"   "` 는 빈 문자열이 아니라서 통과한 뒤에 `''` 로 바뀌었습니다.

`name = ` 없이 `name.strip()` 만 쓰면 아무것도 안 떼어져서 `정리 후: ['김민수', '  이서연 ', '   ', '박지훈 ']` 가 나옵니다.
`names = []` 를 for 안에 넣으면 바퀴마다 리스트가 새로 비워져 `정리 후: ['박지훈']` 만 남습니다.

리스트에 바로 `.strip()` 을 붙이면 에러입니다. `.strip()` 은 문자열에만 있습니다.

```python
names = raw_names.strip()
```
```
AttributeError: 'list' object has no attribute 'strip'
```

「리스트에는 strip 이 없다」는 뜻입니다. 하나씩 꺼내서 붙여야 합니다.

**실제로 쓸 때는**
엑셀이나 웹 폼에서 복사해 온 명단·태그 목록에는 공백과 빈칸이 섞여 옵니다. 「떼고 -> 검사하고 -> 새 리스트에 모으기」는 그런 값을 쓰기 전에 거의 매번 거치는 첫 단계입니다.

**앞 문제와의 연결**
1-11 의 for 안에 1-9·1-10 의 if 를 한 겹 넣었습니다. `.strip()` 은 1-6, `.append()` 는 1-7 에서 썼습니다.

## [1-13] 목표 금액까지 저축

**묻는 것**
몇 번 돌지 미리 모를 때 조건이 참인 동안 되풀이하는 while, 그리고 `<` 와 `<=` 의 경계입니다.

**코드 한 줄씩**

```python
day = 0
while saved < goal:
    saved = saved + daily
    day = day + 1
print(f"{day}일 뒤 {saved:,}원")   # -> 5일 뒤 30,000원
```

`day` 는 걸린 날을 셉니다. 1-11 의 `count` 와 같은 역할입니다.
`while saved < goal:` 은 「`saved` 가 목표보다 작은 동안」 아래에 들여 쓴 줄을 되풀이합니다. 한 바퀴가 끝날 때마다 조건을 다시 봅니다.
14000(1일) -> 18000(2일) -> 22000(3일) -> 26000(4일) -> 30000(5일). 30000 은 30000 보다 작지 않으니 거기서 멈추고 print 로 갑니다.

**왜 이렇게 푸나**
for 는 리스트 길이만큼 돕니다. 여기는 리스트가 없고 「몇 번 도는가」가 바로 답이라서, 조건으로 도는 while 을 씁니다.
조건에는 멈출 때가 아니라 **계속 모을 때**를 적습니다(힌트). 「30000원 이상이 되면 멈춘다」는 「30000원보다 작으면 계속한다」, 곧 `saved < goal` 입니다.
조건 안의 값(`saved`)이 반복 안에서 바뀌어야 언젠가 멈춥니다.

**틀리면 이렇게 된다**
★ 의 답입니다. `<=` 를 쓰면 딱 30000원일 때도 한 번 더 모읍니다.

```python
day = 0
while saved <= goal:
    saved = saved + daily
    day = day + 1
print(f"{day}일 뒤 {saved:,}원")
```
```
6일 뒤 34,000원
```

매일 4000원이면 5일째에 딱 30000원이 됩니다. 그 값에서 멈추느냐 한 번 더 가느냐가 `<` 와 `<=` 의 차이입니다.

멈출 조건을 그대로 `while saved >= goal:` 로 적으면 처음부터 거짓이라 한 번도 안 돌고 `0일 뒤 10,000원` 이 나옵니다.

반복 안에서 `saved = saved + daily` 를 빠뜨리면 조건이 영원히 참이라 끝나지 않습니다. 화면에는 아무것도 안 나오지만 뒤에서 계속 돌고 있습니다.
터미널에서 Ctrl+C(맥도 control+C)를 누르면 멈추고, 마지막 줄에 `KeyboardInterrupt` 가 찍힙니다.

**실제로 쓸 때는**
「목표에 닿을 때까지」「재고가 떨어질 때까지」「성공할 때까지 다시 시도」처럼 횟수를 미리 모를 때 while 을 씁니다.
경계(이상·초과)는 요구 문장 그대로 옮기고, 딱 그 값이 되는 경우로 한 번 돌려 봅니다.

**앞 문제와의 연결**
1-11 의 for 는 정해진 개수만큼 돌았고, while 은 조건으로 돕니다. 쌓고 세는 모양은 1-11 과 같고, `>=` 와 `<` 경계는 1-9 에서 나왔습니다.

## [1-14] 「끝」 칠 때까지 더하기

**묻는 것**
`while True:` 로 입력받기를 되풀이하다가 「끝」이 들어오면 `break` 로 빠져나오는 것, 그리고 검사를 숫자로 바꾸기보다 먼저 하는 순서입니다.

**코드 한 줄씩**

```python
total = 0
count = 0
while True:
    text = input("금액: ")
    if text == "끝":
        break
    total = total + int(text)
    count = count + 1
print(f"영수증 {count}장 / 합계 {total:,}원")
```

`while True:` 는 조건이 늘 참이라 스스로는 멈추지 않습니다. 멈추는 곳은 안쪽의 `break` 하나입니다.
`input("금액: ")` 이 반복 안에 있어서 바퀴마다 새로 묻습니다. 입력은 늘 문자열입니다(1-4).
「끝」이면 `break` 가 곧바로 while 을 빠져나가 맨 아래 print 로 갑니다. 그 아래 두 줄은 실행되지 않습니다.
「끝」이 아닐 때만 `int(text)` 로 바꿔 더하고 장 수를 셉니다.

터미널에서는 이렇게 보입니다. 값을 치고 Enter(맥은 return)를 누릅니다.

```
금액: 4500
금액: 12000
금액: 3000
금액: 끝
영수증 3장 / 합계 19,500원
```

**왜 이렇게 푸나**
1-13 처럼 while 줄에 조건을 쓰려면 반복 전에 `text` 가 있어야 해서, 묻는 줄을 반복 위와 반복 끝 두 곳에 써야 합니다.
`while True:` 와 `break` 를 쓰면 묻는 줄이 한 곳이고, 「받는다 -> 검사한다 -> 쓴다」를 한 바퀴 안에 차례로 적습니다.
검사가 `int()` 보다 앞인 이유는 「끝」을 숫자로 바꿀 수 없기 때문입니다.

**틀리면 이렇게 된다**
★ 의 답입니다. 받자마자 숫자로 바꾸면 「끝」을 친 순간 멈춥니다.

```python
while True:
    text = int(input("금액: "))
    if text == "끝":
        break
```
```
ValueError: invalid literal for int() with base 10: '끝'
```

세 금액은 잘 받다가 네 번째 입력에서 멈추고, 영수증 줄은 안 나옵니다.

장 수를 검사보다 먼저 세면(`count = count + 1` 을 `if` 위로 올리면) 「끝」까지 한 장으로 세어 `영수증 4장 / 합계 19,500원` 이 나옵니다. 합계는 맞고 장 수만 틀려서 놓치기 쉽습니다.

입력받는 줄을 반복 밖(위)에 두면 처음 친 4500 하나로 끝없이 돕니다. 다시 묻지 않으니 「끝」을 칠 기회가 오지 않습니다.
Ctrl+C(맥도 control+C)로 멈추면 마지막 줄에 `KeyboardInterrupt` 가 찍힙니다. 힌트 「입력받는 줄도 되풀이 안에 있어야 매번 묻습니다」가 이 경우입니다.

**실제로 쓸 때는**
「q 를 치면 종료」, 메뉴 번호를 고를 때까지 묻기, 맞는 값을 칠 때까지 다시 묻기 같은 콘솔 프로그램이 대개 이 모양입니다. 멈출 말을 먼저 검사하고, 그다음에 값을 씁니다.

**앞 문제와의 연결**
1-13 의 while 안에 1-4 의 input, 1-3 의 int(), 1-9 의 if 를 넣었습니다. 합계와 장 수 세기는 1-11 과 같습니다.

## [1-15] 메뉴 가격표 고치기

**묻는 것**
딕셔너리에서 키로 값을 꺼내고, 같은 대괄호 문법으로 값을 바꾸고 새로 넣는 것입니다.

**코드 한 줄씩**

```python
menu = {"아메리카노": 4500, "라떼": 5000, "녹차": 4800}
print(f"라떼: {menu['라떼']:,}원")   # -> 라떼: 5,000원
menu["라떼"] = 5500
menu["레몬에이드"] = 6000
print(f"고친 가격표: {menu}")
```

`{키: 값, ...}` 이 딕셔너리입니다. 리스트는 0, 1, 2 같은 번호로 찾고(1-7), 딕셔너리는 `"라떼"` 같은 이름표(키)로 찾습니다.
f-string 을 큰따옴표로 열었으니 안쪽 키는 작은따옴표로 감쌉니다(★).
있는 키에 `=` 로 넣으면 값이 바뀌고, 없는 키에 넣으면 새로 생깁니다(힌트). 두 줄은 모양이 같고, 키가 이미 있었느냐만 다릅니다.
마지막 줄은 `고친 가격표: {'아메리카노': 4500, '라떼': 5500, '녹차': 4800, '레몬에이드': 6000}` 입니다. 라떼는 제자리에서 값만 바뀌었고, 레몬에이드는 맨 뒤에 붙었습니다. 딕셔너리는 넣은 순서를 기억합니다.

**왜 이렇게 푸나**
가격표는 「메뉴 이름 -> 가격」 짝입니다. 리스트에 담으면 라떼가 몇 번 칸인지 따로 외워야 합니다.
딕셔너리는 이름으로 바로 찾고, 꺼내기·바꾸기·넣기가 전부 `menu[키]` 하나로 됩니다.

**틀리면 이렇게 된다**
리스트 버릇대로 번호로 꺼내면 「0 이라는 키가 없다」는 에러가 납니다. `KeyError` 뒤에 오는 것이 못 찾은 키입니다.

```python
print(menu[0])
```
```
KeyError: 0
```

리스트처럼 `.append()` 로 넣으려 해도 안 됩니다. 딕셔너리에는 append 가 없습니다.

```python
menu.append("레몬에이드")
```
```
AttributeError: 'dict' object has no attribute 'append'
```

키 글자가 하나만 달라도 에러 없이 새 키가 생깁니다. `menu["라테"] = 5500` 으로 치면 라떼는 5000 그대로이고 `'라테': 5500` 이 하나 더 붙습니다.

★ f-string 안의 키를 큰따옴표로 감싸면 버전에 따라 갈립니다.

```python
print(f"라떼: {menu["라떼"]:,}원")
```

3.12 이상(3.12·3.14·3.15 에서 실측)은 이대로 `라떼: 5,000원` 이 나옵니다. 3.11 이하(3.9·3.10·3.11 에서 실측)는 이렇게 멈춥니다.

```
SyntaxError: f-string: unmatched '['
```

f-string 을 연 큰따옴표가 `menu[` 바로 뒤에서 닫힌 것으로 읽혀 대괄호 짝이 안 맞는다는 뜻입니다.
SyntaxError 는 파일을 실행하기 전에 나서, 그 줄보다 위에 있는 문제의 출력도 하나도 안 나옵니다(3.9 에서 위에 print 한 줄을 두고 실측). 어느 버전에서나 돌게 하려면 작은따옴표를 씁니다.

**실제로 쓸 때는**
가격표, 설정값, 회원 번호와 이름처럼 「이름으로 찾는」 자료는 거의 딕셔너리에 담습니다. 키 오타가 조용히 새 키를 만들기 때문에, 고친 뒤에는 통째로 한 번 찍어 확인하는 편이 안전합니다.

**앞 문제와의 연결**
1-7 에서 `todos[1] = ...` 로 리스트 칸을 바꾼 것과 같은 대괄호 모양입니다. 리스트는 번호, 딕셔너리는 키입니다. 다음 1-16 은 「없는 키에 넣으면 생긴다」를 써서 표를 셉니다.

## [1-16] 희망 요일 투표 세기

**묻는 것**
처음 나온 요일은 1로 넣고 이미 있는 요일은 1을 더해 요일별 표 수를 세는 것, 그리고 키가 있는지 `in` 으로 먼저 묻는 것입니다.

**코드 한 줄씩**

```python
counts = {}
for day in votes:
    if day in counts:
        counts[day] = counts[day] + 1
    else:
        counts[day] = 1
for day in counts:
    print(f"{day}: {counts[day]}표")
```

`day in counts` 는 「`day` 라는 키가 `counts` 에 들어 있나」를 묻습니다.
있으면 지금 표 수에 1을 더하고, 없으면(처음 나온 요일) 1로 새로 넣습니다.
첫 표 「화」는 없어서 `{'화': 1}`, 둘째 「목」도 없어서 `{'화': 1, '목': 1}`, 셋째 「화」는 있어서 `{'화': 2, '목': 1}` 이 됩니다. 8표를 다 돌면 `{'화': 3, '목': 3, '금': 1, '월': 1}` 입니다.
for 로 딕셔너리를 돌면 키가 하나씩 나오고, 값은 `counts[day]` 로 꺼냅니다. 키는 처음 넣은 순서대로 나오니 「처음 나온 요일부터」가 저절로 맞습니다.

```
화: 3표
목: 3표
금: 1표
월: 1표
```

**왜 이렇게 푸나**
`counts[day] + 1` 은 키가 이미 있어야 계산됩니다. 처음 나온 요일은 아직 없으니(힌트) 그때만 따로 1을 넣고, 그 갈림을 `in` 으로 묻습니다.
요일을 미리 다 적은 표를 만들지 않아도 되니, 투표에 무엇이 나오든 그대로 셉니다.

**틀리면 이렇게 된다**
`in` 검사 없이 바로 더하면 첫 표에서 멈춥니다.

```python
counts = {}
for day in votes:
    counts[day] = counts[day] + 1
```
```
KeyError: '화'
```

「'화' 라는 키가 없다」는 뜻이고, 1-15 의 `KeyError: 0` 과 같은 에러입니다.
없는 키를 **꺼내면** 에러가 나고, 없는 키에 **넣으면** 새로 생깁니다. `counts[day] + 1` 은 꺼내기부터 하다가 멈춥니다.

처음 나온 요일을 0 으로 넣으면 에러 없이 요일마다 한 표씩 모자랍니다(`화: 2표`, `목: 2표`, `금: 0표`, `월: 0표`). 처음 나온 그 표도 한 표입니다.

**실제로 쓸 때는**
「무엇이 몇 번 나왔나」는 설문 집계, 메뉴별 주문 수, 사람별 방문 횟수에 늘 나옵니다.
같은 일을 `counts[day] = counts.get(day, 0) + 1` 한 줄로도 씁니다. `.get(키, 0)` 은 키가 없으면 에러 대신 0 을 줍니다.

**앞 문제와의 연결**
1-15 의 딕셔너리 넣기·바꾸기를 1-11 의 for, 1-10 의 if·else 안에서 씁니다. 1-11 의 쌓아 더하기를 요일마다 하나씩 따로 하는 셈입니다.

## [1-17] 텀블러 할인 함수

**묻는 것**
같은 계산을 함수로 한 번 만들어 두 번 부르고, 함수가 `return` 으로 돌려준 값으로 바깥에서 합계를 내는 것입니다.

**코드 한 줄씩**

```python
def tumbler_price(price, cups):
    return (price - 300) * cups

americano = tumbler_price(4500, 2)         # -> (4500 - 300) * 2 = 8400
latte = tumbler_price(5000, 3)             # -> (5000 - 300) * 3 = 14100
print(f"아메리카노 2잔: {americano:,}원")   # -> 아메리카노 2잔: 8,400원
print(f"라떼 3잔: {latte:,}원")             # -> 라떼 3잔: 14,100원
print(f"합계: {americano + latte:,}원")     # -> 합계: 22,500원
```

`def 이름(값, 값):` 이 함수를 만드는 줄입니다. 이 줄만으로는 계산이 일어나지 않고, 부를 때 실행됩니다.
`price` 와 `cups` 는 부를 때 넣어 주는 값을 받는 이름(매개변수)입니다. `tumbler_price(4500, 2)` 라고 부르면 `price` 에 4500, `cups` 에 2 가 차례로 들어갑니다.
`return` 은 계산한 값을 부른 자리로 돌려줍니다. 돌려받은 8400 이 `americano` 에 담깁니다.
돌려받은 값이 보통 숫자라서 `:,` 도 붙고 더하기도 됩니다.

**왜 이렇게 푸나**
`(가격 - 300) * 잔 수` 를 메뉴마다 따로 쓰면, 할인액이 바뀔 때 고칠 곳이 메뉴 수만큼 생깁니다. 함수로 묶으면 한 곳만 고칩니다.
`print` 가 아니라 `return` 인 이유는 힌트 그대로입니다. 바깥에서 그 값으로 합계를 내야 하는데, print 는 화면에 보여 줄 뿐 값을 돌려주지 않습니다.

**틀리면 이렇게 된다**
함수 안에서 print 만 하면 화면에 숫자는 찍히지만, 돌려받는 값은 `None`(아무것도 없음)입니다. 거기에 `:,` 를 붙이면 멈춥니다.

```python
def tumbler_price(price, cups):
    print((price - 300) * cups)

americano = tumbler_price(4500, 2)
print(f"아메리카노 2잔: {americano:,}원")
```
```
TypeError: unsupported format string passed to NoneType.__format__
```

에러 위에 함수 안 print 가 찍은 `8400` 이 먼저 나옵니다. 숫자가 보이니 된 줄 알기 쉽습니다.
`:,` 없이 두 값을 더해도 `None` 끼리라서 더할 수 없다는 TypeError 가 납니다.

괄호를 빼고 `return price - 300 * cups` 로 쓰면 곱하기가 먼저라서, 아메리카노가 `4500 - 600` 인 `3,900원` 이 됩니다. 에러가 안 나서 숫자만 보고 알아채야 합니다.

부를 때 값을 하나 빠뜨리면 「cups 에 들어갈 값이 없다」고 합니다.

```python
def tumbler_price(price, cups):
    return (price - 300) * cups

americano = tumbler_price(4500)
```
```
TypeError: tumbler_price() missing 1 required positional argument: 'cups'
```

만들 때 이름이 두 개였으면 부를 때도 값이 두 개입니다.

**실제로 쓸 때는**
할인·세금·배송비처럼 규칙이 있는 계산은 함수 하나로 두고 여러 곳에서 부릅니다. 규칙이 바뀌면 함수만 고칩니다.
계산 함수는 return 만 하고 화면에 찍는 일은 바깥에서 하도록 나눠 두면, 같은 함수를 어디서든 다시 씁니다.

**앞 문제와의 연결**
1-1·1-2 에서 줄마다 직접 썼던 계산을 이름 붙은 묶음으로 만들었습니다. 1-20 에서 같은 모양의 함수를 파일의 줄마다 부릅니다.

## [1-18] 장보기 메모 파일 읽기

**묻는 것**
`with open(...)` 으로 파일을 열고 for 로 한 줄씩 읽어 번호를 붙여 찍는 것, 그리고 `encoding` 을 적는 이유입니다.

**코드 한 줄씩**

```python
num = 1
with open("shopping.txt", encoding="utf-8") as f:
    for line in f:
        print(f"{num}. {line.strip()}")
        num = num + 1
```

`open("shopping.txt", encoding="utf-8")` 이 파일을 엽니다. 맨 위 두 줄이 data 폴더를 작업 폴더로 잡아 줘서 파일 이름만 쓰면 됩니다.
`encoding="utf-8"` 은 「이 파일의 글자는 UTF-8 방식으로 저장돼 있다」고 알려 주는 것입니다.
`with ... as f:` 는 연 파일에 `f` 라는 이름을 붙이고, 들여 쓴 부분이 끝나면 파일을 알아서 닫아 줍니다.
`for line in f:` 는 파일을 한 줄씩 문자열로 꺼냅니다. 리스트를 돌던 1-11 과 같은 모양입니다.
읽은 줄은 `'우유,2,2800\n'` 처럼 끝에 줄바꿈 글자 `\n` 이 붙어 있습니다(힌트). `.strip()` 이 그것을 뗍니다.
줄 번호 `num` 은 1-11 의 `count` 처럼 바퀴마다 1씩 올립니다.

**왜 이렇게 푸나**
`with` 를 쓰면 닫는 줄을 따로 쓰지 않아도 되고, 중간에 에러가 나도 파일이 닫힙니다. 이 문제는 읽기만 하고, 파일에 쓰기는 중급에서 합니다.

**틀리면 이렇게 된다**
`.strip()` 을 빼고 `{line}` 을 그대로 찍으면 줄 끝의 `\n` 과 print 가 붙이는 줄바꿈이 겹칩니다.
`1. 우유,2,2800` 아래에 빈 줄이 하나 끼고 `2. 계란,1,6900` 이 나오는 식으로, 줄마다 사이에 빈 줄이 생깁니다.
파일의 마지막 줄도 `\n` 으로 끝나서 `5. 식빵,2,3200` 뒤에도 빈 줄이 하나 남습니다.

파일 이름을 틀리면 「그런 파일이나 폴더가 없다」고 합니다. 따옴표 안이 파이썬이 찾은 이름이니, 철자와 확장자를 거기서 봅니다.

```python
with open("shoping.txt", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```
```
FileNotFoundError: [Errno 2] No such file or directory: 'shoping.txt'
```

맨 위 두 줄을 지우고 python-problems 폴더에서 돌려도 같은 에러가 납니다(그때는 `'shopping.txt'`). data 폴더가 아닌 곳에서 찾기 때문입니다.
`num = 1` 을 for 안에 넣으면 번호가 전부 `1.` 입니다.

★ encoding 을 빼면 컴퓨터에 따라 갈립니다.

```python
num = 1
with open("shopping.txt") as f:
    for line in f:
        print(f"{num}. {line.strip()}")
        num = num + 1
```

맥(한국어 설정)에서는 3.9·3.14·3.15 모두 빼도 그대로 돌았습니다. 맥의 기본 글자 방식이 UTF-8 이라서입니다.
한국어 윈도우는 기본 글자 방식이 cp949 라서 3.14 이하에서는 이렇게 멈출 것으로 봅니다.

```
UnicodeDecodeError: 'cp949' codec can't decode byte 0xec in position 0: illegal multibyte sequence
```

이 줄은 맥에서 기본 글자 방식을 CP949 로 바꿔(로케일 `ko_KR.CP949`) 3.9·3.14 로 받은 것입니다. **윈도우 실기에서는 확인하지 못했습니다.**
3.15 는 기본이 UTF-8 모드라서 로케일을 바꿔도 정상으로 돌았습니다. 어느 컴퓨터, 어느 버전에서나 같게 돌게 하려면 `encoding="utf-8"` 을 적습니다.

**실제로 쓸 때는**
메모·설정 파일·내려받은 목록 같은 텍스트 파일은 거의 이 모양(`with open` -> `for line in f` -> `line.strip()`)으로 읽기 시작합니다.
남이 만든 파일은 UTF-8 이 아닐 수도 있어서, 글자가 깨지거나 UnicodeDecodeError 가 나면 encoding 부터 의심합니다.

**앞 문제와의 연결**
1-11 의 for 가 리스트 대신 파일을 돕니다. `.strip()` 은 1-6·1-12 에서 썼습니다. 1-20 에서 이 파일을 다시 읽어 금액을 냅니다.

## [1-19] 간식 상자 몇 개

**묻는 것**
`import math` 로 모듈을 불러와 `math.ceil()`(올림)로 모자라지 않는 상자 수를 구하는 것입니다.

**코드 한 줄씩**

```python
import math
people = 23
per_box = 6
boxes = math.ceil(people / per_box)
print(f"{boxes}상자 필요 / 남는 간식 {boxes * per_box - people}개")   # -> 4상자 필요 / 남는 간식 1개
```

`import math` 는 파이썬에 딸려 오는 수학 도구 묶음(모듈) `math` 를 불러옵니다. 불러온 뒤에는 `math.도구이름` 으로 씁니다.
`people / per_box` 는 3.8333333333333335 입니다. 3상자로는 모자랍니다.
`math.ceil()` 은 소수가 조금이라도 있으면 위로 올려 4 를 줍니다. 결과가 정수라서 `4.0` 이 아니라 `4` 로 찍힙니다.
`boxes * per_box - people` 은 24개에서 23명을 뺀 1개입니다.
맨 위의 `import os` 도 같은 import 입니다. `os` 모듈을 불러와 그 안의 `os.chdir()`(작업 폴더 바꾸기)를 쓴 것입니다.

**왜 이렇게 푸나**
상자는 반만 살 수 없고, 간식이 모자라면 안 됩니다. 그래서 버림(`//`)이 아니라 올림이고, 올림은 `+ - * / // %` 같은 기본 기호에 없어서 math 를 불러옵니다.
`//` 만으로 같은 답을 낼 수도 있습니다. 상자 크기보다 1 작은 수(여기선 5)를 더한 뒤 몫을 내면 올림과 같아집니다.

```python
boxes = (people + per_box - 1) // per_box
print(f"{boxes}상자 필요 / 남는 간식 {boxes * per_box - people}개")
```
```
4상자 필요 / 남는 간식 1개
```

`(23 + 5) // 6` 은 28 // 6 = 4 입니다. 출력이 같아서 문제 칸으로는 둘을 가려낼 수 없습니다.
그래도 이 문제는 `math.ceil` 로 풉니다. 「올린다」는 뜻이 이름에 그대로 보이고, `+ 5` 가 왜 5인지 따로 설명할 필요가 없습니다.
`(23 + 5) // 6` 처럼 숫자로 적어 두면 위험하기도 합니다. 상자당 4개로 바꾸면서 `+ 5` 를 그대로 두면 `(23 + 5) // 4` 는 7 인데, 맞는 답은 6상자입니다.

**틀리면 이렇게 된다**
`math.` 을 빼고 `ceil()` 만 쓰면 그런 이름이 없다고 합니다. ceil 은 math 안에 있어서 앞에 `math.` 을 붙여야 찾습니다(힌트).

```python
boxes = ceil(people / per_box)
```
```
NameError: name 'ceil' is not defined
```

`import math` 를 빼면 math 라는 이름부터 없습니다.

```python
boxes = math.ceil(people / per_box)
```
```
NameError: name 'math' is not defined. Did you forget to import 'math'?
```

3.14 는 「import 를 잊었느냐」고 짚어 줍니다. 3.9 에서는 `NameError: name 'math' is not defined` 까지만 나옵니다.

★ 의 답입니다. `23 // 6` 은 3 이라 3상자 = 18개, 5개가 모자랍니다. 몫 `//` 을 먼저 내고 올리면 소수가 이미 버려져 올릴 것이 없습니다.

```python
import math
boxes = math.ceil(people // per_box)
print(f"{boxes}상자 필요 / 남는 간식 {boxes * per_box - people}개")
```
```
3상자 필요 / 남는 간식 -5개
```

「-5개」가 곧 「5개 모자람」입니다. 올림은 나누기 `/` 의 결과에 해야 합니다.
`round()`(반올림)는 23명일 때는 우연히 맞습니다. 25명이면 25 / 6 = 4.166... 이 4 로 내려가 `4상자 필요 / 남는 간식 -1개` 가 나옵니다. 맞는 답은 5상자입니다.

**실제로 쓸 때는**
게시판 페이지 수(글 23개를 한 쪽에 6개씩), 버스 대수, 포장 상자 수처럼 「나누고 남으면 하나 더」인 계산은 전부 올림입니다.
import 는 보통 파일 맨 위에 모아 둡니다. 정답 파일에서는 어느 문제에서 쓰는지 보이도록 1-19 칸에 두었습니다.

**앞 문제와의 연결**
1-1 의 `//`(몫)은 버림이었고, 여기서는 올림이 필요해 math 를 불러왔습니다. 문제 파일 맨 위 `import os` 두 줄이 무슨 뜻이었는지도 여기서 풀립니다.

## [1-20] 장보기 메모 합계 -- 종합

**묻는 것**
1-18 의 파일을 한 줄씩 읽고, 1-8 처럼 쉼표로 잘라 숫자로 바꾸고, 1-17 처럼 함수로 줄 금액을 내서, 1-11 처럼 총합계에 더하는 것입니다.

**코드 한 줄씩**

```python
def line_amount(count, price):
    return count * price

total = 0
with open("shopping.txt", encoding="utf-8") as f:
    for line in f:
        parts = line.strip().split(",")
        amount = line_amount(int(parts[1]), int(parts[2]))
        total = total + amount
        print(f"{parts[0]} {amount:>6,}원")
print(f"총합계 {total:,}원")
```

`line_amount` 는 수량과 단가를 받아 곱을 돌려줍니다(1-17). 함수는 부르기 전에 만들어 둬야 하니 맨 위에 둡니다.
총합계 `total` 은 for 위에서 0 으로 놓고(1-11), 파일을 여는 두 줄은 1-18 과 같습니다.
첫 줄 `'우유,2,2800\n'` 은 `.strip()` 으로 `'우유,2,2800'`, `.split(",")` 으로 `['우유', '2', '2800']` 이 됩니다(1-8). 점으로 이어 쓴 것은 왼쪽부터 차례로 됩니다.
`parts[1]` 과 `parts[2]` 는 아직 문자열이라(힌트) `int()` 로 바꿔 함수에 넣습니다. 돌아온 5600 을 총합계에 더합니다.
`{amount:>6,}` 은 쉼표를 넣고 6칸 오른쪽 맞춤입니다(1-2). `5,600` 은 다섯 글자라 앞에 공백이 하나 붙어 `우유  5,600원` 이 됩니다.
마지막 print 는 들여쓰기가 없어서 for 와 with 가 다 끝난 뒤 한 번만 찍힙니다.

```
우유  5,600원
계란  6,900원
두부  4,500원
대파  2,500원
식빵  6,400원
총합계 25,900원
```

**왜 이렇게 푸나**
한 줄을 처리하는 순서는 「떼고 -> 자르고 -> 숫자로 -> 계산하고 -> 더하고 -> 찍기」입니다. 줄마다 똑같으니 for 안에 그 순서대로 적습니다.
금액 계산을 함수로 뺀 것은 1-17 과 같은 이유입니다. 나중에 할인이나 세금이 붙어도 함수만 고칩니다.
총합계는 놓는 줄이 for 위, 더하는 줄이 for 안, 찍는 줄이 for 밖입니다. 1-11 과 같은 배치입니다.

**틀리면 이렇게 된다**
함수에서 `return` 을 빼면 돌려받는 값이 None 이라 총합계에 더할 때 멈춥니다.

```python
def line_amount(count, price):
    count * price

total = 0
total = total + line_amount(2, 2800)
```
```
TypeError: unsupported operand type(s) for +: 'int' and 'NoneType'
```

「정수 `total` 에 None 을 더하려 했다」는 뜻입니다. 1-17 의 None 과 같은 원인입니다.

`int()` 를 빼면 문자열끼리 곱하게 됩니다.

```python
def line_amount(count, price):
    return count * price

print(line_amount("2", "2800"))
```
```
TypeError: can't multiply sequence by non-int of type 'str'
```

글자에 글자를 곱할 수는 없다는 뜻입니다.

`total = 0` 을 for 안에 넣으면 줄 금액은 맞고 마지막 줄만 `총합계 6,400원` 으로 틀립니다. 식빵 한 줄 금액만 남은 것입니다.

`.strip()` 을 빼도 이 파일에서는 출력이 같습니다. `int()` 가 숫자 앞뒤의 공백과 줄바꿈은 무시하기 때문입니다(`int("3200\n")` 은 3200).
대신 마지막 칸이 `'3200\n'` 처럼 줄바꿈을 단 채로 남아서, 그 칸을 글자로 찍거나 비교하는 순간 드러납니다. 숫자로 바꾸기 전에 떼어 두는 편이 안전합니다.

**실제로 쓸 때는**
가계부, 주문 목록, 영수증 메모처럼 한 줄에 한 건씩 적힌 파일에서 금액을 내는 일이 이 모양입니다. 중급과 고급에서는 여기에 빈 줄·깨진 줄 거르기, 분류별 합계 같은 일이 붙습니다.

**앞 문제와의 연결**
새 문법은 없습니다. 1-18 의 파일 읽기, 1-8 의 split·int, 1-17 의 함수·return, 1-11 의 쌓아 더하기, 1-2 의 자리 맞춤을 한 반복 안에 넣었습니다.
