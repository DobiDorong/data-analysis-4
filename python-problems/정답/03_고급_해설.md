# 고급 20문제 해설

문제마다 여섯 칸으로 적었습니다. 「묻는 것 -> 코드 한 줄씩 -> 왜 이렇게 푸나 ->
틀리면 이렇게 된다 -> 실제로 쓸 때는 -> 앞 문제와의 연결」 입니다.
막힌 문제만 골라 봐도 됩니다.

해설에 적힌 에러 문구와 출력은 전부 직접 실행해서 받은 것입니다(파이썬 3.14, 맥).
3.10 이하에서는 `Did you mean:` 같은 안내가 붙지 않는 등 문구가 조금 짧게 나옵니다.
에러 이름과 콜론 뒤의 핵심 문장은 같습니다. 버전마다 크게 다른 곳은 본문에 따로 적었습니다.

메모리 주소가 섞인 문구(`0x1061b4330` 같은 것)는 실행할 때마다 값이 바뀝니다.
그 자리는 숫자가 달라도 맞습니다.

## [3-1] 앱 로그 오류 요약

**묻는 것**
「|」 로 나뉜 로그를 읽어 깨진 줄은 따로 모으고, 수준별 건수와 수준마다 가장 많이 나온 문구를 세는 법을 묻습니다. 새 도구는 없습니다. 중급의 파일 읽기·튜플·딕셔너리 세기를 일 하나로 엮습니다.

**코드 한 줄씩**

```python
def read_log(path):
    records = []
    broken = []
    no = 0
    with open(path, encoding="utf-8") as f:
        for line in f:
            no = no + 1
            line = line.strip()
            if line == "":
                continue
            parts = line.split("|")
            if len(parts) != 3:
                broken.append((no, line))
                continue
            records.append((parts[1].strip(), parts[2].strip()))
    return records, broken
```

`no` 는 줄을 읽자마자 1을 더하고 나서 빈 줄을 거릅니다. 그래서 빈 줄도 세어지고, 깨진 줄 번호가 파일의 실제 줄 번호와 같습니다. `line.strip()` 으로 줄 끝 `\n` 을 떼야 빈 줄이 `""` 가 됩니다.
「|」 로 자른 칸이 3개가 아니면 (줄번호, 원본) 을 `broken` 에 넣고 넘어갑니다. `parts[1]` `parts[2]` 는 칸 수를 확인한 뒤에 꺼냅니다.
기록은 (수준, 문구) 튜플입니다. 「|」 양옆 공백이 칸에 붙어 오니 둘 다 `.strip()` 합니다. 날짜 칸(`parts[0]`)은 안 써서 버립니다.

```python
def count_levels(records):
    counts = {}
    for level, message in records:
        counts[level] = counts.get(level, 0) + 1
    return counts

def top_message(records, level):
    counts = {}
    for rec_level, message in records:
        if rec_level == level:
            counts[message] = counts.get(message, 0) + 1
    best = ""
    best_count = 0
    for message in counts:
        if counts[message] > best_count:
            best = message
            best_count = counts[message]
    return best, best_count
```

count_levels 는 수준을 키로 1씩 쌓습니다(2-8 의 `.get`). top_message 는 고른 수준의 문구만 센 뒤, 지금까지 본 것보다 큰 것을 들고 다니며 1등을 찾습니다(2-7).
`>` 라서 건수가 같으면 바꾸지 않습니다. 딕셔너리는 넣은 순서대로 도니, 동점이면 먼저 나온 문구가 남습니다.

```python
records, broken = read_log("app.log")
levels = count_levels(records)
print(f"INFO {levels.get('INFO', 0)}건 / WARN {levels.get('WARN', 0)}건 / ERROR {levels.get('ERROR', 0)}건")
print(f"형식이 깨진 줄 {len(broken)}줄")
for no, line in broken:
    print(f"  {no}번 줄: {line}")
for level in ["WARN", "ERROR"]:
    message, count = top_message(records, level)
    print(f"가장 많은 {level}: {message} ({count}건)")
```

f-string 안의 딕셔너리 키는 작은따옴표로 씁니다. 큰따옴표로 쓰면 3.14 는 돌지만 3.9 는 `SyntaxError` 로 멈춥니다.

**왜 이렇게 푸나**
함수를 「읽기」 하나와 「세기」 둘로 나눴습니다. read_log 가 파일을 한 번만 읽고, 그 뒤로는 목록만 봅니다. top_message 는 수준을 인자로 받아 WARN·ERROR 에 두 번 부릅니다. 수준이 늘어도 리스트에 이름만 더하면 됩니다. 줄 하나 안의 순서는 strip -> 빈 줄 -> 칸 수 -> 꺼내기입니다. strip 전에 빈 줄을 보면 `"\n"` 이 `""` 와 달라 빈 줄이 깨진 줄로 갑니다. 칸 수보다 먼저 `parts[2]` 를 꺼내면 칸이 1개인 6번 줄에서 멈춥니다.

칸이 못 가려내는 풀이가 있습니다. `>` 를 `>=` 로 바꿔도 칸이 같습니다. 이 로그에는 1등이 둘인 수준이 없습니다. 동점이면 갈립니다.

```python
records_tie = [("WARN", "재고 부족 알림"), ("WARN", "디스크 사용량 80% 넘음")]
print(top_message(records_tie, "WARN"))
```
```
('재고 부족 알림', 1)
```

`>=` 로 바꾼 top_message 는 `('디스크 사용량 80% 넘음', 1)` 을 돌려줍니다. 규칙의 「먼저 나온 것」 은 `>` 쪽입니다.

**틀리면 이렇게 된다**
문구의 `.strip()` 을 빼면 「|」 뒤 공백이 문구 앞에 붙습니다. 공백이 한 칸인 줄과 두 칸인 줄(8번·13번)이 다른 문구로 세어져 마지막 두 줄이 바뀝니다(4번 줄 끝 공백은 `line.strip()` 이 이미 뗐습니다).

```
가장 많은 WARN:  디스크 사용량 80% 넘음 (1건)
가장 많은 ERROR:  결제 승인 실패 (2건)
```

수준의 `.strip()` 을 빼면 더 조용히 틀립니다. 키가 `" INFO "` 가 되어 `.get` 이 0을 줍니다. 에러 없이 첫 줄이 `INFO 0건 / WARN 0건 / ERROR 0건`, 마지막 두 줄이 `가장 많은 WARN:  (0건)` 꼴로 나옵니다.

`if line == "": continue` 를 빼면 11번 빈 줄이 깨진 줄이 되어 `형식이 깨진 줄 3줄` 과 `  11번 줄: ` 이 나옵니다(콜론 뒤에 공백 하나).

`.get` 없이 대괄호로 세면 처음 나온 수준에서 멈춥니다.

```python
counts = {}
counts["INFO"] = counts["INFO"] + 1
```
```
KeyError: 'INFO'
```

**실제로 쓸 때는**
장애가 난 다음 날 아침 「어젯밤 무슨 오류가 몇 번 났나」 를 정리하는 일이 신입에게 자주 옵니다. 같은 오류가 공백 하나 차이로 따로 세어지면 3번 난 결제 실패를 「2건」 으로 보고하게 됩니다. 문구는 세기 전에 모양부터 맞춥니다. 깨진 줄은 버리지 말고 줄번호와 함께 보고에 붙입니다. 여러 줄로 찍힌 오류나 다른 프로그램이 끼워 쓴 줄이 거기 숨어 있습니다.

**앞 문제와의 연결**
줄번호 세기·`continue`·(줄번호, 원본) 목록은 2-13, 튜플을 나눠 받는 for 와 가장 큰 값 찾기는 2-7, `.get` 으로 세기는 2-8 과 같습니다. 3-2 가 이 「읽기 함수가 살린 것·버린 것 두 목록을 돌려준다」 틀에 사유와 파일 쓰기를 더합니다.

## [3-2] 모임 일정 메모를 CSV로

**묻는 것**
「/」 로 적은 메모에서 주석·빈 줄을 건너뛰고, 칸 수 -> 날짜 -> 회비 순서로 검사해 통과한 줄은 CSV 로, 걸린 줄은 사유와 함께 오류 파일로 나눠 쓰는 법을 묻습니다. 새 도구는 `startswith` 와 `not` 입니다.

**코드 한 줄씩**

```python
def is_date(text):
    parts = text.split("-")
    if len(parts) != 3:
        return False
    if len(parts[0]) == 4 and len(parts[1]) == 2 and len(parts[2]) == 2:
        return parts[0].isdigit() and parts[1].isdigit() and parts[2].isdigit()
    return False

def parse_memo(path):
    rows = []
    errors = []
    no = 0
    with open(path, encoding="utf-8") as f:
        for line in f:
            no = no + 1
            line = line.strip()
            if line == "" or line.startswith("#"):
                continue
            cells = line.split("/")
            if len(cells) != 4:
                errors.append((no, "칸 수", line))
                continue
            date = cells[0].strip()
            fee = cells[3].strip()
            if fee == "무료":
                fee = "0"
            if not is_date(date):
                errors.append((no, "날짜", line))
            elif not fee.isdigit():
                errors.append((no, "회비", line))
            else:
                rows.append([date, cells[1].strip(), cells[2].strip(), int(fee)])
    return rows, errors
```

is_date 는 「-」 로 잘라 칸이 3개인지, 길이가 4·2·2 인지, 셋 다 숫자인지 봅니다. `return 조건` 은 조건의 결과(True/False)를 그대로 돌려줍니다. `line.startswith("#")` 은 줄이 「#」 으로 시작하면 True 입니다. 빈 줄과 `or` 로 묶어 건너뜁니다. 칸이 4개가 아니면 「칸 수」 를 남기고 넘어갑니다. `cells[3]` 은 그 뒤에 꺼냅니다.
「무료」 는 글자 `"0"` 으로 바꿔 둡니다. 그러면 숫자 검사 한 번으로 무료와 숫자를 같이 처리합니다.
`not` 은 True 와 False 를 뒤집습니다. `not is_date(date)` 는 「날짜 모양이 아니면」 입니다. if / elif / else 한 사슬이라 처음 걸린 사유 하나만 남고, 둘 다 통과한 줄만 일정이 됩니다.

```python
def write_schedule(path, rows):
    with open(path, "w", encoding="utf-8") as f:
        f.write("날짜,모임,장소,회비\n")
        for row in rows:
            f.write(f"{row[0]},{row[1]},{row[2]},{row[3]}\n")

def write_errors(path, errors):
    with open(path, "w", encoding="utf-8") as f:
        for no, reason, line in errors:
            f.write(f"{no}: {reason}: {line}\n")

rows, errors = parse_memo("schedule_memo.txt")
write_schedule("schedule.csv", rows)
write_errors("schedule_errors.txt", errors)
monthly = {}
for row in rows:
    month = row[0][:7]
    monthly[month] = monthly.get(month, 0) + row[3]
print(f"일정 {len(rows)}건 / 오류 {len(errors)}건")
for month in monthly:
    print(f"{month} 회비 {monthly[month]:,}원")
for path in ["schedule.csv", "schedule_errors.txt"]:
    with open(path, encoding="utf-8") as f:
        for line in f:
            print(line.strip())
```

두 쓰기 함수는 2-14 와 같은 모양입니다. 달은 날짜 앞 7글자(`"2026-12"`)이고, 이 달을 키로 회비를 쌓아 더합니다. 다시 읽기는 파일 이름 두 개를 리스트에 넣고 같은 코드로 돕니다.

**왜 이렇게 푸나**
is_date 를 따로 뺀 것은 날짜 검사만 시험해 보기 위해서입니다. `is_date("2027-1-24")` 한 줄로 False 를 확인합니다. parse_memo 는 읽고 가르기만 하고, 쓰기와 달별 합은 밖에서 합니다. 3-1 과 같은 틀입니다.
칸 수가 맨 앞인 것은 칸이 모자란 줄에서 `cells[3]` 을 꺼낼 수 없어서입니다. 날짜를 칸 수보다 먼저 보면 칸이 3개인 11번 줄이 `11: 날짜: 1월 10일 / 독서 모임 / 동네 카페` 로 사유가 바뀝니다.

칸이 못 가려내는 풀이가 있습니다. 날짜와 회비 검사의 순서를 바꿔도 칸이 같습니다. 이 메모에는 날짜와 회비가 둘 다 틀린 줄이 없습니다. 그런 줄이 생기면 사유가 「회비」 로 바뀌니 지문 순서를 지킵니다.

**틀리면 이렇게 된다**
elif 를 if 로 바꾸면 사슬이 끊겨 else 가 회비 검사에만 붙습니다. 날짜가 틀려도 회비가 숫자면 일정에 들어가고 오류 목록에도 남습니다. 첫 줄이 `일정 8건 / 오류 5건` 이 되고 달별 합에 `2026.12 회비 30,000원` 과 `2027-1- 회비 8,000원` 이 끼어듭니다.

회비의 `.strip()` 을 빼면 「/」 뒤 공백 때문에 `" 3000".isdigit()` 이 False 입니다. `일정 0건 / 오류 11건` 이 되고, 칸 수·날짜로 걸린 네 줄 말고는 사유가 전부 「회비」 입니다.

「무료」 를 0으로 안 바꾸면 `4: 회비: 2026-12-12 / 보드게임 / 역 앞 보드게임방 / 무료` 가 오류에 들어가고 일정은 5건이 됩니다.

is_date 에서 칸 길이(4·2·2)를 안 보면 `2027-1-24` 가 통과해 `2027-1- 회비 8,000원` 줄이 생깁니다.

isdigit 검사 없이 `int(fee)` 를 부르면 「미정」 에서 멈춥니다.

```python
fee = "미정"
print(int(fee))
```
```
ValueError: invalid literal for int() with base 10: '미정'
```

isdigit 은 이 에러가 나기 전에 글자를 걸러 냅니다. 3-3 은 에러를 받아서 처리하는 try 를 씁니다.

**실제로 쓸 때는**
사람이 손으로 적은 메모를 표로 옮기는 일이 신입에게 자주 옵니다. 못 옮긴 줄을 조용히 버리면 총무는 일정이 빠진 줄도 모릅니다. 줄번호와 사유를 붙여 돌려주면 그 줄만 고쳐 다시 보내 줍니다. 숫자 자리에 글자가 오면, 뜻이 분명한 것(무료=0)만 바꾸고 모르는 것(미정)은 추측하지 말고 오류로 돌려줍니다.

**앞 문제와의 연결**
읽어서 두 목록으로 가르기는 3-1, 「줄번호: 사유: 원본」 쓰기는 2-14, isdigit 은 2-12, 달별 합은 2-7 의 분류별 합과 같습니다. 3-3 은 같은 틀에서 숫자 검사를 try 로 바꿉니다.

## [3-3] 회원 명단 정제

**묻는 것**
CSV 명단을 한 줄씩 검사해 살릴 줄과 버릴 줄로 나누는 법을 묻습니다. 고급에서 처음 try 를 씁니다. 포인트가 정수로 바뀔지 미리 따지지 않고, 바꿔 보다가 실패하면 그 줄을 버립니다.

**코드 한 줄씩**

```python
def clean_email(text):
    return text.strip().lower()

def read_members(path):
    kept = []
    bad = []
    seen = []
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            line = line.strip()
            if no == 1 or line == "":
                continue
            cells = line.split(",")
            if len(cells) != 4:
                bad.append((no, "칸 수", line))
                continue
            email = clean_email(cells[1])
            if "@" not in email:
                bad.append((no, "메일", line))
                continue
            try:
                point = int(cells[3])
            except ValueError:
                bad.append((no, "포인트", line))
                continue
            if email in seen:
                bad.append((no, "중복", line))
                continue
            seen.append(email)
            city = cells[2].strip()
            if city == "":
                city = "미정"
            kept.append([cells[0].strip(), email, city, point])
    return kept, bad
```

clean_email 은 메일을 앞뒤 공백 없는 소문자로 맞춥니다(2-4). `seen` 은 지금까지 살린 메일 목록입니다. 중복은 「앞에서 살린 줄과 같은 메일」 이라 맨 끝에 보고, 모든 검사를 통과한 줄의 메일만 `seen` 에 넣습니다.
BOM 있는 CSV 라 `utf-8-sig` 로 열고, 머리줄(1번)과 빈 줄은 건너뜁니다(2-13). 검사에 걸리면 사유를 남기고 `continue` 하니 처음 걸린 사유 하나만 남습니다.

이 문제의 주인공은 try 부분입니다. 정수로 못 바꾸는 글자를 `int()` 에 넣으면 원래는 ValueError 로 프로그램이 멈춥니다(1-3).
`try:` 아래에는 실패할 수 있는 줄을 둡니다. 파이썬은 그 줄을 일단 실행해 봅니다. 거기서 ValueError 가 나면 멈추지 않고 `except ValueError:` 아래로 건너뜁니다. 여기서는 버린 줄에 넣고 continue 합니다. 에러가 안 나면 except 아래는 통째로 건너뛰고, point 에 정수가 담긴 채 다음 검사로 갑니다.

```python
def write_members(path, rows):
    with open(path, "w", encoding="utf-8") as f:
        f.write("이름,메일,도시,포인트\n")
        for row in rows:
            f.write(f"{row[0]},{row[1]},{row[2]},{row[3]}\n")

kept, bad = read_members("members.csv")
write_members("members_clean.csv", kept)
print(f"살린 회원 {len(kept)}명 / 버린 줄 {len(bad)}줄")
for no, reason, line in bad:
    print(f"  {no}: {reason}: {line}")
with open("members_clean.csv", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```

**왜 이렇게 푸나**
try 의 흐름은 작은 예로 따로 돌려 보면 보입니다. 바뀌는 글자는 try 쪽, 못 바꾸는 글자는 except 쪽 줄을 탑니다.

```python
for text in ["1200", "", "구백"]:
    try:
        print(int(text))
    except ValueError:
        print(f"못 바꿈: [{text}]")
```
```
1200
못 바꿈: []
못 바꿈: [구백]
```

clean_email 을 따로 둔 것은 메일 규칙을 한 곳에 두려고서입니다. 중복 비교도, 파일에 쓰는 메일도 이 함수를 거칩니다. 규칙이 바뀌면 이 함수만 고칩니다. 검사 순서는 앞 검사가 뒤 검사의 재료를 보장하게 짰습니다. 칸이 4개여야 `cells[1]` `cells[3]` 이 있고, 메일과 포인트가 멀쩡한 줄만 `seen` 에 들어갑니다.
포인트를 try 로 보는 것은 지문이 「정수로 안 바뀜」 이라고 했기 때문입니다. `int(" 7 ")` 은 7, `int("-50")` 은 -50 인데 isdigit 은 둘 다 False 입니다. 바뀌는지는 int 에게 직접 시켜 보는 것이 정확합니다.

칸이 못 가려내는 풀이가 셋 있습니다. isdigit 으로 걸러도 같습니다(이 파일 포인트엔 공백·음수가 없습니다). 중복을 정리 전 메일(`cells[1]`)로 비교해도 같습니다(겹친 5·6번 줄이 글자까지 똑같습니다). 중복 검사와 `seen.append` 를 메일 검사 앞으로 옮겨도 같습니다(버린 줄의 메일이 뒤에 다시 안 나옵니다). 포인트가 빈 박다은 줄 뒤에 제대로 된 박다은 줄이 오면, 옮긴 쪽은 그 줄을 「중복」 으로 버립니다(작은 파일로 돌려 확인했습니다).

**틀리면 이렇게 된다**
try 없이 `int(cells[3])` 만 쓰면 4번 박다은 줄의 빈 포인트에서 멈춥니다. 3-3 출력은 한 줄도 안 나옵니다.

```python
cells = "박다은,DAEUN@EXAMPLE.COM,서울,".split(",")
point = int(cells[3])
```
```
ValueError: invalid literal for int() with base 10: ''
```

`except ValueError:` 를 `except TypeError:` 처럼 다른 이름으로 적어도 같은 에러로 멈춥니다. except 는 적은 이름의 에러만 받습니다.

except 아래 `continue` 를 빼면 멈추지 않아서 더 찾기 어렵습니다. 버린 줄이 그대로 내려가 살린 목록에도 들어가고, point 에는 앞 줄의 값이 남아 있습니다. 첫 줄이 `살린 회원 8명 / 버린 줄 5줄` 이 되고, 파일에 `박다은,daeun@example.com,서울,840` 과 `한지우,jiwoo@example.com,인천,1500` 이 섞입니다. 840 은 앞 줄 이준서의 포인트, 1500 은 6번 최민재 줄에서 바꾼 값입니다.

**실제로 쓸 때는**
회원 명단을 메일 발송 도구에 올리기 전에 정리해 달라는 일이 자주 옵니다. 대소문자만 다른 메일을 못 거르면 같은 사람에게 안내 메일이 두 통 갑니다. 버린 줄을 줄번호·사유와 같이 돌려주면 담당자가 원본에서 바로 고칩니다. try 는 「실패하면 이렇게 한다」 가 정해진 줄에만 씁니다. 아무 데나 감싸 에러를 숨기면 3-17 같은 일이 생깁니다.

**앞 문제와의 연결**
메일 정리와 `@` 검사는 2-4, BOM 과 머리줄 건너뛰기는 2-13, 중복 거르기는 2-15, 검사 순서와 사유 남기기는 3-2 와 같습니다. 3-2 는 isdigit 으로 글자를 미리 걸렀고, 여기서는 바꿔 보고 실패를 받았습니다. try 는 3-11·3-12·3-17 에서 다시 나옵니다.

## [3-4] 전화번호 표준화

**묻는 것**
모양이 제각각인 전화번호에서 숫자만 뽑아 길이로 나누고, 국가번호 82 를 0 으로 바꿔 「010-1234-5678」 모양으로 맞추는 법을 묻습니다. 고칠 수 없는 번호는 빈 글자로 알립니다.

**코드 한 줄씩**

```python
def format_phone(text):
    digits = ""
    for ch in text:
        if ch.isdigit():
            digits = digits + ch
    if len(digits) == 12 and digits[:2] == "82":
        digits = "0" + digits[2:]
    if len(digits) == 11:
        return f"{digits[:3]}-{digits[3:7]}-{digits[7:]}"
    if len(digits) == 10:
        return f"{digits[:3]}-{digits[3:6]}-{digits[6:]}"
    return ""
```

`for ch in text` 는 글자를 하나씩 꺼냅니다. 숫자인 글자만 이어 붙이면 하이픈·공백·괄호·+ 가 다 빠집니다.
82 로 시작하는 12자리면 앞 두 글자를 떼고 `"0"` 을 붙입니다. `821023456789` 가 `01023456789` 가 됩니다.
11자리는 3-4-4, 10자리는 3-3-4 로 잘라 하이픈으로 잇습니다(1-5). `digits[3:7]` 은 4째부터 7째 글자까지입니다. 어느 길이도 아니면 `""` 를 돌려줍니다.

```python
def fix_contacts(src, dst):
    rows = []
    problems = []
    no = 0
    with open(src, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            cells = line.strip().split(",")
            if no == 1 or len(cells) != 3:
                continue
            name = cells[0].strip()
            phone = format_phone(cells[1])
            group = cells[2].strip()
            if group == "":
                group = "미지정"
            if phone == "":
                problems.append((name, cells[1].strip()))
            else:
                rows.append(f"{name},{phone},{group}")
    with open(dst, "w", encoding="utf-8") as f:
        f.write("이름,전화,그룹\n")
        for row in rows:
            f.write(row + "\n")
    return len(rows), problems
```

머리줄과 칸이 3개가 아닌 줄(빈 줄은 나누면 1칸)은 `or` 로 묶어 건너뜁니다. format_phone 에는 칸을 그대로 넘깁니다. 공백도 숫자가 아니라 저절로 빠집니다.
못 고친 번호는 (이름, 공백 뗀 원래 번호) 로, 고친 줄은 파일에 쓸 모양 그대로 모읍니다. 읽기 with 가 끝난 뒤 쓰기로 엽니다.

```python
for text in samples:
    phone = format_phone(text)
    if phone == "":
        phone = "확인 필요"
    print(f"{text} -> {phone}")
count, problems = fix_contacts("contacts.csv", "contacts_fixed.csv")
print(f"저장 {count}명 / 확인 필요 {len(problems)}명")
for name, raw in problems:
    print(f"  {name}: [{raw}]")
with open("contacts_fixed.csv", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```

`""` 는 「확인 필요」 로 바꿔 찍습니다. 원래 번호를 대괄호로 감싸서 노하준처럼 빈 번호도 `[]` 로 보입니다.

**왜 이렇게 푸나**
format_phone 은 글자 하나를 받아 글자 하나를 돌려줍니다. 파일과 상관없으니 samples 로 따로 시험할 수 있습니다. contacts.csv 에는 10자리·+82·괄호 번호가 없어서 파일만 돌리면 그 갈래가 맞는지 알 수 없습니다. 그래서 지문이 시험용 번호를 따로 줬습니다. fix_contacts 는 읽기·쓰기를 한 함수에 담고, 화면 출력은 밖에서 합니다.
format_phone 안의 순서는 숫자 뽑기 -> 82 바꾸기 -> 길이 보기입니다. 82 를 먼저 바꿔야 12자리가 11자리가 되어 길이 검사를 통과합니다.

칸이 못 가려내는 풀이가 있습니다. `digits[:2] == "82"` 를 빼고 12자리만 봐도 칸이 같습니다. 12자리 번호가 +82 하나뿐이어서입니다. 82 로 시작하지 않는 12자리가 오면 앞 두 자리를 잘못 지웁니다.

**틀리면 이렇게 된다**
82 바꾸기를 길이 검사 뒤로 옮기면 12자리가 길이 검사를 먼저 만나 `""` 가 됩니다. samples 둘째 줄이 `+82 10-2345-6789 -> 확인 필요` 로 바뀝니다.

숫자만 뽑는 for 대신 `text.replace("-", "")` 로 하이픈만 지우면 공백·괄호·+ 가 남아 길이가 안 맞습니다. 파일 쪽은 결과가 그대로라 더 늦게 알아챕니다.

```
031-123-4567 -> 031-123-4567
+82 10-2345-6789 -> 확인 필요
(010) 3456 7890 -> 확인 필요
010-123-456 -> 확인 필요
```

`no == 1` 을 빼면 머리줄도 칸이 3개라 사람으로 읽힙니다. 「전화」 에 숫자가 없어 확인 필요가 3명이 되고 `  이름: [전화]` 가 맨 위에 찍힙니다.

칸 수 검사를 빼면 빈 줄에서 멈춥니다. 빈 줄은 나누면 칸이 1개라 `cells[1]` 이 없습니다.

```python
cells = "".split(",")
phone = format_phone(cells[1])
```
```
IndexError: list index out of range
```

**실제로 쓸 때는**
단체 문자를 보내기 전에 연락처를 정리하라는 일에서 자주 나옵니다. 사람마다 하이픈·공백·괄호·국가번호를 다르게 적습니다. 숫자만 뽑아 길이로 판단하면 모양이 몇 가지든 한 번에 맞춥니다. 자리 수가 모자란 번호(구본희)를 그럴듯하게 채우지 말고, 이름과 원래 번호를 따로 알려 사람이 확인하게 합니다.

**앞 문제와의 연결**
isdigit 은 2-12, 슬라이싱은 1-5, 읽고 고쳐 새 파일로 쓰기는 2-15·3-3, 빈 칸 기본값(「미지정」)은 3-3 의 「미정」 과 같습니다. 실패를 `""` 로 돌려주고 부르는 쪽이 보는 것은 2-16 의 `("", 0)` 과 같은 방식입니다.

## [3-5] 할 일 JSON 불러와 고쳐 저장

**묻는 것**
JSON 파일을 `json.load` 로 읽어 리스트·딕셔너리로 받고, 고친 뒤 `json.dump` 로 새 파일에 쓰는 법을 묻습니다. 없는 번호와 이미 있는 제목을 골라내고, 새 번호를 「가장 큰 번호 + 1」 로 매깁니다.

**코드 한 줄씩**

```python
import json
def next_id(todos):
    biggest = 0
    for todo in todos:
        if todo["id"] > biggest:
            biggest = todo["id"]
    return biggest + 1

def mark_done(todos, ids):
    missing = []
    for todo_id in ids:
        found = False
        for todo in todos:
            if todo["id"] == todo_id:
                todo["done"] = True
                found = True
        if not found:
            missing.append(todo_id)
    return missing
```

`import json` 은 JSON 도구 묶음을 불러옵니다(1-19 의 import math 와 같은 방식). 할 일 하나가 딕셔너리라 번호는 `todo["id"]` 로 꺼냅니다. next_id 는 가장 큰 번호를 들고 다니며 찾아 1을 더합니다(2-7).
mark_done 의 `found` 는 「찾았나」 를 기억하는 깃발입니다. 안쪽 for 가 다 끝나야 「없다」 고 말할 수 있어서, 없는 번호 넣기는 안쪽 for 밖에 둡니다. `todo["done"] = True` 는 todos 안의 딕셔너리를 그 자리에서 바꿉니다. 넘긴 리스트와 함수 안의 todos 가 같은 리스트라서, 함수가 끝난 뒤 밖의 todos 도 바뀐 채 남습니다.

```python
def add_todos(todos, titles):
    skipped = []
    for title in titles:
        title = title.strip()
        exists = False
        for todo in todos:
            if todo["title"] == title:
                exists = True
        if exists:
            skipped.append(title)
        else:
            todos.append({"id": next_id(todos), "title": title, "done": False})
    return skipped
```

제목은 맨 처음에 공백을 떼어 둡니다. 그래서 비교·저장·돌려주는 목록(`'우유 사기'`)이 다 뗀 제목입니다. 깃발 `exists` 는 found 와 같은 모양입니다. 새 할 일마다 `next_id(todos)` 를 다시 부릅니다. 방금 붙인 8번이 todos 에 들어 있으니 다음은 9번입니다.

```python
with open("todos.json", encoding="utf-8") as f:
    todos = json.load(f)
missing = mark_done(todos, done_ids)
skipped = add_todos(todos, new_titles)
with open("todos_after.json", "w", encoding="utf-8") as f:
    json.dump(todos, f, ensure_ascii=False, indent=2)
print(f"없는 번호: {missing}")
print(f"이미 있는 제목: {skipped}")
with open("todos_after.json", encoding="utf-8") as f:
    saved = json.load(f)
for todo in saved:
    mark = " "
    if todo["done"]:
        mark = "v"
    print(f"[{mark}] {todo['id']} {todo['title']}")
no = 0
with open("todos_after.json", encoding="utf-8") as f:
    for line in f:
        no = no + 1
        if no > 5:
            break
        print(line.replace("\n", ""))
```

`json.load(f)` 는 열린 파일을 통째로 읽어 파이썬 값으로 바꿉니다. 이 파일은 딕셔너리 6개가 든 리스트가 되고, `true` 는 `True` 로 옵니다. `json.dump(값, f, ...)` 는 반대로 값을 JSON 글자로 바꿔 씁니다. `ensure_ascii=False` 는 한글을 그대로 쓰게 하고, `indent=2` 는 값마다 줄을 바꾸고 두 칸씩 들여 씁니다.
마지막 부분은 파일을 그냥 글자로 열어 6째 줄에서 break 로 멈춥니다. `replace` 로 줄 끝 `\n` 만 지웁니다. strip 은 앞의 들여쓰기까지 지웁니다.

**왜 이렇게 푸나**
세 함수는 파일이 아니라 todos 리스트만 받습니다. 파일은 밖에서 한 번 읽고 한 번 씁니다. 그래서 `next_id([{"id": 3}])` 처럼 파일 없이 바로 시험할 수 있습니다(4 가 나옵니다).
새 번호를 「가장 큰 번호 + 1」 로 하는 것은 4번이 비어 있어서입니다. 개수 + 1 로 매기면 이미 있는 7번과 겹칩니다(아래).

칸이 못 가려내는 풀이가 있습니다. 「마지막 할 일 번호 + 1」(`todos[len(todos) - 1]["id"] + 1`)로 매겨도 칸이 같습니다. 이 파일은 번호 순으로 저장되어 마지막이 가장 큽니다. 순서가 섞인 파일이면 번호가 겹칩니다.

**틀리면 이렇게 된다**
새 번호를 `len(todos) + 1` 로 매기면 할 일이 6개라 7번부터 붙습니다. `[ ] 7 관리비 영수증 정리` 가 이미 있는 `[v] 7 엄마 생신 선물 고르기` 와 겹치고, 세탁소는 8번이 됩니다.

`ensure_ascii=False` 를 빼면 한글이 `\uc6b0` 같은 글자로 저장됩니다. 다시 load 하면 한글로 돌아와 할 일 줄은 그대로고, 파일 글자 그대로 찍은 14째 줄만 `    "title": "\uc6b0\uc720 \uc0ac\uae30",` 로 바뀝니다. `indent=2` 를 빼면 파일 전체가 한 줄로 저장되어, 앞 5줄 대신 긴 한 줄만 찍힙니다.

제목의 `.strip()` 을 빼면 `" 우유 사기 "` 가 「우유 사기」 와 달라 새 할 일로 들어갑니다. `이미 있는 제목: []` 이 되고, `[ ] 9  우유 사기 ` 가 생기며 세탁소는 10번이 됩니다.

found 깃발 없이 안쪽 for 에 `else:` 를 붙여 없는 번호를 넣으면, 다른 할 일을 만날 때마다 넣어 `없는 번호: [2, 2, 2, 2, 2, 4, 4, 4, 4, 4, 4, 7, 7, 7, 7, 7]` 이 됩니다.

json.load 에 파일 이름을 바로 넘기면 멈춥니다. load 는 열린 파일(f)을 받습니다. dump 에 이름을 넘기면 끝이 `'write'` 인 같은 꼴의 에러가 납니다.

```python
todos = json.load("todos.json")
```
```
AttributeError: 'str' object has no attribute 'read'
```

**실제로 쓸 때는**
앱이나 웹 서비스가 주고받는 자료는 JSON 인 경우가 많습니다. 「데이터 몇 개 고쳐 주세요」 가 오면 원본을 덮어쓰지 말고 새 파일로 저장해 비교한 뒤 바꿔 넣습니다. 번호를 개수 + 1 로 매기면 지운 항목이 생기는 순간 번호가 겹칩니다. 사람이 열어 볼 파일은 `ensure_ascii=False, indent=2` 로 써야 읽을 수 있습니다.

**앞 문제와의 연결**
import 는 1-19, 가장 큰 값 찾기는 2-7·3-1 과 같습니다. 끝까지 찾아도 없을 때를 따로 처리하는 것은 2-16 의 「하나도 없으면」 과 같은 생각입니다. 원본을 두고 새 파일로 쓰기는 3-2~3-4 와 같고, JSON 은 3-18 에서 설정 검증으로 다시 나옵니다.

## [3-6] 가게 설정 파일 로더

**묻는 것**
「키 = 값」 줄로 된 설정 파일을 읽어 기본값 위에 덮어쓰되, 잘못 적은 줄이 있어도 멈추지 않고 경고로 모으는 법을 묻습니다. 기본값을 건드리지 않으려고 `.copy()` 로 사본을 만드는 것이 새로 나옵니다.

**코드 한 줄씩**

```python
def split_setting(line):
    parts = line.split("=")
    return parts[0].strip(), parts[1].strip()

def load_config(path, defaults, number_keys):
    config = defaults.copy()
    warnings = []
    no = 0
    with open(path, encoding="utf-8") as f:
        for line in f:
            no = no + 1
            line = line.strip()
            if line == "" or line[:1] == "#":
                continue
            if "=" not in line:
                warnings.append(f"{no}번 줄: = 없음 [{line}]")
                continue
            key, value = split_setting(line)
            if key in number_keys:
                if value.isdigit():
                    value = int(value)
                else:
                    warnings.append(f"{no}번 줄: {key} 숫자 아님 [{value}] -> 기본값 {defaults[key]}")
                    continue
            config[key] = value
    return config, warnings

config, warnings = load_config("store.cfg", DEFAULTS, NUMBER_KEYS)
for key in config:
    print(f"{key} = {config[key]}")
print(f"경고 {len(warnings)}건")
for warning in warnings:
    print(warning)
hours = config["close_hour"] - config["open_hour"]
print(f"영업 {hours}시간 ({config['open_hour']}시 ~ {config['close_hour']}시)")
print(f"DEFAULTS 그대로: open_hour = {DEFAULTS['open_hour']}")
```

split_setting 은 「=」 양쪽을 앞뒤 공백 떼고 돌려줍니다. `split_setting("delivery_fee =  2500 ")` 은 `('delivery_fee', '2500')` 입니다. 줄에 「=」 가 있다고 믿고 `parts[1]` 을 꺼내니, 「=」 가 있는지는 부르는 쪽이 먼저 봅니다.
`defaults.copy()` 는 내용이 같은 새 딕셔너리를 만듭니다. 뒤의 `config[key] = value` 는 사본만 바꿉니다.
`no` 는 줄을 읽자마자 1을 더합니다. 건너뛰는 빈 줄·주석 줄도 세어서 경고의 줄번호가 파일의 줄번호와 맞습니다.
`line[:1]` 은 첫 글자입니다. 빈 줄에서도 `""` 가 나와 멈추지 않습니다. 3-2 의 `line.startswith("#")` 와 같은 일입니다.
숫자여야 하는 키만 `isdigit()` 으로 봅니다(2-12). 숫자가 아니면 경고를 넣고 `continue` 로 `config[key] = value` 를 건너뛰어 기본값이 남습니다.
딕셔너리는 키가 처음 들어간 순서를 지킵니다. 이미 있는 키에 값을 다시 넣어도 자리는 그대로라 DEFAULTS 순서로 찍힙니다.
f-string 안의 키는 작은따옴표로 적었습니다. 큰따옴표(`config["open_hour"]`)는 3.12 부터 되고, 3.9 에서는 `SyntaxError: f-string: unmatched '['` 입니다.

**왜 이렇게 푸나**
함수가 둘인 것은 일이 둘이라서입니다. split_setting 은 「한 줄 -> 키와 값」 만 하고, load_config 는 「어느 줄을 쓰고 어느 줄을 경고로 돌릴지」 를 정합니다. 기본값과 숫자 키 목록도 인자로 받아서 다른 가게의 설정 파일도 같은 함수로 읽습니다. 화면 출력은 함수 밖에서 합니다.

검사 순서에도 이유가 있습니다. 「#」 줄을 가장 먼저 거르는 것은 9번 줄 `# notice = 이번 주 휴무 없음` 에도 「=」 가 있어서입니다. 「=」 가 있는지는 split_setting 을 부르기 전에 봐야 7번 줄에서 안 멈춥니다(아래). 숫자 검사는 키를 안 뒤에, NUMBER_KEYS 에 든 키에만 합니다.

★칸이 못 가려내는 풀이: `isdigit()` 대신 3-3 처럼 try/except ValueError 로 int 를 감싸도 칸이 똑같이 나옵니다(직접 돌려 확인). 차이는 다른 값에서 납니다. `"-500".isdigit()` 은 False 인데 `int("-500")` 은 -500 이 됩니다. 배달비에 음수가 적혀 오면 try 쪽은 그대로 받아들입니다.

**틀리면 이렇게 된다**
`.copy()` 를 빼고 `config = defaults` 라고 쓰면 사본이 안 생깁니다. 딕셔너리 하나에 이름이 하나 더 붙을 뿐입니다.

```python
original = {"open_hour": 9}
config = original
config["open_hour"] = 8
print(original)
```
```
{'open_hour': 8}
```

정답에서 이 한 줄만 바꾸면 위 11줄은 그대로이고 마지막 줄만 `DEFAULTS 그대로: open_hour = 8` 로 바뀝니다. 칸의 마지막 줄은 이 실수를 잡으려고 있습니다.

「#」 검사를 빼고 `if line == "":` 만 남기면 설정이 7줄, 경고가 4건이 됩니다. 9번 줄이 `# notice = 이번 주 휴무 없음` 이라는 새 키로 들어가고, 1번 줄은 `1번 줄: = 없음 [# 가게 설정 파일 (사장님이 직접 고침)]` 경고가 됩니다.

확인 없이 `int(value)` 를 바로 하면 4번 줄에서 멈춥니다. 「앱이 멈추지 말고」 라는 요청을 어깁니다.

```python
value = "스물한시"
value = int(value)
```
```
ValueError: invalid literal for int() with base 10: '스물한시'
```

split_setting 을 「=」 검사보다 먼저 부르면 7번 줄에서 `parts[1]` 이 없어 멈춥니다.

```python
key, value = split_setting("배달 가능 지역 강남구 서초구")
```
```
IndexError: list index out of range
```

`no = no + 1` 을 `continue` 뒤로 옮기면 건너뛴 두 줄을 안 세서 경고가 `3번 줄` `5번 줄` `6번 줄` 로 찍힙니다. 에러 없이 줄번호만 틀립니다.
split_setting 에서 strip 을 빼면 키가 `"store_name "` 처럼 공백을 달고 나와 DEFAULTS 의 키를 못 덮어씁니다. 위 여섯 줄은 기본값 그대로(`store_name = 우리 가게`), 뒤에 새 키 5개가 붙고, 경고는 1건으로 줄어듭니다.

**실제로 쓸 때는**
설정 파일은 개발자가 아닌 사람이 메모장으로 고칩니다. 「2만」 「스물한시」 같은 값은 반드시 들어옵니다. 앱이 안 켜지는 것보다 기본값으로 켜고 경고를 남기는 편이 가게에는 낫습니다. 경고에 줄번호와 원래 글자를 같이 남기면 사장님이 그 줄을 바로 찾아 고칩니다.
값 안에 「=」 가 들어가는 설정(주소의 `?page=2` 같은 것)이 오면 `split("=", 1)` 로 처음 「=」 에서 한 번만 나눕니다. DEFAULTS 에 없는 키(오타 `open_hours` 같은 것)도 지금 코드는 조용히 넣으니, 실무에서는 모르는 키도 경고로 남깁니다.

**앞 문제와의 연결**
2-13 처럼 줄번호를 세며 건너뛸 줄은 `continue` 로 넘기고, 2-12 의 `isdigit()` 으로 숫자를 가립니다. 3-2 의 주석 줄 거르기와 3-3 의 「버린 줄은 사유와 함께」 를 설정 파일에 그대로 썼습니다. 새로 나온 것은 `.copy()` 하나입니다.

## [3-7] 일자별 파일 한 번에 합치기

**묻는 것**
폴더 안 파일 이름을 `os.listdir` 로 받아 `.csv` 만 고르고, 파일마다 머리줄을 떼어 한 파일로 합치는 법을 묻습니다. 어느 날 매출인지는 파일 이름에서 꺼냅니다.

**코드 한 줄씩**

```python
def csv_names(folder):
    names = []
    for name in sorted(os.listdir(folder)):
        if name.endswith(".csv"):
            names.append(name)
    return names

def read_rows(path):
    rows = []
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            line = line.strip()
            if no > 1 and line != "":
                rows.append(line)
    return rows

def merge_daily(folder, out_path):
    counts = {}
    total = 0
    with open(out_path, "w", encoding="utf-8") as out:
        out.write("날짜,품목,수량,금액\n")
        for name in csv_names(folder):
            date = name.replace(".csv", "")
            rows = read_rows(folder + "/" + name)
            counts[name] = len(rows)
            for row in rows:
                out.write(f"{date},{row}\n")
                total = total + int(row.split(",")[2])
    return counts, total

counts, total = merge_daily("daily", "daily_all.csv")
```

`os.listdir("daily")` 는 폴더 안 이름만 담은 리스트를 줍니다. 앞에 폴더는 안 붙습니다. `sorted` 로 이름 순서로 늘어놓습니다. 이름이 `2026-11-24` 처럼 자리 수가 같아서 이름 순서가 곧 날짜 순서입니다.
`name.endswith(".csv")` 가 `.csv` 로 끝나는 이름만 남깁니다. `memo.txt` 는 여기서 빠집니다.
read_rows 는 첫 줄(머리줄)과 빈 줄을 뺀 나머지를 원본 그대로 담습니다. 합친 파일에는 앞에 「날짜,」 만 붙이면 되니 칸은 나누지 않습니다. 빈 파일 `2026-11-25.csv` 는 `for` 가 한 번도 안 돌아 `[]`, 곧 「0줄」 입니다.
merge_daily 는 머리줄을 파일을 연 직후, 루프 밖에서 한 번만 씁니다. `name.replace(".csv", "")` 가 이름에서 날짜만 남깁니다.
listdir 이 준 것은 이름뿐이라 열 때는 `folder + "/" + name`(`daily/2026-11-24.csv`)으로 폴더를 붙입니다.
금액은 원본의 셋째 칸(`[2]`)입니다. 쓰는 김에 더해 둡니다. counts 에는 읽은 순서대로 키가 들어가 이름 순서로 찍힙니다.
합친 파일은 `daily/` 가 아니라 `data/` 에 씁니다(아래 「틀리면」). 그 뒤의 출력·다시 읽기 줄은 3-2 와 같은 모양이라 뺐습니다.

**왜 이렇게 푸나**
세 함수가 「어느 파일을」「한 파일에서 무엇을」「어디에 어떻게」 를 하나씩 맡아 따로 불러 확인할 수 있습니다. `csv_names("daily")` 는 `.csv` 세 개, `read_rows("daily/2026-11-25.csv")` 는 `[]` 입니다. 합계가 이상하면 어느 함수에서 틀렸는지 바로 좁혀집니다.
거르는 순서는 파일 이름 먼저(.csv 만), 그다음 파일 안의 줄(머리줄·빈 줄)입니다. 이름에서 걸린 파일은 아예 열지 않습니다.

★칸이 못 가려내는 풀이 두 가지입니다(맥에서 직접 돌려 확인).
- `utf-8-sig` 대신 `utf-8` 로 읽어도 칸이 같습니다. BOM 이 붙는 첫 줄은 머리줄이라 버리기 때문입니다(2-13 과 같은 이유).
- `sorted` 를 빼도 이 맥에서는 칸이 같았습니다. listdir 이 마침 이름 순서로 줬습니다. 그런데 파이썬 문서는 listdir 의 순서를 「정해지지 않은 순서(arbitrary order)」 라고 적습니다. 다른 컴퓨터에서는 날짜가 섞일 수 있으니 빼지 마세요. 윈도우에서 나오는 순서는 직접 확인하지 못했습니다.

**틀리면 이렇게 된다**
endswith 검사를 빼면 이름 순서상 맨 끝의 `memo.txt` 까지 읽습니다. read_rows 는 메모 첫 줄을 머리줄로 여겨 버리고 `26일부터 유자차를 새로 팝니다.` 한 줄을 돌려줍니다. 쉼표가 없으니 셋째 칸이 없습니다.

```python
rows = read_rows("daily/memo.txt")
total = int(rows[0].split(",")[2])
```
```
IndexError: list index out of range
```

정답에서 endswith 줄만 빼고 돌리면 이 에러로 멈추는데, daily_all.csv 에는 이미 9줄이 써져 있고 마지막 줄은 `memo.txt,26일부터 유자차를 새로 팝니다.` 입니다. 멈춘 프로그램도 쓰다 만 파일은 남깁니다.

폴더를 안 붙이고 이름만 넘기면 data 폴더에서 그 이름을 찾습니다. 거기엔 없습니다.

```python
rows = read_rows("2026-11-24.csv")
```
```
FileNotFoundError: [Errno 2] No such file or directory: '2026-11-24.csv'
```

read_rows 에서 `no > 1` 을 빼면 원본 머리줄 `품목,수량,금액` 이 줄로 들어와 금액을 더하다 멈춥니다.

```python
total = int("품목,수량,금액".split(",")[2])
```
```
ValueError: invalid literal for int() with base 10: '금액'
```

머리줄 쓰기(`out.write("날짜,품목,수량,금액\n")`)를 `for name` 안으로 옮기면 파일마다 머리줄이 붙어, 다시 읽은 화면에 `날짜,품목,수량,금액` 이 세 번(빈 파일 몫까지) 나옵니다.

합친 파일을 daily 안에 쓰면 첫 실행부터 자기 파일까지 합칠 대상으로 고릅니다. `"w"` 로 여는 순간 빈 `daily_all.csv` 가 생기고, 그 뒤에 csv_names 가 폴더를 읽기 때문입니다.

```python
counts, total = merge_daily("daily", "daily/daily_all.csv")
print(counts)
```
```
{'2026-11-24.csv': 3, '2026-11-25.csv': 0, '2026-11-26.csv': 4, 'daily_all.csv': 0}
```

지금은 쓰는 중인 파일이 아직 비어 있어 0줄입니다. 하루치를 1,000줄로 늘려 돌려 보니 3.9 에서는 방금 쓴 줄 960개를 도로 읽어 합계가 틀어졌고, 3.14 는 같은 조건에서 0줄이었습니다(파일에 실제로 써지는 때가 버전마다 다릅니다).

**실제로 쓸 때는**
매일 쌓이는 파일(주문·매출·로그)을 월말에 한 파일로 합치는 일은 신입에게 자주 옵니다. 폴더에는 늘 엉뚱한 파일이 섞입니다. 누가 넣은 메모, 맥 Finder 가 만드는 숨은 파일 `.DS_Store` 같은 것입니다. 이름으로 고르는 `endswith(".csv")` 가 이것들을 열기 전에 걸러 줍니다(daily 에 `.DS_Store` 라는 파일을 넣고 돌려도 칸이 같았습니다). 다른 프로그램이 `.CSV` 처럼 대문자로 저장하면 이 검사에서 빠지니(`"2026-11-27.CSV".endswith(".csv")` 는 False), 그런 폴더라면 3-13 처럼 소문자로 바꿔 비교합니다. 결과 파일은 입력 폴더 밖에 씁니다.

**앞 문제와의 연결**
2-15 처럼 원본 머리줄은 버리고 새 파일에 머리줄을 한 번만 씁니다. 2-16 에서 `os.path.exists` 로 파일 하나가 있는지 봤다면, 이번에는 `os.listdir` 로 폴더 안 이름을 한꺼번에 받습니다. 3-13 에서 파일 이름을 다시 다룹니다.

## [3-8] 연체 보고서

**묻는 것**
대출 기록에서 기한을 넘긴 날 수를 계산해 회원별로 더하고, 많이 밀린 회원부터 보고서 파일에 쓰는 법을 묻습니다. 「열흘」 처럼 글자로 적힌 일수는 사전으로 바꾸고, 못 읽는 줄은 줄번호만 모아 둡니다.

**코드 한 줄씩**

```python
def to_days(text):
    text = text.strip()
    if text.isdigit():
        return int(text)
    return WORD_DAYS.get(text, -1)

def overdue_days(days, renewals):
    late = days - (14 + renewals * 7)
    if late > 0:
        return late
    return 0

def sum_overdue(path):
    totals = {}
    count = 0
    unknown = []
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            line = line.strip()
            if no == 1 or line == "":
                continue
            parts = line.split(",")
            if len(parts) != 4 or to_days(parts[2]) == -1:
                unknown.append(no)
                continue
            late = overdue_days(to_days(parts[2]), int(parts[3]))
            if late > 0:
                email = parts[1].strip().lower()
                totals[email] = totals.get(email, 0) + late
                count = count + 1
    return totals, count, unknown

def write_report(path, totals, count, unknown):
    pairs = []
    for email in totals:
        pairs.append((totals[email], email))
    rank = 0
    with open(path, "w", encoding="utf-8") as f:
        f.write(f"연체 {count}건 / 회원 {len(totals)}명 / 확인 필요 줄 {unknown}\n")
        for pair in sorted(pairs, reverse=True):
            rank = rank + 1
            f.write(f"{rank}위 {pair[0]:>2}일 {pair[0] * 100:>5,}원  {pair[1]}\n")
    return rank + 1
```

to_days 는 숫자면 정수로, 아니면 WORD_DAYS 에서 찾습니다. `.get(text, -1)` 은 사전에 없으면 -1 을 줍니다. 일수는 0 이상이라 -1 을 「못 읽음」 표시로 씁니다. `한 달` 이 -1 입니다.
overdue_days 의 괄호가 기한 전체(14 + 연장횟수 x 7)를 묶습니다. 기한 안이면 뺀 값이 0 이하라 0 을 돌려줍니다.
sum_overdue 의 `or` 는 왼쪽이 True 면 오른쪽을 안 봅니다. 칸이 4개일 때만 `parts[2]` 를 읽습니다. 13번 줄(칸 3개)과 11번 줄(`한 달`)은 unknown 에 줄번호만 들어갑니다.
연체된 대출(`late > 0`)만 회원별 합에 더하고 건수를 셉니다. 안 밀린 회원은 totals 에 아예 안 들어가서 보고서에 없습니다. `totals.get(email, 0) + late` 는 3-1 에서 건수를 셀 때 쓴 모양입니다.
write_report 는 (연체일, 메일) 튜플을 거꾸로 정렬해 연체일이 많은 순서로 씁니다(2-9). `{unknown}` 은 리스트를 그대로 찍어 `[11, 13]` 이 됩니다.
`:>2` 는 2칸, `:>5,` 는 쉼표를 넣고 5칸 오른쪽 맞춤입니다. `4일` 앞에 공백 하나, `400원` 앞에 공백 둘이 붙습니다. 돌려주는 `rank + 1` 은 회원 줄 수에 요약 한 줄을 더한 값입니다. 부르는 줄과 다시 읽어 찍는 줄은 3-7 과 같은 모양이라 뺐습니다.

**왜 이렇게 푸나**
계산(to_days·overdue_days), 집계(sum_overdue), 쓰기(write_report)를 나눴습니다. 계산 함수는 파일 없이 값만 넣어 확인합니다. `overdue_days(40, 2)` 는 기한 28일을 넘긴 12 입니다. 연체료가 하루 200원으로 바뀌면 write_report 한 줄만 고칩니다.
sum_overdue 의 검사 순서는 머리줄·빈 줄 -> 칸 수 -> 일수 -> 연체 계산 -> 메일 정리 입니다. 칸 수를 먼저 봐야 `parts[3]` 을 안전하게 꺼냅니다. 같은 사람이 ` KIM.Haneul@Example.COM ` 과 `kim.haneul@example.com` 처럼 다르게 적혀 있어서, 정리한 메일로 묶어야 한 사람이 됩니다.

★칸이 못 가려내는 풀이: overdue_days 안의 `if late > 0:` 을 `>=` 로 바꿔도 칸이 같습니다(직접 돌려 확인). late 가 0 일 때 late 를 돌려주나 0 을 돌려주나 같은 0 이라서입니다. sum_overdue 안의 `if late > 0:` 은 바꾸면 칸이 달라집니다(아래).

**틀리면 이렇게 된다**

## [3-9] 열람실 날짜별 방문 요약

**묻는 것**
방문 기록에서 쓸 수 있는 줄만 골라 튜플로 바꾸고, 같은 날 같은 사람은 한 번만 세서 날짜별 명수와 머문 시간을 내는 법을 묻습니다. 분을 「X시간 Y분」 으로 바꾸는 함수도 씁니다.

**코드 한 줄씩**

```python
def time_text(minutes):
    if minutes < 60:
        return f"{minutes}분"
    return f"{minutes // 60}시간 {minutes % 60}분"

def load_visits(path):
    visits = []
    dropped = 0
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            if no == 1:
                continue
            parts = line.strip().split(",")
            if len(parts) == 3 and parts[2].strip().isdigit():
                visits.append((parts[0].strip(), parts[1].strip().lower(), int(parts[2])))
            else:
                dropped = dropped + 1
    return visits, dropped

def by_date(visits):
    counts = {}
    minutes = {}
    seen = []
    dupes = 0
    for date, email, stay in visits:
        if (date, email) in seen:
            dupes = dupes + 1
            continue
        seen.append((date, email))
        counts[date] = counts.get(date, 0) + 1
        minutes[date] = minutes.get(date, 0) + stay
    return counts, minutes, dupes

visits, dropped = load_visits("visits.csv")
counts, minutes, dupes = by_date(visits)
people = 0
total = 0
for date in counts:
    print(f"{date}  {counts[date]}명  {time_text(minutes[date])}")
    people = people + counts[date]
    total = total + minutes[date]
print(f"합계 {people}명  {time_text(total)}")
print(f"뺀 줄 {dropped}줄 / 겹친 기록 {dupes}줄")
```

time_text 는 60분 미만이면 분만, 그 이상이면 `//` 로 시간, `%` 로 남은 분을 냅니다(1-1). 60분은 `1시간 0분` 입니다.
load_visits 는 머리줄을 `continue` 로 넘겨 뺀 줄로 세지 않습니다. 칸이 3개이고 셋째 칸이 숫자인 줄만 (날짜, 메일, 분) 튜플로 담고, 메일은 이때 정리합니다.
빠지는 줄은 4번(빈 값), 7번(`사십`), 9번(빈 줄), 12번(칸 2개) 넷입니다. 11번 `minjae.example.com` 은 @ 가 없지만 규칙대로 살립니다.
`int()` 는 앞뒤 공백이 있어도 바꿔 줍니다(`int(" 35 ")` 는 35). 그래서 strip 은 isdigit 검사 쪽에만 붙였습니다.
by_date 의 `for date, email, stay in visits` 는 튜플 세 칸을 세 변수로 나눠 받습니다.
seen 에는 (날짜, 메일) 짝을 담습니다. 짝이 이미 있으면 겹친 기록으로 세고 넘깁니다. 6번 줄 `park.daeun@example.com` 이 2번 줄과 날짜·메일이 같아 여기서 걸립니다.
두 딕셔너리는 처음 나온 날짜 순서로 키가 생깁니다. time_text 는 날짜 줄과 합계 줄(195분 -> `3시간 15분`)에서 두 번 부릅니다.

**왜 이렇게 푸나**
load_visits 는 「쓸 수 있는 줄인가」 만, by_date 는 「무엇을 한 번으로 칠까」 만 정합니다. 겹친 기록 규칙이 바뀌어도 by_date 만 고치면 됩니다. time_text 는 두 군데서 써서 따로 뗐습니다.
순서가 중요한 곳은 「메일 정리 -> 겹침 검사」 입니다. 2번 줄 ` PARK.Daeun@Example.com ` 과 6번 줄 `park.daeun@example.com` 은 정리한 뒤에야 같은 메일이 됩니다. 그래서 정리는 읽을 때(load_visits) 끝내고, by_date 는 정리된 값만 받습니다.

★칸이 못 가려내는 풀이 두 가지입니다(직접 돌려 확인).
- 날짜 없이 메일만 seen 에 담아 겹침을 봐도 칸이 같습니다. 이 파일에는 같은 사람이 다른 날 온 기록이 없어서입니다. 다음 날 또 온 사람이 있으면 그 방문까지 겹친 기록으로 지워 버립니다.
- `for date in sorted(counts):` 로 날짜를 정렬해도 칸이 같습니다. 처음 나온 순서가 마침 날짜 순서라서입니다. 규칙은 「처음 나온 순서」 입니다.

**틀리면 이렇게 된다**
메일을 소문자로 바꾸지 않으면 2번 줄과 6번 줄이 다른 사람이 되어 11-01 이 3명이 됩니다. strip 을 빼고 lower 만 해도, 겹침 검사를 통째로 빼도 화면이 똑같이 이렇게 나옵니다.

```
2026-11-01  3명  1시간 22분
2026-11-02  1명  20분
2026-11-03  1명  45분
2026-11-04  2명  23분
2026-11-05  1명  1시간 0분
합계 8명  3시간 50분
뺀 줄 4줄 / 겹친 기록 0줄
```

time_text 의 `<` 를 `<=` 로 쓰면 다섯째 줄만 `2026-11-05  1명  60분` 으로 바뀝니다. 에러가 없어서 칸과 맞춰 봐야 보입니다.
머리줄 `continue` 를 빼면 머리줄의 셋째 칸 `머문분` 이 숫자가 아니라서 `뺀 줄 5줄` 이 됩니다. 「머리줄은 뺀 줄로 세지 않습니다」 를 어깁니다.

`and` 양쪽을 바꿔 셋째 칸부터 보면 9번 빈 줄에서 멈춥니다(2-13 과 같습니다).

```python
parts = "".split(",")
if parts[2].strip().isdigit() and len(parts) == 3:
    print("살림")
```
```
IndexError: list index out of range
```

**실제로 쓸 때는**
출입 기록은 카드를 두 번 대거나 나갔다 바로 들어오면 두 번 남는 일이 있습니다. 그대로 세면 이용자 수가 부풀어 운영 보고가 틀립니다. 메일도 사람이 입력한 것이라 대소문자와 공백이 제각각입니다. 「뺀 줄 4줄 / 겹친 기록 1줄」 처럼 뺀 것을 숫자로 같이 보여 주면 받는 사람이 결과를 믿고 씁니다.

**앞 문제와의 연결**
2-13 에서 같은 visits.csv 의 더러운 줄을 골랐습니다. 그때는 「사십」 줄을 살렸지만, 이번에는 분을 더해야 해서 isdigit 로 뺍니다. 2-19 의 「이미 있으면 안 넣기」 를 (날짜, 메일) 짝으로 했고, 3-3 의 seen 목록과 같은 모양입니다. 3-20 에서 visits.csv 를 회원·대출과 함께 다시 씁니다.

## [3-10] 게시판 페이지 나누기

**묻는 것**
「|」 로 나뉜 글 목록에서 공지와 공개 글만 골라 최신순으로 늘어놓고, 한 쪽에 4개씩 잘라 보여 주는 법을 묻습니다. 없는 쪽 번호가 들어와도 멈추지 않게 합니다.

**코드 한 줄씩**

```python
import math

def load_posts(path):
    notice = ""
    posts = []
    with open(path, encoding="utf-8") as f:
        for line in f:
            parts = line.strip().split("|")
            if len(parts) != 4:
                continue
            if parts[3] == "공지":
                notice = parts[2]
            elif parts[3] == "공개":
                posts.append((parts[1], int(parts[0]), parts[2]))
    return notice, sorted(posts, reverse=True)

def page_count(posts, size):
    return math.ceil(len(posts) / size)

def show_page(notice, posts, page, size):
    total = page_count(posts, size)
    if page < 1 or page > total:
        print(f"[{page}쪽] 없는 쪽입니다 (전체 {total}쪽)")
    else:
        print(f"[{page}/{total}쪽] 글 {len(posts)}개")
        print(f"  [공지] {notice}")
        start = (page - 1) * size
        for date, no, title in posts[start:start + size]:
            print(f"  {no:>3}  {date}  {title}")

notice, posts = load_posts("posts.txt")
for page in [1, 3, 4, 0]:
    show_page(notice, posts, page, 4)
```

load_posts 는 칸이 4개가 아닌 줄(끝의 빈 줄)을 건너뜁니다. 구분이 「공지」 면 제목을 notice 에 두고, 「공개」 면 (날짜, 번호, 제목) 튜플로 담습니다. 「비공개」 는 어느 쪽에도 안 걸려 빠집니다.
첫 줄 `번호|날짜|제목|구분` 도 칸이 4개지만 구분 칸이 「구분」 이라 그냥 지나갑니다. 머리줄을 따로 안 걸러도 되는 이유입니다.
번호는 정렬할 때 숫자로 비교하려고 `int` 로 바꿔 담습니다.
`sorted(posts, reverse=True)` 는 튜플을 첫 칸(날짜)부터 비교해 늦은 날짜를 앞에 둡니다. 날짜가 같으면 둘째 칸(번호)이 큰 글이 앞입니다(2-9). 날짜는 자리 수가 같아 글자로 비교해도 날짜 순서와 같습니다.
page_count 는 글 10개를 4개씩 나눈 2.5 를 `math.ceil` 로 올려 3쪽으로 만듭니다(1-19).
show_page 는 쪽 번호부터 검사하고, 범위 밖이면 한 줄만 찍고 끝납니다. 1쪽은 0번째부터, 3쪽은 8번째부터 4개입니다.
3쪽은 글이 2개뿐인데 `posts[8:12]` 는 있는 데까지만 잘라 줍니다. 끝이 넘쳐도 멈추지 않는 것은 1-5 의 문자열 자르기와 같습니다. `{no:>3}` 은 번호를 3칸 오른쪽 맞춤으로 찍습니다.

**왜 이렇게 푸나**
load_posts 가 한 번 읽어 거르고 정렬해 두면, show_page 는 자르기만 합니다. 쪽을 넘길 때마다 파일을 다시 읽거나 다시 정렬하지 않습니다. 쪽 수 계산은 show_page 말고도(쪽 번호 단추 같은 곳) 쓰는 값이라 page_count 로 뗐습니다.
load_posts 의 검사 순서는 칸 수 -> 구분 -> int 입니다. int 는 「공개」 갈래 안에서만 합니다. 머리줄의 `번호` 는 int 로 못 바꾸는데, 구분에서 이미 걸러져 int 까지 안 옵니다.
show_page 는 쪽 번호가 맞는지 먼저 보고 나서 자릅니다. 0쪽을 검사 없이 자르면 에러 없이 엉뚱한 화면이 나옵니다(아래).

★칸이 못 가려내는 풀이 두 가지입니다(직접 돌려 확인).
- `len(posts) // size + 1` 도 이 데이터에서는 3쪽이라 칸이 같습니다. 10 이 4 로 나누어떨어지지 않아서입니다. 글이 8개면 갈립니다.

```python
print(8 // 4 + 1, math.ceil(8 / 4))
```

## [3-11] 가입 입력 검증기

**묻는 것**
틀린 값을 맞을 때까지 다시 묻는 while 을 칸마다 함수 하나에 넣는 것입니다. 메일은 「@ 가 있나 -> 이미 있나」, 포인트는 「정수인가 -> 0 이상인가」 를 정해진 순서로 봅니다. 「이미 있나」 는 파일의 메일과 이번에 받은 메일을 한 목록에서 찾습니다.

**코드 한 줄씩**

```python
def load_emails(path):
    emails = []
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            parts = line.split(",")
            if no > 1 and len(parts) >= 2:
                emails.append(parts[1].strip().lower())
    return emails
```

머리줄(`no` 가 1)은 건너뛰고, 쉼표가 없는 빈 줄은 `len(parts) >= 2` 에서 빠집니다. 메일 칸만 쓰니 칸이 3개인 강태윤 줄도 담습니다. `.strip().lower()` 로 「 KIM.Haneul@Example.COM 」 이 `kim.haneul@example.com` 이 됩니다. 입력 쪽과 같은 모양이어야 `in` 비교가 맞습니다.

```python
def ask_email(emails):
    while True:
        email = input("메일: ").strip().lower()
        if "@" not in email:
            print("  다시 입력: 메일 모양이 아닙니다")
        elif email in emails:
            print("  다시 입력: 이미 가입한 메일입니다")
        else:
            return email

def ask_point():
    while True:
        text = input("포인트: ")
        try:
            point = int(text)
        except ValueError:
            print("  다시 입력: 포인트는 숫자로 적어 주세요")
            continue
        if point < 0:
            print("  다시 입력: 포인트는 0 이상이어야 합니다")
        else:
            return point
```

`while True:` 안의 `return` 이 통과한 값을 돌려주며 되풀이와 함수를 같이 끝냅니다(2-10). 거절 갈래에는 return 이 없어 다시 묻습니다.
`if` 다음이 `elif` 라 @ 가 없으면 중복은 보지 않습니다. 규칙의 검사 순서 그대로입니다. `int("백")` 은 ValueError 라 except 로 가고(3-3), `continue` 가 그 바퀴를 끝내 다시 묻습니다. int 는 앞뒤 공백을 스스로 떼서 포인트에는 strip 을 안 붙였습니다.

```python
def save_members(path, rows):
    with open(path, "w", encoding="utf-8") as f:
        f.write("이름,메일,포인트\n")
        for row in rows:
            f.write(row + "\n")

emails = load_emails("members.csv")
rows = []
while True:
    name = input("이름(빈 줄이면 끝): ").strip()
    if name == "":
        break
    email = ask_email(emails)
    point = ask_point()
    emails.append(email)
    rows.append(f"{name},{email},{point}")
save_members("new_members.csv", rows)
print(f"새 회원 {len(rows)}명 -> new_members.csv")
with open("new_members.csv", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```

`emails.append(email)` 이 이번에 받은 메일을 목록에 더합니다. 그래서 이영희의 `gildong@example.com` 이 「이미 가입한 메일」 로 걸립니다.
바깥 while 은 사람마다 한 바퀴이고, 이름이 빈 줄이면 break 해서 저장합니다. members.csv 는 읽기만 합니다(요청).
화면은 문제 칸과 같습니다(값을 치고 Enter, 맥은 return). `메일:  Kim.Haneul@EXAMPLE.com` 의 콜론 뒤 공백 둘은 안내문 공백에 직접 친 공백이 더해진 것입니다.

**왜 이렇게 푸나**
메일이 틀렸다고 이름부터 다시 묻지 않습니다. 그래서 칸마다 묻는 함수(ask_email · ask_point)를 두고, while 이 그 칸 안에서만 돌다가 통과한 값 하나만 돌려주게 했습니다. 바깥 while 은 「다음 사람」 만 맡습니다. 파일 읽기 · 쓰기도 따로 둬서, 입력이 웹 폼으로 바뀌어도 그대로 씁니다.
ask_email 이 목록을 받는 것은 중복 기준이 「파일 + 이번 입력」 이어서입니다. 한 목록에 모으면 검사는 `email in emails` 한 줄입니다.
@ 가 없으면 메일이 아니니 모양 검사가 먼저입니다. 순서를 바꿔도 칸의 12개 입력으로는 화면이 같아 칸으로는 알 수 없습니다. members.csv 에 있는 `seoyeon.example.com`(@ 없음)을 쳐 보면 갈립니다. 정답은 「메일 모양이 아닙니다」, 바꾼 코드는 「이미 가입한 메일입니다」 입니다.

**틀리면 이렇게 된다**
load_emails 에서 `.strip().lower()` 를 빼면 파일 쪽 메일이 그대로 남아 둘째 메일이 통과합니다. 칸과 같은 12개를 차례로 치면 그 자리가 이렇게 됩니다.

```
메일:  Kim.Haneul@EXAMPLE.com
포인트: Gildong@Example.com
  다시 입력: 포인트는 숫자로 적어 주세요
```

입력이 한 칸씩 밀려 저장된 첫 회원은 `홍길동,kim.haneul@example.com,300` 입니다. 이미 있는 김하늘 메일로 새 회원이 생겼습니다. 입력 쪽 `.strip()` 만 빼도 같은 자리에서 통과하고, 저장 줄에 `홍길동, kim.haneul@example.com,300` 처럼 공백이 남습니다.

`emails.append(email)` 을 빼면 이영희의 `gildong@example.com` 이 통과합니다. 뒤에 친 `younghee@example.com` 은 포인트 자리에서 거절되고, 파일 끝 두 줄이 `홍길동,gildong@example.com,300` · `이영희,gildong@example.com,0` 으로 같은 메일이 됩니다.

except 아래 `continue` 를 빼면 `포인트: 백` 의 거절 줄 다음에 `UnboundLocalError` 로 멈춥니다. `point` 를 못 만든 채 아래 `if point < 0:` 으로 내려가서입니다. `point <= 0` 으로 쓰면 이영희의 0 을 거절하고, 끝내려고 친 엔터가 포인트 자리로 들어가 포인트를 계속 묻습니다. try 없이 바로 바꾸면 첫 포인트에서 멈춥니다.

```python
point = int(input("포인트: "))
```
```
ValueError: invalid literal for int() with base 10: '백'
```

**실제로 쓸 때는**
회원가입 · 예약 폼이 이 모양입니다. 칸마다 검사해 무엇이 틀렸는지 알리고 그 칸만 다시 받습니다. 받은 회원은 원래 명단에 바로 쓰지 않고 새 파일에 둡니다. 원본을 덮은 뒤 잘못된 줄이 섞이면 되돌리기 어렵습니다.

**앞 문제와의 연결**
2-10 의 while 안 return 으로 「통과하면 끝, 아니면 다시」 를 만들고, 2-4 의 메일 정리와 `in` 검사, 3-3 의 try/except 를 입력 쪽에 썼습니다. 바깥 되풀이는 1-14 의 `while True` + `break`, 저장은 2-14 입니다. 3-12 는 틀리면 다시 묻지 않고 그 건만 버리는 콘솔입니다.

## [3-12] 재고 출고 콘솔

**묻는 것**
「끝」 이 나올 때까지 명령을 받는 콘솔에서, 한 건을 검사하고 처리하는 일을 ship 하나에 모으는 것입니다. ship 은 결과 한 줄을 돌려주고, 출고가 되면 받은 딕셔너리의 개수를 그 자리에서 줄입니다. 없는 품목이면 수량을 묻지 않는 입력 순서도 묻습니다.

**코드 한 줄씩**

```python
def load_stock(path):
    stock = {}
    safety = {}
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            parts = line.strip().split(",")
            if no == 1 or len(parts) != 3:
                continue
            stock[parts[0]] = int(parts[1])
            safety[parts[0]] = int(parts[2])
    return stock, safety
```

딕셔너리 두 개를 같은 키(품목)로 채워 둘 다 돌려줍니다(2-6). 머리줄과 칸이 3개가 아닌 줄은 건너뜁니다(2-13).

```python
def ship(stock, safety, item, text):
    try:
        count = int(text)
    except ValueError:
        count = 0
    if count < 1:
        return f"수량은 1 이상의 정수로: {text.strip()}"
    if count > stock[item]:
        return f"재고 부족: {item} 남은 {stock[item]}개"
    stock[item] = stock[item] - count
    message = f"출고: {item} {count}개, 남은 {stock[item]}개"
    if stock[item] < safety[item]:
        message = message + f" (안전재고 {safety[item]}개 미만)"
    return message
```

글자면 except 에서 `count` 를 0 으로 둡니다. 그러면 「열」 과 「0」 이 `count < 1` 한 갈래에서 같은 문장으로 걸립니다.
검사 두 개는 규칙 순서대로이고, 걸리면 return 으로 끝나 개수를 빼지 않습니다.
`stock[item] = stock[item] - count` 는 함수 밖의 stock 을 바꿉니다. 딕셔너리는 함수에 넘겨도 같은 것 하나입니다. 3-6 에서 `.copy()` 가 필요했던 까닭과 같습니다. 경고는 `<` 라서, 남은 10개가 안전재고 10개와 같은 A4 용지에는 안 붙습니다.

```python
def save_stock(path, stock, safety):
    with open(path, "w", encoding="utf-8") as f:
        f.write("품목,재고,안전재고\n")
        for item in stock:
            f.write(f"{item},{stock[item]},{safety[item]}\n")

stock, safety = load_stock("stock.csv")
while True:
    item = input("품목: ").strip()
    if item == "끝":
        break
    if item not in stock:
        print(f"  없는 품목입니다: {item}")
        continue
    print("  " + ship(stock, safety, item, input("수량: ")))
save_stock("stock_after.csv", stock, safety)
print("stock_after.csv 에 저장했습니다")
with open("stock_after.csv", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```

「끝」 검사가 맨 앞, 없는 품목 검사가 그다음입니다. `input("수량: ")` 이 ship 을 부르는 줄 안에 있어서 있는 품목일 때만 수량을 묻습니다.
결과 줄 앞 두 칸은 부르는 쪽에서 붙입니다. save_stock 은 stock 에 넣은 순서(파일 순서)대로 씁니다. 화면은 문제 칸과 같고, `품목:  클립` 의 앞 공백은 `.strip()` 이 뗍니다.

**왜 이렇게 푸나**
ship 은 출고 한 건을 판정해 결과를 글자로 돌려줄 뿐, 화면에 찍지도 키보드에서 받지도 않습니다. 그래서 `ship(stock, safety, "볼펜", "25")` 처럼 입력 없이 불러 시험할 수 있고, 결과를 로그 파일에 쓸 때도 그대로 씁니다. 읽기 · 한 건 처리 · 쓰기 · 콘솔이 각각 한 가지 일만 합니다.
「정수인가」 가 먼저인 것은 숫자가 아니면 재고와 견줄 수도 없어서입니다. 3-11 과 달리 다시 묻지 않고 다음 품목을 묻습니다. 잘못 친 출고를 다시 칠지 넘어갈지는 사람이 정합니다.

**틀리면 이렇게 된다**
경고 비교를 `<=` 로 쓰면 A4 용지 줄에 경고가 붙습니다. 남은 10개가 「10개 미만」 이라는 틀린 문장입니다.

```
  출고: A4 용지 30개, 남은 10개 (안전재고 10개 미만)
```

`count < 1` 검사를 빼면 「열」 과 「0」 이 `출고: 포스트잇 0개, 남은 15개` 처럼 0개 출고로 처리됩니다. 저장 파일은 같아도 화면에는 하지도 않은 출고가 찍힙니다.

품목을 확인하기 전에 `input("수량: ")` 부터 받으면 없는 품목에도 수량을 묻습니다. 칸과 같은 16개를 차례로 치면 입력이 한 칸씩 밀리고, 「끝」 도 수량 자리로 들어가 콘솔이 끝나지 않습니다.

```
품목: 연필
수량: A4 용지
  없는 품목입니다: 연필
품목: 50
```

없는 품목 검사를 아예 빼면 ship 이 없는 키를 꺼내다 멈춥니다.

```python
print(ship(stock, safety, "연필", "3"))
```
```
KeyError: '연필'
```

ship 은 「있는 품목만 온다」 고 믿고 짠 함수라, 그 약속은 부르는 쪽이 `item not in stock` 으로 지킵니다.

**실제로 쓸 때는**
창고 출고, 매장 재고 차감이 이 모양입니다. 한 건 처리 함수를 따로 두면 콘솔에서도, 바코드 스캐너에서도, 하루치 출고 파일을 한꺼번에 돌릴 때도 같은 함수를 씁니다. 「미만」 과 「이하」 처럼 경계가 갈리는 규칙은 명세대로 쓰고, 안 적혀 있으면 요청한 사람에게 물어 정합니다.

**앞 문제와의 연결**
2-11 의 「결제」 칠 때까지 받아 딕셔너리에 담기를 뼈대로, 3-3 의 try 와 2-6 의 두 값 돌려주기를 더했습니다. 3-11 과 같은 콘솔이지만 다시 묻지 않습니다. 3-13 부터는 키보드 입력 없이 파일만 다룹니다.

## [3-13] 사진 파일 이름 정리 계획

**묻는 것**
파일 이름 글자에서 날짜와 확장자를 뽑고, 이미 정한 이름과 겹치면 번호를 올려 가며 빈 이름을 찾는 것입니다. 몇 번 올릴지 모르니 while 을 씁니다. 새 도구는 맨 끝 칸 `리스트[-1]` 입니다.

**코드 한 줄씩**

```python
def find_date(name):
    digits = ""
    for ch in name:
        if ch.isdigit():
            digits = digits + ch
    return digits[:4] + "-" + digits[4:6] + "-" + digits[6:8]
```

숫자만 모으는 뼈대는 3-4 의 format_phone 과 같습니다. `IMG_20260503_142233.jpg` 는 `20260503142233`, `2026-05-03 18.02.11.jpg` 는 `20260503180211` 이 됩니다.
날짜보다 앞에 숫자가 없으니(규칙) 앞 8자리가 늘 날짜입니다. 4 · 2 · 2 자리로 잘라 `-` 로 잇습니다.

```python
def new_name(old, plan):
    ext = old.split(".")[-1].lower()
    date = find_date(old)
    name = f"{date}.{ext}"
    number = 1
    while name in plan:
        number = number + 1
        name = f"{date}_{number}.{ext}"
    return name
```

`[-1]` 은 맨 끝 칸입니다. `2026-05-03 18.02.11.jpg` 를 `.` 로 자르면 `['2026-05-03 18', '02', '11', 'jpg']` 입니다. 앞에서 세면 이름마다 자리가 다르고, 뒤에서 세면 늘 확장자입니다. `.lower()` 가 JPG 를 jpg 로 바꿉니다.
처음 이름이 plan 에 없으면 while 은 한 번도 안 돌고 번호 없는 이름이 나갑니다. 있으면 `_2`, `_3` 으로 올리며 빈 이름이 나올 때까지 돕니다.

```python
def make_plan(path):
    plan = {}
    with open(path, encoding="utf-8") as f:
        for line in f:
            old = line.strip()
            if old != "":
                new = new_name(old, plan)
                plan[new] = old
    return plan

plan = make_plan("photo_list.txt")
with open("rename_plan.txt", "w", encoding="utf-8") as f:
    for new in plan:
        f.write(f"{plan[new]} -> {new}\n")
print(f"계획 {len(plan)}건 -> rename_plan.txt")
with open("rename_plan.txt", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```

`plan[new] = old` 로 새 이름을 키로 둡니다. 그래서 new_name 의 `name in plan` 이 「이미 정한 새 이름인가」 를 묻게 됩니다.
빈 줄은 `old != ""` 에서 빠집니다. for 는 넣은 순서대로 꺼내니 rename_plan.txt 도 파일 순서입니다.

**왜 이렇게 푸나**
요청이 「바꿀 계획만 먼저」 입니다. 이 코드는 사진 이름을 하나도 바꾸지 않고 계획 파일만 씁니다. 이름 바꾸기는 잘못되면 되돌리기 어려워서, 계획을 사람이 본 뒤에 바꿉니다.
find_date(이름 -> 날짜), new_name(이름 + 지금까지의 계획 -> 새 이름), make_plan(파일 -> 계획) 으로 나눴습니다. 다른 폰의 이름 모양이 들어오면 find_date 만, 번호 규칙이 바뀌면 new_name 만 고칩니다. 겹침은 앞에서 정한 이름들과의 관계라, new_name 은 plan 을 인자로 받아야 판정할 수 있습니다.
확장자를 `old[-3:]` 로 잘라도 이 목록은 jpg · png · JPG 뿐이라 칸과 같습니다. 칸으로는 알 수 없는 자리입니다. 네 글자 확장자면 갈립니다. `"IMG_20260506_101010.heic"[-3:]` 은 `eic`, `.split(".")[-1]` 은 `heic` 입니다.

**틀리면 이렇게 된다**
확장자를 `split(".")[1]` 로 꺼내면 점이 여러 개인 이름에서 틀립니다.

```
2026-05-03 18.02.11.jpg -> 2026-05-03.02
2026-05-05 12.00.01.jpg -> 2026-05-05.00
IMG_20260505_120000.JPG -> 2026-05-05.jpg
```

점이 하나인 이름은 맞게 나와서 위쪽 줄만 보면 놓칩니다. `2026-05-05.00` 은 `.jpg` 와 다른 이름이라, 셋째 줄 JPG 사진이 번호 없는 `2026-05-05.jpg` 를 가져갑니다.

`.lower()` 를 빼면 `IMG_20260505_120000.JPG -> 2026-05-05.JPG` 로 대문자가 남고, 다음 사진은 `2026-05-05_2.jpg` 가 됩니다. 두 이름은 글자가 달라 겹침 검사를 지나갑니다. 그런데 맥 기본 설정의 디스크는 `x.JPG` 가 있으면 `x.jpg` 도 있다고 답합니다. 계획대로 바꾸면 두 이름이 한 자리를 두고 부딪칩니다.

빈 줄을 안 거르면 빈 이름에도 계획이 생겨 10건이 되고, 이런 줄이 섞입니다.

```
-> --.
```

`number = number + 1` 을 빼면 같은 날 둘째 사진은 `_1` 을 받고, 셋째 사진에서 while 이 끝나지 않습니다. 아무것도 안 찍히고 멈춘 것처럼 보이면 Ctrl+C(맥도 control+C)로 끊으세요.

확장자 자리를 앞에서 세면 에러로 멈춥니다. 점이 셋인 이름을 보고 넷째 칸을 고르면, 점이 하나인 첫 줄에서 멈춥니다.

```python
old = "IMG_20260503_142233.jpg"
ext = old.split(".")[3]
```
```
IndexError: list index out of range
```

**실제로 쓸 때는**
사진 정리, 내려받은 첨부 정리, 백업 파일 이름 맞추기에 이 모양이 나옵니다. 파일을 직접 고치는 스크립트는 「계획 뽑기 -> 확인 -> 실행」 으로 나눠 짭니다. 규칙에 안 맞는 이름도 생각해 두세요. `IMG2_20260503.jpg` 처럼 날짜 앞에 숫자가 있으면 find_date 가 `2202-60-50` 을 돌려줍니다. 이런 이름은 계획에 넣지 말고 확인 목록으로 따로 빼는 것이 다음 할 일입니다.

**앞 문제와의 연결**
3-4 의 「숫자만 모으기」(2-12 의 isdigit), 1-13 의 `while 조건:`, 1-16 의 딕셔너리 키 `in` 을 엮었습니다. 3-5 는 이미 있는 제목을 찾아 건너뛰었고, 여기서는 겹치는 이름을 번호로 비켜 갑니다.

## [3-14] 반납 안내문 채우기

**묻는 것**
`f.read()` 로 문구 파일을 통째로 읽어 `{이름}` · `{도서}` 자리를 replace 로 채우는 것입니다. 두 파일을 메일로 잇고({메일: 이름} 딕셔너리), 같은 대출 줄을 (도서, 메일) 짝으로 한 번만 쓰는 것도 묻습니다.

**코드 한 줄씩**

```python
def load_names(path):
    names = {}
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            parts = line.strip().split(",")
            if no > 1 and len(parts) == 4:
                names[parts[1].strip().lower()] = parts[0].strip()
    return names

def fill(template, name, book):
    return template.replace("{이름}", name).replace("{도서}", book)
```

메일을 키, 이름을 값으로 담습니다. 칸이 3개인 강태윤 줄과 빈 줄은 빠집니다. 최민재는 두 줄이 같은 키라 하나로 겹쳐집니다. fill 은 replace 를 두 번 잇습니다(1-6). 문구 속 `{이름}` 은 f-string 이 아니라 그냥 글자라서 replace 로 찾습니다.

```python
def make_notices(template, names, path):
    notices = []
    seen = []
    unknown = 0
    dupes = 0
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            parts = line.strip().split(",")
            if no == 1 or len(parts) != 4:
                continue
            book = parts[0].strip()
            email = parts[1].strip().lower()
            if (book, email) in seen:
                dupes = dupes + 1
                continue
            seen.append((book, email))
            if email in names:
                notices.append(fill(template, names[email], book))
            else:
                notices.append(fill(template, "회원", book))
                unknown = unknown + 1
    return notices, unknown, dupes
```

메일은 정리한 뒤 비교합니다. 그래서 `파이썬 입문, JUNSEO@example.com` 줄이 앞의 이준서 줄과 같은 짝이 되어 겹친 줄로 셉니다.
`seen` 에는 (도서, 메일) 튜플을 쌓습니다. 3-9 의 (날짜, 메일) 과 같은 모양입니다.
명단에 없는 `haru@example.com` 은 이름 자리에 「회원」 을 넣고 따로 셉니다. 대출일수는 안 보니 「보름」 「한 달」 줄에도 안내문이 나갑니다.

```python
with open("notice_template.txt", encoding="utf-8") as f:
    template = f.read().strip()
names = load_names("members.csv")
notices, unknown, dupes = make_notices(template, names, "loans_nov.csv")
with open("notices.txt", "w", encoding="utf-8") as f:
    for notice in notices:
        f.write(notice + "\n")
print(f"안내문 {len(notices)}통 -> notices.txt (명단에 없는 메일 {unknown}통 · 겹친 줄 {dupes}줄)")
with open("notices.txt", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```

`f.read()` 는 파일 전체를 글자 하나로 줍니다. 끝의 줄바꿈까지 들어 있어서 `.strip()` 으로 뗍니다. 쓸 때는 안내문마다 `"\n"` 을 붙입니다.

**왜 이렇게 푸나**
명단을 먼저 딕셔너리로 만들어 두면, 대출 줄마다 members.csv 를 다시 열지 않고 `email in names` 로 바로 찾습니다. 3-11 은 있나 없나만 보면 돼서 목록이었고, 여기서는 메일로 이름까지 꺼내야 해서 딕셔너리입니다.
fill 은 문구 채우기만 합니다. 문구가 파일에 있으니 담당자가 문장을 고쳐도 코드는 그대로입니다. make_notices 는 세 값을 돌려주고(2-6), 파일 쓰기와 요약 출력은 부르는 쪽이 합니다.
중복 기준이 「같은 사람 + 같은 책」 인 까닭은 아래 「틀리면」 에서 보입니다. 메일만 보면 다른 책 안내가 빠지고, 줄 전체를 보면 공백 · 대소문자만 다른 줄이 남습니다.

**틀리면 이렇게 된다**
문구의 `.strip()` 을 빼면 안내문 끝에 파일의 줄바꿈이 남고, write 가 하나 더 붙여 사이마다 빈 줄이 낍니다.

```
안내문 10통 -> notices.txt (명단에 없는 메일 1통 · 겹친 줄 1줄)
김하늘님, 빌려 가신 「어린 왕자」 반납일을 확인해 주세요.

이준서님, 빌려 가신 「파이썬 입문」 반납일을 확인해 주세요.
```

load_names 에서 `.lower()` 를 빼면 「회원」 이 4통이 됩니다. 명단의 `KIM.Haneul@Example.COM` 과 `DAEUN@EXAMPLE.COM` 이 대문자로 남아, 소문자로 바꾼 대출 쪽 메일과 안 맞습니다. 김하늘 2통 · 박다은 1통 · 원래 없던 1통입니다. 한쪽만 정리하면 정리 안 한 것과 같습니다.

```
안내문 10통 -> notices.txt (명단에 없는 메일 4통 · 겹친 줄 1줄)
회원님, 빌려 가신 「어린 왕자」 반납일을 확인해 주세요.
```

중복을 메일만으로 거르면 7통 · 겹친 줄 4줄입니다. 김하늘 「데미안」, 최민재 「코스모스」, 임채원 「데미안」 이 빠집니다. 줄 전체(`line`)로 거르면 11통 · 겹친 줄 0줄이고, 이준서 님께 「파이썬 입문」 이 두 번 갑니다.

명단에 있는지 안 보고 `names[email]` 로 바로 꺼내면 없는 메일에서 멈춥니다.

```python
print(names["haru@example.com"])
```
```
KeyError: 'haru@example.com'
```

**실제로 쓸 때는**
반납 안내, 예약 확인, 결제 안내 같은 단체 문자 · 메일이 이 모양입니다. 보내기 전에 「몇 통 · 명단에 없는 사람 · 겹친 줄」 요약부터 보면, 같은 분께 두 번 보내거나 이름 자리가 엉뚱하게 채워지는 일을 막습니다. 발송은 notices.txt 를 눈으로 확인한 다음입니다.

**앞 문제와의 연결**
1-6 의 replace 와 메일 정리(strip · lower)를 두 파일에 똑같이 걸었습니다. members.csv 는 3-3 · 3-11, loans_nov.csv 는 3-8 에서 읽은 파일입니다. 3-8 은 대출일수를 봤고 여기서는 안 봅니다. 짝으로 겹침을 거르는 것은 3-9 와 같습니다.

## [3-15] 택배 묶음 배송 박스 배정

**묻는 것**
수령인별로 물건을 모은 뒤(딕셔너리 값이 리스트), 순서대로 담다가 한도를 넘으면 새 박스를 여는 「쌓다가 끊기」 입니다. 되풀이가 끝난 뒤 마지막 박스를 한 번 더 넣는 줄이 핵심입니다.

**코드 한 줄씩**

```python
def load_parcels(path, limit):
    groups = {}
    problems = []
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            parts = line.strip().split(",")
            if no == 1 or len(parts) != 3:
                continue
            name = parts[0].strip()
            item = parts[1].strip()
            if parts[2].strip() == "":
                problems.append(f"{name} {item} (무게 빈칸)")
                continue
            weight = float(parts[2])
            if weight > limit:
                problems.append(f"{name} {item} {weight:.1f}kg (한도 넘음)")
                continue
            if name not in groups:
                groups[name] = []
            groups[name].append((item, weight))
    return groups, problems
```

빈칸 검사가 `float()` 보다 먼저입니다. `float("")` 은 에러라서입니다. 빈칸과 한도 넘음은 problems 에 파일 순서로 쌓고 박스에는 안 넣습니다. 수령인이 처음 나오면 빈 리스트를 만들고 (물건, 무게) 튜플을 붙입니다(2-7). 딕셔너리라 수령인은 처음 나온 순서입니다.

```python
def pack(parcels, limit):
    boxes = []
    total = 0
    names = ""
    for item, weight in parcels:
        if total + weight > limit:
            boxes.append((total, names))
            total = 0
            names = ""
        if names == "":
            names = item
        else:
            names = names + ", " + item
        total = total + weight
    boxes.append((total, names))
    return boxes
```

`total` · `names` 는 지금 채우는 박스의 무게 합과 물건 이름입니다. 첫 물건은 이름만, 다음부터는 `", "` 를 붙여 잇습니다.
담기 전에 「더하면 넘나」 를 봅니다. 넘으면 지금 박스를 boxes 에 넣고 비운 뒤 새 박스에 담습니다. `>` 라서 한도와 같으면 담습니다. 김하늘은 쌀 10 + 세제 4.5 + 라면 5.5 = 20.0 이 한 박스, 고양이 모래 8 에서 새 박스입니다. for 가 끝났을 때 마지막 박스는 아직 boxes 에 없어서, for 밖에서 한 번 더 넣습니다.

```python
def write_plan(path, groups, problems, limit):
    with open(path, "w", encoding="utf-8") as f:
        for name in groups:
            boxes = pack(groups[name], limit)
            no = 0
            for total, names in boxes:
                no = no + 1
                f.write(f"{name} 박스 {no}/{len(boxes)} {total:.1f}kg: {names}\n")
        for problem in problems:
            f.write(f"확인 필요: {problem}\n")

groups, problems = load_parcels("parcels.csv", 20)
write_plan("box_plan.txt", groups, problems, 20)
print(f"수령인 {len(groups)}명 / 확인 필요 {len(problems)}건 -> box_plan.txt")
with open("box_plan.txt", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
```

write_plan 이 수령인마다 pack 을 불러, 박스 수(`len(boxes)`)를 안 다음 「1/2」 처럼 씁니다. 무게는 `:.1f` 로 소수 첫째 자리까지입니다.

**왜 이렇게 푸나**
거르기(load_parcels)와 담기(pack)를 나눴습니다. pack 은 「담을 수 있는 물건만 온다」 고 믿고 담기만 하고, 한도를 넘는 물건은 load_parcels 가 limit 를 받아 미리 뺍니다(아래 「틀리면」 의 빈 박스가 그 까닭). pack 은 한 사람의 목록만 받으니 몇 명이든 사람마다 부르면 됩니다. 물건마다 한 번씩만 보니 while 없이 for 로 끝납니다. `:.1f` 를 빼도 무게가 전부 0.5 단위라 합에 오차가 없어 칸과 같습니다(칸으로는 알 수 없음). `1.1 + 2.2` 는 `3.3000000000000003` 이지만 `:.1f` 면 `3.3` 입니다.

**틀리면 이렇게 된다**
비교를 `>=` 로 쓰면 한도와 딱 같은 20.0 을 못 담아 김하늘 박스가 틀어집니다.

```
김하늘 박스 1/2 14.5kg: 쌀, 세제
김하늘 박스 2/2 16.5kg: 라면 한 상자, 고양이 모래, 휴지
```

for 밖의 마지막 `boxes.append` 를 빼면 사람마다 마지막 박스가 사라져 `김하늘 박스 1/1 20.0kg` · `이준서 박스 1/1 18.0kg` 만 남습니다. 박스가 하나뿐인 박다은은 박스 줄이 아예 없습니다.

새 물건마다 앞 박스부터 빈자리를 찾아 담으면 규칙 「앞 박스에는 다시 담지 않습니다」 를 어깁니다. 이준서의 양말 1.5kg 이 18.0kg 짜리 첫 박스로 돌아가, `이준서 박스 1/2 19.5kg: 생수 한 묶음, 전기밥솥, 양말` 과 `이준서 박스 2/2 2.5kg: 커피 원두` 가 됩니다.

load_parcels 의 한도 검사를 빼면 pack 이 23kg 책상을 받습니다. 빈 박스(합 0)에 23 을 더하면 한도를 넘어서 빈 박스부터 내보내고, `박다은 박스 1/3 0.0kg:` 다음에 `박다은 박스 2/3 23.0kg: 접이식 책상` 이 찍힙니다. 빈칸을 거르지 않고 바로 `float()` 하면 행주 줄에서 멈춥니다.

```python
parts = "박다은,행주,".split(",")
weight = float(parts[2])
```

택배 묶음, 첨부 파일을 용량 한도로 나눠 보내기가 이 모양입니다. 순서대로 담기는 박스 수가 가장 적다는 보장은 없지만, 포장하는 사람이 목록 순서대로 따라 하기 쉽습니다. 한도를 넘거나 무게가 빈 물건은 조용히 버리지 말고 「확인 필요」 로 사람에게 넘깁니다.

## [3-16] 출결 요약과 수료 판정

**묻는 것**
출결표를 함수 셋으로 나눠 푸는 법을 묻습니다. 한 사람의 칸을 세고(count_status), 규칙으로 판정하고(judge), 파일에서 사람을 꺼냅니다(read_attendance). 「지각 3번 = 결석 1번」 은 `//` 로 풀고, 수업일수가 0 인 사람은 나누기 전에 거릅니다.

**코드 한 줄씩**

```python
def count_status(cells):
    counts = {"출석": 0, "지각": 0, "결석": 0}
    typos = []
    for cell in cells:
        cell = cell.strip()
        if cell in counts:
            counts[cell] = counts[cell] + 1
        else:
            typos.append(cell)
    return counts, typos
```

`counts` 는 세 상태를 키로 미리 넣고 0 에서 시작합니다. 키가 처음부터 있으니 `.get` 없이 `counts[cell] + 1` 로 더합니다. `cell in counts` 가 아니면 모두 `typos` 로 갑니다. 최민재의 「출썩」 이 여기에 걸리고, 한지우의 「 결석」(앞에 공백)은 `cell.strip()` 덕분에 「결석」 으로 셉니다.

```python
def judge(counts):
    days = counts["출석"] + counts["지각"] + counts["결석"]
    if days == 0:
        return 0.0, "판정 불가"
    absent = counts["결석"] + counts["지각"] // 3
    rate = (days - absent) / days * 100
    if rate >= 80:
        return rate, "수료"
    return rate, "미수료"
```

`days` 가 수업일수입니다. 오타 칸은 `counts` 에 없으니 저절로 빠집니다. 최민재는 10칸 중 9일이라 (9 - 2) / 9 x 100 = 77.8 입니다.

`days == 0` 은 나누기보다 위에서 봅니다. 이름만 있는 윤가온은 세 수가 모두 0 이고, return 을 만나 함수가 끝나서 나누기까지 가지 않습니다. 판정 불가도 `(0.0, "판정 불가")` 로 두 값 모양을 지켜, 부르는 쪽이 늘 두 값으로 받습니다.

`counts["지각"] // 3` 이 「지각 3번 = 결석 1번」 입니다. 박다은은 지각 4번이라 4 // 3 = 1 이고, 남는 1번은 출석입니다. `rate >= 80` 이 「80 이상」 이고, 이준서가 (10 - 2) / 10 x 100 = 80.0 으로 딱 경계에 있습니다.

```python
def read_attendance(path):
    people = []
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            if no == 1:
                continue
            cells = line.strip().split(",")
            people.append((cells[0].strip(), cells[1:]))
    return people
```

`cells[1:]` 은 둘째 칸부터 끝까지(1회~10회)입니다. 윤가온 줄은 칸이 하나라 `cells[1:]` 이 빈 리스트 `[]` 입니다. 잘라 내기는 범위를 넘어도 에러 없이 빈 리스트를 줍니다.

```python
result = {"수료": 0, "미수료": 0, "판정 불가": 0}
for name, cells in read_attendance("attendance.csv"):
    counts, typos = count_status(cells)
    rate, verdict = judge(counts)
    status = f"출석 {counts['출석']} 지각 {counts['지각']} 결석 {counts['결석']}"
    if verdict == "판정 불가":
        print(f"{name}  {status}  판정 불가")
    else:
        print(f"{name}  {status}  출석률 {rate:.1f}% {verdict}")
    for typo in typos:
        print(f"  확인 필요: '{typo}' (계산에서 뺌)")
    result[verdict] = result[verdict] + 1
print(f"수료 {result['수료']}명 / 미수료 {result['미수료']}명 / 판정 불가 {result['판정 불가']}명")
```

`result` 의 키가 judge 가 돌려주는 판정 글자 셋과 똑같아서 `result[verdict]` 한 줄로 판정별 인원을 셉니다. 소수 첫째 자리는 찍는 쪽의 `:.1f` 가 맞춥니다.

**왜 이렇게 푸나**
규칙이 사는 곳을 judge 하나로 모았습니다. 「지각 2번 = 결석 1번」 으로 바뀌면 `// 3` 만, 수료 기준이 90 으로 오르면 `>= 80` 만 고칩니다. count_status 는 파일을 모르고 칸 목록만 받으니 따로 불러 확인할 수 있습니다. `count_status(["출석", "출썩", " 지각"])` 은 `({'출석': 1, '지각': 1, '결석': 0}, ['출썩'])` 을 돌려줍니다.

judge 안의 순서는 「0 인지 -> 지각 바꾸기 -> 나누기 -> 80 과 비교」 입니다. 0 검사가 나누기 뒤에 있으면 이미 늦습니다. 오타를 출석이나 결석으로 짐작하지 않고 빼는 것은 규칙대로입니다. 「출썩」 이 무엇이었는지는 출결표를 쓴 사람만 압니다.

**틀리면 이렇게 된다**
`//` 를 `/` 로 쓰면 지각 1번이 결석 0.333... 번이 됩니다. 김하늘(결석 0, 지각 1)을 그 식으로 계산하면 이렇습니다.

```python
absent = 0 + 1 / 3
print(f"{(10 - absent) / 10 * 100:.1f}%")
```
```
96.7%
```

judge 에서 `//` 만 `/` 로 바꿔 돌리면 김하늘 96.7%, 박다은 66.7% 가 되고, 지각이 딱 3번인 이준서는 80.0% 그대로입니다. 여섯 명 판정과 끝 줄 인원은 하나도 안 바뀝니다(직접 돌려 봤습니다). 판정만 보면 놓치고 출석률 숫자에서만 잡힙니다.

`cell = cell.strip()` 을 빼면 한지우가 「출석 7 지각 0 결석 2  출석률 77.8% 미수료」 가 되고 그 아래 `  확인 필요: ' 결석' (계산에서 뺌)` 줄이 생깁니다(직접 돌려 봤습니다). 이번에도 판정은 미수료 그대로입니다.

0 검사를 빼면 윤가온에서 나누기가 이렇게 됩니다.

```python
days = 0
print((days - 0) / days * 100)
```
```
ZeroDivisionError: division by zero
```

**실제로 쓸 때는**
출결표는 사람이 손으로 채우는 표라 오타와 공백이 늘 섞입니다. 고칠 수 없는 칸은 「확인 필요」 로 띄워 담당자에게 넘기는 것이 안전합니다.

이 파일에는 빈 줄이 없어서, 빈 줄을 건너뛰는 코드를 넣든 안 넣든 칸이 같습니다. 칸이 못 가려내는 자리입니다. 파일 끝에 빈 줄이 하나 붙으면 이 정답은 이름이 빈 사람을 만들어 `  출석 0 지각 0 결석 0  판정 불가` 를 한 줄 더 찍고, 끝 줄이 「판정 불가 2명」 이 됩니다(빈 줄을 붙여 직접 돌려 봤습니다). 판정 불가가 이상하게 늘면 빈 줄부터 의심하세요.

**앞 문제와의 연결**
2-3 의 average 는 응시자가 0명이면 나누기 전에 0.0 을 돌려줬습니다. judge 의 `days == 0` 이 같은 자리입니다(문제의 「막히면 2-3」). 상태별로 세는 딕셔너리는 3-1 의 수준별 건수와 같은 모양이고, 키를 미리 넣어 둔 것만 다릅니다. `cells[1:]` 은 1-5 의 `[시작:]` 잘라 내기를 리스트에 쓴 것입니다.

## [3-17] 삼킨 예외에서 범인 찾기

**묻는 것**
에러 없이 틀린 숫자를 내는 코드에서 원인을 찾는 법을 묻습니다. 모든 에러를 삼키는 `except:` 를 잠깐 좁혀 숨은 에러 이름을 꺼내 보고, 고친 함수는 버린 줄을 사유와 함께 돌려주게 만듭니다.

**코드 한 줄씩**
주어진 broken_total 은 try 안에서 `int(cells[3])` 을 하고 `except:` 에서 `continue` 합니다. `except:` 는 에러 이름이 없어서 try 안의 에러를 종류 가리지 않고 다 잡습니다. 무엇이 왜 버려졌는지 흔적이 안 남아 「고치기 전: 합계 1회 / 센 줄 1줄」 이 에러 없이 찍힙니다. 할 일 2 대로 `except ValueError:` 로 좁히면 ValueError 가 아닌 에러는 터집니다(장면은 아래 「틀리면」). 마지막 줄 `IndexError: list index out of range` 는 리스트에 없는 칸 번호를 꺼냈다는 뜻이라 `cells[3]` 이 범인입니다. 맞힌횟수는 셋째 칸이니 번호는 2 입니다.

```python
# 범인: 맞힌횟수는 셋째 칸(cells[2])인데 cells[3] 을 읽었다. 칸이 3개인 줄마다
#       IndexError 가 났고 except: 가 전부 삼켰다. 4칸인 escalate 줄만 더해져 합계 1.
#       except ValueError: 로 좁히면 「IndexError: list index out of range」 로 멈춘다.
```

합계 1 의 정체는 13번 escalate 줄입니다. 뜻 칸 「상부에 올리다, 보고하다」 안의 쉼표 때문에 칸이 4개로 잘렸고, 넷째 칸이 `"1"` 이었습니다.

```python
def fixed_total(path):
    total = 0
    counted = 0
    dropped = []
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            if no == 1:
                continue
            cells = line.strip().split(",")
            if len(cells) != 3:
                dropped.append((no, f"칸 {len(cells)}개"))
                continue
            try:
                total = total + int(cells[2])
                counted = counted + 1
            except ValueError:
                dropped.append((no, f"숫자 아님 '{cells[2].strip()}'"))
    return total, counted, dropped
```

`dropped` 에 (줄번호, 사유) 튜플을 쌓습니다. 칸 수 검사가 try 보다 위에 있어서, 칸이 3개가 아닌 줄은 사유를 남기고 넘어갑니다. 빈 9번 줄도 `"".split(",")` 가 `['']` 라서 「칸 1개」 입니다. try 안에는 숫자로 바꾸는 줄과 세는 줄만 둡니다. 칸 수를 이미 봤으니 여기서 날 수 있는 에러는 ValueError 뿐이고, 그 이름만 적어 잡습니다. 4번 줄의 빈칸 `''` 와 7번 줄의 「두번」 이 사유와 함께 남습니다. 12번 vendor 줄의 0 은 「한 번도 못 맞힘」 이라 버리지 않고 셉니다.

```python
total, counted, dropped = fixed_total("wordbook.csv")
print(f"고친 뒤: 합계 {total}회 / 센 줄 {counted}줄 / 버린 줄 {len(dropped)}줄")
for no, reason in dropped:
    print(f"  {no}번 줄: {reason}")
```

**왜 이렇게 푸나**
broken_total 은 그대로 두고 fixed_total 을 새로 만들었습니다. 같은 파일로 「고치기 전」 과 「고친 뒤」 를 나란히 찍으면, 요청한 사람에게 1 이 26 이 된 까닭을 숫자로 보여 줄 수 있습니다. 검사 순서는 「칸 수 -> 숫자」 입니다. 13번 줄의 셋째 칸 ` 보고하다` 는 숫자로도 안 바뀝니다. 한 줄이 두 규칙에 다 걸리면 먼저 본 규칙이 사유가 되니, 칸 수를 먼저 봐야 진짜 원인(뜻 칸 안 쉼표)인 「칸 4개」 가 남습니다. try 는 에러가 날 줄만 감쌌습니다. broken_total 처럼 split 까지 넓게 감싸면 엉뚱한 에러까지 같은 사유로 묶입니다.

**틀리면 이렇게 된다**
할 일 2 의 장면입니다. 주어진 코드에서 `except:` 를 `except ValueError:` 로만 바꾸면 첫 데이터 줄(2번 budget 줄)에서 바로 멈추고, 「고치기 전」 줄도 안 찍힙니다. 에러 마지막 줄은 3.9·3.14·3.15 모두 같습니다.

```python
def broken_total(path):
    total = 0
    counted = 0
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            if no == 1:
                continue
            try:
                cells = line.strip().split(",")
                total = total + int(cells[3])
                counted = counted + 1
            except ValueError:
                continue
    return total, counted

total, counted = broken_total("wordbook.csv")
```
```
IndexError: list index out of range
```

범인을 적었으면 `except:` 로 되돌려야 「고치기 전」 줄이 칸대로 찍힙니다. 이 함수에서 `cells[3]` 을 `cells[2]` 로 고쳐도 `except ValueError:` 만 두고 칸 수 검사가 없으면, 같은 IndexError 로 멈춥니다(직접 돌려 봤습니다). 9번 빈 줄은 칸이 하나라 셋째 칸이 없고, IndexError 는 ValueError 가 아니라서 그대로 터집니다. 「한 줄이 틀려도 다음 줄로」 가 깨지고 파일 전체가 멈춥니다. 반대로 `cells[2]` 로 고치고 `except:` 를 두면 (26, 7) 로 숫자는 맞지만(직접 돌려 봤습니다), 버린 줄과 사유가 안 남아 요청의 뒷부분을 못 채웁니다.

fixed_total 의 `except ValueError:` 를 `except:` 로 써도 칸은 정답과 똑같습니다. 칸 수를 먼저 봐서 try 안에서는 ValueError 밖에 안 나기 때문입니다. 칸이 못 가려내는 자리입니다. 차이는 다음 실수에서 납니다. `cells` 를 `cell` 로 잘못 쳤다고 하겠습니다.

```python
cells = "budget,예산,3".split(",")
try:
    total = total + int(cell[2])
except:
    print(f"숫자 아님 '{cells[2].strip()}'")
```
```
숫자 아님 '3'
```

`except:` 가 NameError 까지 삼켜 멀쩡한 3 을 버립니다. fixed_total 에 이 오타를 넣으면 12줄이 전부 버려져 「합계 0회 / 센 줄 0줄 / 버린 줄 12줄」 이 찍힙니다(직접 돌려 봤습니다). `except ValueError:` 였다면 그 자리에서 멈춥니다.

```python
cells = "budget,예산,3".split(",")
try:
    total = total + int(cell[2])
except ValueError:
    print(f"숫자 아님 '{cells[2].strip()}'")
```
```
NameError: name 'cell' is not defined. Did you mean: 'cells'?
```

파이썬 3.9 에서는 뒤의 `Did you mean: 'cells'?` 없이 `NameError: name 'cell' is not defined` 로 나옵니다.

**실제로 쓸 때는**
「에러는 안 났는데 숫자가 이상해요」 는 신입이 자주 받는 신고입니다. 남의 코드에서 이름 없는 `except:` 를 보면 범인 후보 1순위로 두고, 잠깐 에러 이름을 적어 좁혀 보세요. 버린 줄을 줄번호·사유와 함께 남기면 다음 사람이 원본의 몇 번 줄을 고칠지 바로 압니다. 값 안에 쉼표가 들어가야 하면 그 값을 따옴표로 감싸 저장하고 3-19 의 csv.reader 로 읽습니다. 이 파일의 13번 줄은 따옴표가 없어서 csv.reader 로 읽어도 4칸입니다.

**앞 문제와의 연결**
3-3 에서 처음 쓴 `try:` · `except ValueError:` 를 이번에는 거꾸로, 너무 넓게 잡으면 무엇이 숨는지로 봤습니다(문제의 「막히면 3-3」). 같은 wordbook.csv 를 2-15 에서 읽을 때도 칸이 3개가 아닌 줄을 버렸습니다. 버린 줄에 사유를 붙이는 모양은 2-14 이고, 빈 줄은 칸이 하나라 셋째 칸을 꺼내면 IndexError 가 나는 것은 2-13 에서 본 것입니다.

## [3-18] 할인 이벤트 설정 검증

**묻는 것**
JSON 설정을 정해진 순서로 검사해 통과와 탈락을 가르는 법을 묻습니다. 이 문제에서 처음 쓰는 도구는 날짜끼리 `<` `>` 로 비교하기입니다. 검사 순서가 그대로 탈락 사유가 됩니다.

**코드 한 줄씩**

```python
required = ["code", "name", "rate", "start", "end"]
import datetime
import json

def to_date(text):
    parts = text.split("-")
    return datetime.date(int(parts[0]), int(parts[1]), int(parts[2]))
```

`required` 는 주어진 줄입니다. to_date 는 `"2026-04-01"` 을 하이픈으로 잘라 숫자로 바꾼 뒤 `datetime.date` 에 넣습니다. `int("04")` 는 4 입니다.

```python
def check_promo(promo, base_day):
    for key in required:
        if key not in promo:
            return f"필수 키 없음 ({key})"
    if promo["rate"] < 1 or promo["rate"] > 50:
        return f"할인율 범위 밖 ({promo['rate']})"
    start = to_date(promo["start"])
    end = to_date(promo["end"])
    if start > end:
        return "기간 거꾸로"
    if base_day < start:
        return "시작 전"
    if base_day > end:
        return "이미 끝남"
    return ""
```

걸리는 즉시 return 하니 처음 걸린 사유 하나만 나갑니다. `for key in required` 가 required 순서로 돌아서, 빠진 키가 여럿이어도 앞쪽 키 하나가 사유입니다. 할인율은 `< 1 or > 50` 일 때만 탈락이라 1 과 50 은 통과합니다. 날짜는 to_date 로 바꾼 뒤 비교하고, 앞선 날이 작습니다. `base_day < start` 와 `base_day > end` 는 같은 날이면 False 라서 시작일·끝날 당일은 통과합니다. LASTDAY30(끝날 05-01)과 MAYDAY50(시작일 05-01, 할인율 50)이 이 경계에 있습니다. 통과면 빈 글자 `""` 를 돌려줍니다.

```python
def filter_promos(promos, base_day):
    passed = []
    failed = []
    no = 0
    for promo in promos:
        no = no + 1
        reason = check_promo(promo, base_day)
        if reason == "":
            passed.append(promo)
        else:
            failed.append((no, promo.get("code", "(코드 없음)"), reason))
    return passed, failed
```

`promo.get("code", "(코드 없음)")` 은 code 키가 없는 9번에서 둘째 값을 줍니다. 통과한 promo 는 받은 딕셔너리 그대로 넣습니다. check_promo 가 날짜를 `start`·`end` 라는 새 변수에 담고 promo 는 안 고쳐서, 파일에는 원래 글자 `"2026-04-01"` 이 그대로 나갑니다.

```python
with open("promo_config.json", encoding="utf-8") as f:
    promos = json.load(f)
passed, failed = filter_promos(promos, datetime.date(2026, 5, 1))
for no, code, reason in failed:
    print(f"{no}번 {code}: {reason}")
with open("valid_promos.json", "w", encoding="utf-8") as f:
    json.dump(passed, f, ensure_ascii=False, indent=2)
print(f"통과 {len(passed)}개 / 탈락 {len(failed)}개 -> valid_promos.json")
with open("valid_promos.json", encoding="utf-8") as f:
    for promo in json.load(f):
        print(f"{promo['code']}  {promo['rate']}%  {promo['start']} ~ {promo['end']}  {promo['name']}")
```

쓰기는 3-5 와 같은 세 설정이고, 다시 읽어 찍는 것은 파일에 제대로 들어갔는지 확인하는 단계입니다.

**왜 이렇게 푸나**
이벤트 하나를 보는 check_promo 와 목록을 가르는 filter_promos 를 나눴습니다. check_promo 는 이벤트 하나와 기준일만 받아 사유 하나를 돌려주니 한 건만 따로 불러 확인할 수 있고, 6월 1일 기준으로 다시 거를 때는 부르는 줄의 날짜만 바꿉니다. 검사 순서 「필수 키 -> 할인율 -> 기간」 은 사유를 정하면서 에러도 막습니다. 키가 다 있는지 먼저 봐야 뒤에서 `promo["end"]` 를 안전하게 꺼냅니다. 기간 셋 가운데 「거꾸로」 를 먼저 보는 것은, 기간이 거꾸로면 시작 전·이미 끝남을 따지는 일 자체가 뜻이 없어서입니다.

**틀리면 이렇게 된다**
필수 키 검사를 빼면 4번 NOEND5 의 끝날을 꺼내다 멈춥니다. filter_promos 가 이 에러로 끝나서 탈락 사유를 하나도 못 찍습니다.

```python
print(to_date(promos[3]["end"]))
```
```

```

기간 검사에서 「거꾸로」 를 맨 뒤로 보내면 BACKWARD(05-31 ~ 04-01)는 「시작 전」 이 됩니다. 기준일 5월 1일이 시작일 5월 31일보다 앞이라 그 검사에 먼저 걸립니다. 에러가 없어서 사유가 바뀐 줄 모르고 지나치기 쉽습니다. 할인율을 `promo["rate"] >= 50` 으로 쓰면 「11번 MAYDAY50: 할인율 범위 밖 (50)」 이 생겨 통과 3개 / 탈락 8개가 됩니다(직접 돌려 봤습니다). filter_promos 에서 `.get` 대신 `promo["code"]` 로 꺼내면 9번 이벤트에서 멈춥니다.


날짜를 to_date 로 안 바꾸고 글자 그대로 비교해도(기준일도 `"2026-05-01"` 로 넘기면) 칸은 정답과 똑같습니다(직접 돌려 봤습니다). 이 파일의 날짜가 전부 월·일 두 자리라서입니다. 칸이 못 가려내는 자리입니다. 글자 비교는 앞 글자부터 하나씩 견줘서, 0 을 빼고 적은 날짜가 섞이면 틀립니다.

```python

print(to_date("2026-10-01") < to_date("2026-9-30"))
```

글자로는 「1」 이 「9」 보다 작아 10월 1일이 9월 30일보다 앞이 됩니다. 날짜로 바꾸면 바르게 False 입니다.

**실제로 쓸 때는**
설정 파일은 운영 중에 사람이 고치는 파일이라, 켜기 전에 기계로 거르는 단계를 둡니다. 탈락은 「몇 번 · 코드 · 사유」 로 담당자에게 돌려보냅니다. 사유가 하나뿐이라 고친 뒤 다시 돌리면 그 이벤트의 다음 문제가 나올 수 있습니다. 기준일을 오늘 날짜로 넣으면 돌리는 날마다 결과가 바뀌니, 날이 정해진 검사는 날짜를 인자로 넘겨 미리 돌려 봅니다.

**앞 문제와의 연결**
`datetime.date` 는 2-17 택배 도착 예정일에서 처음 썼습니다(문제의 「막히면 2-17」). json.load·json.dump 는 3-5, 「검사 순서를 정하고 처음 걸린 사유 하나만」 은 3-2 일정 메모와 같은 짜임입니다. 설정을 읽어 잘못된 값을 알려 주는 일은 3-6 가게 설정 로더에서도 했습니다.

## [3-19] 가계부와 카드 내역 대조

**묻는 것**
두 파일을 같은 열쇠 (날짜, 가게) 로 짝지어 일치·불일치·한쪽에만을 가르는 법을 묻습니다. 카드 금액 `"4,500"` 처럼 따옴표 안에 쉼표가 든 CSV 는 split(",") 대신 csv.reader 로 읽습니다.

**코드 한 줄씩**

```python
import csv

def read_amounts(path):
    amounts = {}
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for row in csv.reader(f):
            no = no + 1
            if no == 1 or len(row) != 3:
                continue
            key = (row[0].strip(), row[1].strip())
            amounts[key] = int(row[2].replace(",", ""))
    return amounts
```

`csv.reader(f)` 는 파일을 한 줄씩 읽어 칸 리스트로 줍니다. 따옴표로 감싼 `"4,500"` 은 칸 하나 `'4,500'` 이 되고 따옴표도 떨어집니다. 빈 줄은 `[]`(칸 0개)로 나와 `len(row) != 3` 에 걸립니다.

열쇠는 (날짜, 가게) 튜플이고, 카드 쪽 「 화장품 가게 」 는 strip 으로 공백을 떼야 가계부와 같은 열쇠가 됩니다. `row[2].replace(",", "")` 가 쉼표를 지워 int 로 바꿀 수 있게 합니다. 가계부 금액에는 쉼표가 없어 replace 가 아무것도 안 바꾸니, 두 파일에 같은 함수를 씁니다.

```python
def compare(ledger, card):
    lines = []
    counts = {"일치": 0, "불일치": 0, "가계부에만": 0, "카드에만": 0}
    for key in ledger:
        if key not in card:
            kind = "가계부에만"
            lines.append(f"가계부에만: {key[0]} {key[1]} {ledger[key]:,}원")
        elif ledger[key] == card[key]:
            kind = "일치"
            lines.append(f"일치: {key[0]} {key[1]} {ledger[key]:,}원")
        else:
            kind = "불일치"
            lines.append(f"불일치: {key[0]} {key[1]} 가계부 {ledger[key]:,}원 / 카드 {card[key]:,}원")
        counts[kind] = counts[kind] + 1
    for key in card:
        if key not in ledger:
            lines.append(f"카드에만: {key[0]} {key[1]} {card[key]:,}원")
            counts["카드에만"] = counts["카드에만"] + 1
    return lines, counts
```

첫 for 는 가계부 딕셔너리를 넣은 순서대로 돕니다. 카드 파일에는 카페 봄이 동네빵집보다 먼저 있지만 결과는 가계부 순서입니다. `key not in card` 를 맨 앞에 두는 것은, 카드에 없는 열쇠로 `card[key]` 를 꺼내면 KeyError 라서입니다. 세 갈래가 `kind` 에 이름을 남기고, 갈래 밖 한 줄 `counts[kind] + 1` 이 건수를 셉니다. 둘째 for 는 카드 쪽을 돌며 가계부에 없는 열쇠만 찾습니다.

```python
lines, counts = compare(read_amounts("ledger.csv"), read_amounts("card_bill.csv"))
for line in lines:
    print(line)
summary = f"일치 {counts['일치']}건 / 불일치 {counts['불일치']}건"
print(f"{summary} / 가계부에만 {counts['가계부에만']}건 / 카드에만 {counts['카드에만']}건")
```

끝 줄은 길어서 앞 절반을 `summary` 에 담아 두 줄로 나눴습니다.

**왜 이렇게 푸나**
읽기(read_amounts)와 대조(compare)를 나눴습니다. 두 파일은 머리줄 이름과 금액 모양만 다르고 칸 순서가 같습니다. 머리줄을 이름이 아니라 번호로 건너뛰고 쉼표를 늘 지우니, 함수 하나로 두 파일을 같은 모양 `{(날짜, 가게): 금액}` 으로 맞춥니다. 모양이 같아진 뒤로는 compare 가 파일을 몰라도 됩니다. 열쇠를 둘로 묶은 것은, 날짜만 쓰면 5월 1일 두 건이 겹치고 가게만 쓰면 같은 가게를 다른 날 간 것이 겹쳐서입니다.

**틀리면 이렇게 된다**
csv.reader 대신 `line.strip().split(",")` 로 자르면 카드 줄이 4칸이 됩니다.

```python
print('2026-05-01,카페 봄,"4,500"'.split(","))
```
```
['2026-05-01', '카페 봄', '"4', '500"']
```

카드 줄이 전부 `len(row) != 3` 에 걸려 카드 딕셔너리가 빕니다. 가계부 7건이 모두 「가계부에만」 이 되고 일치 0건 / 불일치 0건 / 가계부에만 7건 / 카드에만 0건이 나옵니다(read_amounts 를 그렇게 바꿔 돌려 봤습니다). 에러가 하나도 안 나서 더 위험합니다.

쉼표를 안 지우고 int 로 바꾸면 카드 첫 줄에서 멈춥니다.

```python
row = ["2026-05-01", "카페 봄", "4,500"]
amount = int(row[2])
```
```
ValueError: invalid literal for int() with base 10: '4,500'
```

가게 이름의 공백을 안 떼면 결과가 「가계부에만: 2026-05-03 화장품 가게 23,000원」 과 「카드에만: 2026-05-03  화장품 가게  23,000원」 두 줄로 갈립니다(직접 돌려 봤습니다). 금액까지 같아 눈으로는 일치인데 프로그램은 다른 가게로 봅니다.

compare 에서 `ledger[key] == card[key]` 를 `key not in card` 보다 먼저 보면, 카드에 없는 김밥집에서 이렇게 멈춥니다.

```python
card = read_amounts("card_bill.csv")
print(card[("2026-05-04", "김밥집")])
```
```
KeyError: ('2026-05-04', '김밥집')
```

`"utf-8-sig"` 대신 `"utf-8"` 로 열어도 칸은 같습니다(직접 돌려 봤습니다). 머리줄을 번호로 건너뛰어 BOM 이 붙은 첫 칸을 아무도 안 쓰기 때문입니다. 칸이 못 가려내는 자리입니다. 머리줄을 `row[0] == "날짜"` 처럼 글자로 찾는 순간, utf-8 쪽은 첫 칸이 `'\ufeff날짜'` 라서 못 찾습니다.

**실제로 쓸 때는**
남이 만든 CSV 는 값 안에 쉼표가 있을 수 있습니다. 칸을 자를 때는 처음부터 csv.reader 를 쓰고, split(",") 는 값에 쉼표가 없다고 확신할 때만 씁니다.

이 문제는 「한 파일 안에 같은 날 같은 가게는 한 번뿐」 이라고 정해 두었지만, 실제 가계부에는 같은 날 같은 서점에 두 번 간 기록이 생깁니다. 이 정답은 같은 열쇠가 또 나오면 나중 금액으로 덮어씁니다. 가계부 끝에 `2026-05-06,서점,2000` 을 붙여 돌리면 서점이 「불일치: 2026-05-06 서점 가계부 2,000원 / 카드 15,000원」 이 됩니다(직접 돌려 봤습니다). 실무에서는 같은 열쇠의 금액을 더해 두거나 결제 시각까지 열쇠에 넣습니다.

**앞 문제와의 연결**
2-19 는 어제·오늘 명단을 양쪽으로 한 번씩 돌며 「새로 온 사람」 과 「빠진 사람」 을 찾았습니다(문제의 「막히면 2-19」). compare 의 for 두 개가 같은 일을 딕셔너리로 합니다. `in` 으로 있는지 보고 나서 꺼내는 순서는 2-8 메뉴에 없는 주문, (날짜, 메일) 같은 튜플 묶음은 3-9 의 겹친 방문 찾기에서 썼습니다. `.replace()` 는 1-6, `:,` 는 1-2 입니다.

## [3-20] 도서관 운영 보고서 -- 마지막 관문

**묻는 것**
세 파일을 메일 하나로 잇는 법을 묻습니다. 세 파일을 같은 함수로 읽어 다듬고(read_rows), 명단에서 「메일 -> 이름」 딕셔너리를 만들고(member_names), 대출과 방문을 그 딕셔너리에 대어 셉니다(build_report). 새 도구 없이 앞 문제의 도구만 씁니다.

**코드 한 줄씩**

```python
def read_rows(path, size):
    rows = []
    no = 0
    with open(path, encoding="utf-8-sig") as f:
        for line in f:
            no = no + 1
            cells = line.split(",")
            if no == 1 or len(cells) != size:
                continue
            row = []
            for cell in cells:
                row.append(cell.strip())
            row[1] = row[1].lower()
            rows.append(row)
    return rows
```

`size` 는 파일마다 다른 칸 수(명단·대출 4, 방문 3)입니다. 칸 수가 맞는 줄만 칸마다 공백을 떼 새 리스트 `row` 에 담고, 마지막 칸의 줄바꿈도 이 strip 이 뗍니다. 세 파일 모두 둘째 칸이 메일이라 `row[1] = row[1].lower()` 한 줄로 세 파일의 메일 모양이 같아집니다. 칸이 모자란 강태윤 명단 줄, gaon 의 모모 대출 줄, seoyeon 의 방문 줄은 여기서 빠집니다.

```python
def member_names(rows):
    names = {}
    for row in rows:
        if "@" in row[1] and row[1] not in names:
            names[row[1]] = row[0]
    return names
```

@ 가 없는 정서연(seoyeon.example.com)은 빼고, 이미 들어간 메일(최민재 두 번째 줄)은 건너뜁니다. 넣은 순서가 명단 순서라 보고서도 명단 순서로 나옵니다.

```python
def build_report(names, loans, visits):
    books = {}
    seen = []
    outside = []
    for row in loans:
        if (row[1], row[0]) in seen:
            continue
        seen.append((row[1], row[0]))
        if row[1] in names:
            books[row[1]] = books.get(row[1], 0) + 1
        else:
            outside.append(f"- {row[0]} ({row[1]})")
```

`seen` 은 이미 센 (메일, 도서) 짝입니다. 3번·6번 줄 「파이썬 입문」 은 junseo 와 JUNSEO 로 달랐지만 read_rows 가 소문자로 맞춰 같은 짝이 되고, 두 번째 줄은 건너뜁니다. 겹침 검사가 「명단에 있나」 보다 위라서 명단에 없는 사람의 겹친 대출도 한 번만 셉니다.

```python
    minutes = {}
    other = 0
    for row in visits:
        if row[2].isdigit():
            if row[1] in names:
                minutes[row[1]] = minutes.get(row[1], 0) + int(row[2])
            else:
                other = other + 1
```

머문분은 read_rows 가 공백을 뗐으니 `isdigit()` 하나로 빈칸과 「사십」 을 거릅니다. 방문은 똑같은 줄도 줄마다 세는 규칙이라 seen 이 없습니다. 박다은의 명단 메일은 daeun@example.com, 방문 메일은 park.daeun@example.com 입니다. 잇는 열쇠는 메일 글자뿐이라 이 두 줄은 명단에 없는 방문입니다.

```python
    lines = [f"도서관 운영 보고서 (회원 {len(names)}명)"]
    for email in names:
        lines.append(f"{names[email]}: 대출 {books.get(email, 0)}권, 열람실 {minutes.get(email, 0)}분")
    lines.append(f"겹친 대출 기록 {len(loans) - len(seen)}건은 한 번만 셌습니다")
    lines.append(f"명단에 없는 대출 {len(outside)}건")
    for line in outside:
        lines.append(line)
    lines.append(f"명단에 없는 방문 {other}건")
    return lines
```

기록이 없는 회원은 `.get(email, 0)` 이 0 을 줘서 박다은·윤가온이 「대출 0권」 입니다. 겹친 건수는 「받은 대출 줄 수 - 센 짝 수」 = 9 - 8 = 1건입니다. build_report 는 print 하지 않고 줄 목록만 돌려줍니다. 화면에 찍을지 파일에 쓸지는 부르는 쪽이 정합니다.

```python
names = member_names(read_rows("members.csv", 4))
lines = build_report(names, read_rows("loans.csv", 4), read_rows("visits.csv", 3))
with open("library_report.txt", "w", encoding="utf-8") as f:
```

`f.write` 는 줄바꿈을 붙이지 않아서 `+ "\n"` 을 씁니다. 화면은 「14줄 썼습니다」 한 줄과 파일 14줄, 모두 15줄입니다.

**왜 이렇게 푸나**
세 파일을 잇는 열쇠는 메일입니다. 메일 다듬기(공백·소문자)를 read_rows 한 곳에 두어 세 파일이 똑같이 다듬어지니, 한 파일만 소문자로 바꾸는 실수가 들어설 자리가 없습니다. 「회원인가」 는 member_names 가 만든 딕셔너리 하나로 판단합니다. @ 검사와 「처음 사람만」 은 여기서만 적용하고, build_report 는 `row[1] in names` 만 묻습니다.

build_report 안의 순서는 대출이 「겹침 -> 명단」, 방문이 「숫자 -> 명단」 입니다. 셀 수 없는 줄을 먼저 걸러 내고, 남은 줄만 회원과 비회원으로 나눕니다.

member_names 에서 `row[1] not in names` 를 빼 나중 사람으로 덮어써도 칸은 정답과 똑같습니다(직접 돌려 봤습니다). 겹친 최민재 두 줄이 글자까지 같아서입니다. 칸이 못 가려내는 자리입니다. 같은 메일에 다른 이름이 오는 명단이면 「처음 사람만」 규칙이 결과를 가릅니다.

**실제로 쓸 때는**
여러 파일을 잇는 보고서에서 숫자가 틀리는 흔한 원인은 열쇠 모양이 파일마다 다른 것입니다(대소문자·공백). 잇기 전에 열쇠를 한 함수에서 같은 모양으로 다듬으세요.

「명단에 없는」 건수는 꼭 같이 찍으세요. 그 숫자가 생각보다 크면 잇기가 새는 곳입니다. park.daeun 처럼 사람은 같아 보여도 메일이 다른 기록은 프로그램이 짐작해 붙이지 말고, 목록으로 넘겨 담당자가 확인하게 합니다.

**앞 문제와의 연결**
마지막 관문이라 새 도구 없이 앞에서 만든 도구를 다시 씁니다.

- read_rows: 머리줄을 번호로 건너뛰고 칸 수로 거르는 것은 2-13, 메일을 strip 과 lower 로 다듬는 것은 2-4 와 3-3 의 clean_email 입니다.
- member_names: 「메일 -> 이름」 딕셔너리는 3-14 의 load_names 입니다. @ 없는 메일을 빼고 같은 메일은 처음 것만 두는 규칙은 3-3 회원 명단 정제에서 왔습니다.
- 대출: 같은 (도서, 메일) 줄을 seen 으로 한 번만 세는 것은 3-14, `.get(키, 0) + 1` 로 쌓는 것은 2-20 대출 기록 집계입니다(문제의 「막히면 2-20」). 「명단에 없는」 을 따로 모으는 것은 2-8 메뉴에 없는 주문과 같은 갈래입니다.
- 방문: 머문분을 `isdigit()` 로 거르는 것은 2-12·3-8·3-9 입니다. 다만 3-9 와 달리 겹친 방문을 거르지 않습니다.
- 쓰기: 줄마다 `+ "\n"` 을 붙여 쓰고 다시 읽어 찍는 것은 2-14 와 3-8 의 보고서입니다.
